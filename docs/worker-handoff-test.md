## 1. 管理者の事前準備（渡す前に確認する）

worker は作物・圃場・農薬を**追加できない**（`src/App.tsx` の管理タブが 3731 / 3889 / 3961 行で
`isAdmin` に囲われている）。下が0件のまま渡すと、worker は必ず詰まる。

| # | 確認するもの | 画面 | 1件以上あるか |
|---|---|---|---|
| 1 | 作物 | メニュー → 登録作物 | ☐ |
| 2 | 圃場 | メニュー → 登録圃場 | ☐ |
| 3 | 農薬 | メニュー → 登録済みの農薬 | ☐ |

3 が無いとタスク③（農薬を撒いたことを記録する）が成立しない。

## 2. 渡すもの

worker に渡すのは次の2つだけ。**使い方の説明は渡さない**（それが測りたいことなので）。

- URL: https://kishu-farm.vercel.app
- ユーザーID と パスワード（管理画面の「アカウントを作成」で設定したもの）

## 3. タスク（口頭で言うだけ。横で黙って見る）

| # | 誰が | 言うこと | 扱い |
|---|---|---|---|
| ① | 管理者 | 畑を1つ登録する | 必達（worker には権限が無いので管理者が実施） |
| ② | **worker** | 今日やった作業を1件記録する | **必達・ここが本丸** |
| ③ | **worker** | 農薬を撒いたことを記録する | 必達 |
| ④ | worker | 「去年いつ○○を撒いたか」を調べる | 記録して次で直す |
| ⑤ | 管理者 | 提出用の帳票を出す | 記録して次で直す |

**助けない。** 質問されたら「どう思いますか？」と返す。詰まった箇所がそのまま課題リストになる。

## 4. 完了の確認

管理者でログインし、カレンダー（記録一覧）に **worker の名前が付いた記録が1件以上ある**ことを見る。
これが確認できた時点で条件③は満たされる。

### 実測メモ（2026-09-16・コードを読んで判明）

- **管理画面（利用者の作成）はナビゲーションに無い。** `navItems` はホーム／カレンダー／相談／分析／メニューの5つで、
  利用者の作成がある `users` タブはそこに含まれない。到達経路はヘッダー右上の丸いアイコン（ラベル無し・
  `src/App.tsx:3014`）→ ユーザー切替シート → 「管理画面」ボタンの2ホップのみ
- **利用者の作成は Web 版のみ。** Expo 版に同じ画面が無いため、worker を増やす作業は管理者の PC に縛られる
  （`docs/decisions/20260912-release-line.md`）

上2点は今回の配布で実際に問題になったかを ☐ で残す → 問題になった ☐ ／ ならなかった ☐

## 6. 出た詰まりの扱い

**このテストは門番ではない。**「1回やったこと」がゲートであって、「出た詰まりを全部直したこと」ではない
（`20260912-release-line.md`）。出たものは次の3問に当てる。

> 1. 直さないと**審査で落ちる**か
> 2. 直さないと**必達3タスクが説明ゼロで完了しない**か
> 3. 直さないと**法令記録が欠ける／画面とAIの数字が食い違う**か

どれでもなければ `20260912-release-line.md` の「既知課題」表に1行積んで、出してから直す。
