# 国の防除マニュアルを取り込み、相談の3層目に参照元を持たせる

- 日付: 2026-09-07
- 状態: 採用（キャベツ・ぶどうの2作目のみ）
- 種別: 機能追加（外部データの取り込み）

## 課題（Why）

相談の情報源は3層に分かれている（`docs/decisions/20260906-advice-reply-tone.md`）。

| 層 | 出どころ | 状態（改修前） |
|---|---|---|
| 農薬の使用基準 | FAMIC 登録適用部の原文 | 参照元あり |
| 自農場の事実 | 自分のDB＋`src/lib` の集計 | 参照元あり |
| 作業の段取り・病害虫の一般知識 | LLM の推論 | **参照元なし** |

3層目だけが推測のままで、「推論では農業エージェントとして成立しない」という指摘を受けていた。`docs/decisions/20260906-regional-calendar-gate.md` の調査で、**防除暦は公的機関から出ていないが、国の防除マニュアルは公共データ利用規約（CC BY 4.0 互換）で取り込める**ことが分かっている。

## 決めたこと

農林水産省「[総合防除実践マニュアル](https://www.maff.go.jp/j/syouan/syokubo/gaicyu/g_ipm/)」の作目別PDFからテキストを抽出し、相談の材料として原文のまま渡す。

- 取り込みは `scripts/fetch-maff-ipm.mjs`（`npm i -D pdfjs-dist` が前提）。出力は `src/data/maffIpmData.ts`（出典URL・取得日・ライセンスを同梱した自動生成モジュール。JSON にしないのは、import 属性の要否が実行環境で違い素の Node でテストできないため）
- **写真・画像は取り込まない**。第三者の権利を含むことが多く、公共データ利用規約の適用外（`https://www.maff.go.jp/j/use/link.html`）
- API は `references`（`{title, source, text}[]`・合計12000字まで）で受け、`## 公的な防除マニュアル（原文・この範囲は資料に基づく）` としてプロンプトに置く
- **出典を `sources` に必ず載せる**。画面の「この回答の前提」に資料名とURLが出るので、利用者が原文まで辿れる（利用規約が求める出典表示でもある）

### 取り込む作目を絞る

本番の作付けと重なる **キャベツ・ぶどう** の2作目だけ。マニュアルは11作目ぶんあるが、**近い作物で代用しない**。ネギ編があるからといって たまねぎ・にんにく に当てるのは、`famic_crop_name` の誤紐付け（2026-09-06 に本番で見つけた「ほうれん草→ぶどう」）と同じ種類の誤りになる。対応が無い作物は資料を渡さず、従来どおり LLM の一般知識に「目安」と断らせる。

畑全体の相談にも渡さない（作物が定まらないため）。

### 資料の時期はそのまま使わせない

マニュアル自身が「**栽培暦は一般化したものではなく、特定の産地（群馬県・夏秋キャベツ）を想定して作成したもの**」「実際には地域の指導機関の指導に従ってください」と断っている。プロンプトでも「資料の栽培暦は特定の産地を想定した例であり、この農場にそのまま当てはめない。時期は自農場の記録と天気から述べる」と明示した。

**「いつ」は自農場のデータ、「何を・どう」は公的資料**、という切り分けは `20260906-regional-calendar-gate.md` の結論のとおり。

### 安全側の設計は変えない

資料に薬剤名が出てきても、**使用の可否は農薬登録情報（FAMIC原文）でしか判断しない**ことをプロンプトで明示している。契約テストで回帰も見ている。

## 検証

契約テストを先に書き、落ちることを確認してから実装した（`scripts/test-advise.mjs`、130 passed / 0 failed）。

実測（本物の gpt-4o-mini・キャベツ・同一質問での比較）:

| 質問 | 資料なし（従来） | 資料あり |
|---|---|---|
| 農薬を使わずにできる対策は？ | 「手作業での捕獲や除去」「マルチングやコンパニオンプランツ」（一般的な家庭菜園の助言・やること0件・出典なし） | 「**密植を避ける**」「**発病株の除去・処分**」「**天敵温存植物の利用・間作**」（いずれも資料の原文にある語彙）。**やること3件**・出典URL付き |
| いま気をつける病害虫は？ | 「アオムシやコナガ」 | 「アブラムシ類、コナガ、ヨトウムシ類」＋生育ステージへの言及 |

本番のブラウザでも確認した。キャベツの相談で「転炉スラグの施用（根こぶ病対策）」まで踏み込み、「この回答の前提」に `総合防除実践マニュアル キャベツ編（農林水産省） — 出典: https://…index-47.pdf` が並ぶ。FAMIC の登録情報（「記載なし（判定不可）」を含む）も従来どおり別枠で表示される。

## 到達できたこと・できていないこと

**できたこと**: 資料がある作目については、回答の「何を・どう」が国の公開資料に紐づき、利用者が原文まで辿れる。

**できていないこと**（正直に）:

- **正確性は保証できない。** LLM が資料を要約する過程は変わらず、資料の記述を取り違える可能性は残る。「資料に書かれていないことを資料由来として述べない」と指示してはいるが、担保はプロンプトのみ
- **対応は2作目だけ。** ほうれん草・にんにく・たまねぎには資料が無く、従来どおり推論のまま
- 抽出は PDF のテキストのみで、**図表の配置は失われる**。防除体系の図は「時期×病害虫×対策」の表なので、テキスト化すると対応関係が緩む
- コストは1回あたり入力が約6000トークン増える（約 $0.001／回）

## 影響範囲

- **DB / 権限**: なし
- **既存機能**: `api/advise.ts` に `references` を追加（省略可・従来の呼び出しは無変更）。Expo版は渡さないので従来どおり動く
- **ストア審査 / 規制**: なし。出典表示は公共データ利用規約の要件を満たす形で画面に出している
- **リポジトリ**: `pdfjs-dist` を devDependency に追加（取り込みスクリプト専用・アプリのバンドルには入らない）
