# 今回の質問を会話の最後に置く（追加質問に前の回答を返していた）

- 日付: 2026-09-07
- 状態: 採用
- 種別: 不具合修正（プロンプトの組み立て）

## 課題（Why）

本番のブラウザで相談機能を検証中に見つけた。**追加質問に対して、1つ前の回答をほぼそのまま返していた。**

実測（畑全体のスレッド・gpt-4o-mini）:

| | 内容 |
|---|---|
| 1問目 | 「今の時期、畑全体で気をつけることは？」→「今の時期は、病害虫の発生や水はけに注意が必要です。特に、連日の雨が続くと…」 |
| 2問目 | 「水はけが悪い場所はどう直せばいい？」→ **1問目とほぼ同じ書き出しをそのまま返す**。排水対策の具体には一切触れない |

「会話として続く」はエージェントが成立する3条件の1つ（`docs/decisions/20260810-next-action-advice.md`）なので、ここが崩れると機能の前提が壊れる。

## 原因

OpenAI に送るメッセージの組み立てがこうなっていた。

```
[ system, 材料ブロック（+ 今回の質問）, ...会話履歴 ]
```

会話履歴の末尾は**前回の assistant の回答**。つまりモデルから見ると「自分の回答の続きを書け」と言われている形で、今回の質問は材料ブロックの中に埋もれている。クライアントは楽観更新した保留中の質問を履歴に含めない（`setAdviseMsgs` の更新前のクロージャ値を送るため）ので、質問が最後に来ることは無かった。

## 決めたこと

質問を材料ブロックから外し、**会話の最後の user メッセージとして置く**。

```
[ system, 材料ブロック, ...会話履歴, 今回の質問 ]
```

あわせて2つ。

- 呼び出し側が送信中の質問を履歴に含めていても二重にしない（履歴の末尾が同じ質問なら落とす）。Expo版など別の呼び出し方に備えた防御
- system に「**会話の最後にある利用者のメッセージが今回の質問**。前の回答を繰り返さず、その質問そのものに答えること」を追加

## 検証

契約テストを先に書き、落ちることを確認してから実装した（`scripts/test-advise.mjs`、117 passed / 0 failed）。既存の「材料 → 会話 の順に並ぶ」テストは現在の（誤った）形を固定していたので、新しい契約に書き換えている。

本番の同じスレッド・同じ質問で前後比較した。

| | 「水はけが悪い場所はどう直せばいい？」への回答 |
|---|---|
| 修正前 | 「今の時期は、病害虫の発生や水はけに注意が必要です。特に、連日の雨が…」（前の回答のコピー） |
| 修正後 | 「水はけが悪い場所は、排水対策を行うことが重要です。具体的には、**土壌の改良や排水溝の設置、必要に応じて高畝**を作ることを検討してください。これにより、水が溜まりにくくなり、作物の根腐れを防ぐことができます。」 |

## 影響範囲

- **DB / 権限**: なし
- **既存機能**: `api/advise.ts` のメッセージ組み立てのみ。作物ごとの相談・畑全体の相談の両方に効く。他のAI機能（防除助言・記録検索・日報・画像診断）は別APIなので影響なし
- **Expo版**: 同じ `api/advise.ts` を叩くので**修正が自動的に効く**。クライアント側の変更は不要
- **ストア審査 / 規制**: なし。農薬まわりの安全側の設計は未変更
