## 1. iOS でどう課金するか（期日に直結・最優先）

### 論点

`20260912-release-line.md` は「0.1.0 に機能開発は無い」としている。しかし12月に課金を立てるなら、
**課金の導線をどこに置くかを先に決めないと、リリース内容が決まらない。**

- App内課金（IAP）を 0.1.0 に載せる → **機能開発が発生し、10月中旬のリリースが後ろ倒しになる**。Apple手数料15〜30%が乗り、グロス30万円の手残りが21〜25.5万円に落ちる
- Web決済のみ → リリースは遅れず手数料も3.6%で済むが、**App Store Review Guideline 3.1.1**（アプリ外で購入した機能をアプリ内で解放する）に触れるリスク

### 推奨: **0.1.0 に課金を載せない。課金は Web のみ。アプリ内では有料機能の解放も価格表示も一切しない。**

理由:

1. **契約するのは管理者で、管理者は Web にいる。** 利用者（worker）の作成は現状 Web 専用＝管理者は PC を使う（`20260912-release-line.md`）。席課金で財布を持つのは管理者1人なので、**Web 決済だけで307席は取れる**。アプリで払う必要があるのは「アプリしか触らない個人農家」だけ
2. リリースが遅れない。0.1.0 の目的は審査を通すこと、という既存の判断を覆さずに済む
3. 手数料が3.6%で済み、**グロス30万円がほぼそのまま手残りになる**
4. 3.1.1 は「**アプリ内で解放しない**」なら回避できる。アプリは記録の道具として無料のまま出す

**やらないことを明記する**: アプリ内に価格・プラン・アップグレードのボタン・外部サイトへの誘導を置かない。
置いた時点で 3.1.1 に触れる。**DR-6 の結果でこの境界を再確認する。**

リスク: iOS しか使わない個人農家は課金できない。→ 0.2.0 で IAP を入れる。12月の目標には載せない。

## 2. トライアル明けに何が止まるか（最重要・既存方針と衝突）

### 論点

7日トライアルの後、**記録の登録まで止めると、蓄積がゼロになる。**
`references/product-context.md` は「段階1（今）の最優先＝入力継続率」と書いており、正面から衝突する。

### 推奨: **記録は永久に無料。止めるのは「読み返し・分析・AI・2席目以降」。**

| | 無料（トライアル明け以降もずっと） | 有料 980円/席 |
|---|---|---|
| 作業記録の登録 | **無制限** | 同左 |
| 圃場・作物・農薬の登録 | 可 | 同左 |
| 記録の閲覧 | **直近◯日ぶんのみ** | 全期間 |
| 検索・分析・グラフ | 不可 | 可 |
| AI（相談・診断・音声・記録検索・防除助言） | 不可（またはごく少数の体験枠） | 可 |
| 帳票出力 | 不可 | 可 |
| 利用人数 | **1席** | 席数ぶん |

これは業界2強と同じ「**蓄積データの活用範囲**」型の課金軸で、
`20260823-pricing-plan-review.md` の論点2（「課金軸を機能から蓄積データの活用範囲へ移すか」）に対する答えでもある。

**この形の良いところ**: 使えば使うほど「見られない過去」が増えて転換の動機が育つ。
記録は止まらないので蓄積も続く。乗り換えコストも効く。

**「直近◯日」の値だけ DR-2 待ち。** アグリハブの無料枠（分析10ヶ月）より**厳しく**引く必要がある
（競合の無料枠より緩いと課金理由が消える）。30日を初期値として置き、DR-2 の結果で確定する。

## 3. Team プラン（2,980円/組織）と席課金は両立しない

### 論点

`docs/roadmap.md` の料金表は Pro 980円/月（個人）・**Team 2,980円/月/組織（10人まで）**。
席課金 980円/席 だと **10席＝9,800円**。**Team の方が3倍安く、席課金が成立しない。**

### 推奨: **プランは 980円/席 の1本にする。Team は廃止（=「10席まで定額」という形では作らない）。**

理由: 12月まで10週しかない。プランが複数あると、説明・実装・判定・画面が全部倍になる。
大口の割引が必要になったら、**席数に応じた逓減（例: 11席目以降は割引）として後から足せる**。
その方が席課金と矛盾しない。

`20260823-pricing-plan-review.md` は「Team の課金理由がアグリハブの無料プランと重複している」と
既に指摘していた。本ログはその指摘を、**プランを消す**という形で解決する。

## 4. 「席」の定義（詰まっていない）

決めるべきこと:

| 論点 | 推奨 |
|---|---|
| 席の単位 | **ログインできるアカウント1つ = 1席**。管理者も1席（個人農家は1席980円） |
| 席の増減 | **即時反映・日割りなし・課金は翌月から**。日割りを入れると実装と説明が跳ね上がる |
| 季節雇用の扱い | 農業の労働力は繁忙期に膨らみ農閑期に縮む（`agriculture` / `labor-and-safety.md`）。**12月は多くの作目で農閑期＝席数が年間最少になる月**。ここが目標に直撃する |
| その対策 | **年払い（例: 9,800円/席）を用意して席を固定する。** 月払いだけだと12月に席を減らされる |
| 家族の席 | 3席払うかは DR-3 / DR-5 待ち。ただし**「1席目は本人・2席目以降は同額」以外の形（家族割・2席込み）は、ARPU が下がるので採らない**（3席×980円が達成条件①そのもの） |

**季節性は設計で殴れる論点。** DR-8（12月は農閑期か）の結果を待たず、年払いの用意だけは先に決められる。

## 5. 自組織（霧珠ファーム）を計測から除外する

自分の農場は永久無料にするとして、**そのまま数えると転換率が歪む**。
記録18件・worker 0人という現状の数字が、新規の登録者と混ざる。

推奨: `organizations` に `is_internal boolean default false` を持ち、**指標の集計から常に除外**する。
`plan-gtm-980-2026-09.md` 2-G ⑤の指標定義に、この除外を明記する。

## 6. DB とアクセス判定（実装の受け皿）

### DB

`organizations(id, org_key, name, plan, status, ...)` は既にある。足りないもの:

| カラム | 用途 |
|---|---|
| `trial_ends_at timestamptz` | 7日トライアルの期限。ここが課金判定の中心 |
| `seats_paid int` | 課金対象の席数。`users` の行数とは別に持つ（無効化したユーザーを除くため） |
| `billing_customer_id text` | 決済側のID |
| `is_internal boolean` | 上記5 |

`plan` は既存だが、値の定義（`'free' | 'paid'`）を確定させる。

### アクセス判定

`src/ui/aiFeatures.ts` の `canUseAiFeature` が、`roadmap.md`「実装順序の原則」どおり
**AI機能については1箇所に集約されている**（全部 `true` を返す仮実装）。

**ただし AI 以外のゲートが存在しない。** 上記2の設計だと、主な課金ポイントは
「**過去◯日より前の閲覧**」「分析」「帳票」「2席目以降」であり、そこに判定が1つも無い。

推奨: `aiFeatures.ts` を `src/ui/entitlements.ts` に格上げし、AI以外も同じ関数を通す。

```
canUse('recordHistoryBeyondFreeWindow' | 'analytics' | 'export' | 'aiVoiceStructuring' | ...)
```

**仮実装のまま（全部 true）で先に全画面を通しておく**のが `roadmap.md` の原則。
決済が決まった日に、この関数の中身だけを差し替える。

### AI の日次上限との関係

`api/_auth.ts` の `DAILY_LIMIT`（診断20/日・他50/日）は現在**プランに関係なく全員に効いている**。
上記2で AI を有料側に置くなら、**無料は「不可」または体験枠（1日1回）、有料は現行の上限**という
2段構えになる。`DAILY_LIMIT` をプラン別の表に変える。

## プレモータム

1. **0.1.0 を課金なしで出したら、Apple が「有料サービスの一部なのにIAPが無い」と指摘した。** → アプリ内に価格・プラン・外部誘導を一切置かないことで回避する。DR-6 でガイドラインの原文を確認し、境界を明文化する
2. **記録は無料のままにしたので、誰も課金しなかった。** → 転換の動機は「見られない過去」に置いている。無料の閲覧窓（初期値30日）が広すぎると効かない。第5週の転換率が18%を下回ったらこの窓を狭める（`plan-gtm-980-2026-09.md` 2-G ④）
3. **繁忙期に増えた席が、12月に減らされて目標を割った。** → 年払いで固定する。用意が間に合わなければ、12月時点の席数は繁忙期のピークより減る前提で目標を引き直す
4. **プランを1本にしたら、複数人で使う農場が「人数ぶん払うのは高い」と離れた。** → アグリハブは「何人でも無料」なので、ここは正面衝突する。DR-2 で無料枠の上限を確定し、席課金で上回る価値（AI・全期間の閲覧・帳票）を明示できるかを見る。できなければ課金軸を席数から外す
