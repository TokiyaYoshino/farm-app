# AI機能の文言・記号を「国内アプリの馴染みのある形」に寄せる

- 日付: 2026-09-09
- 状態: 採用（Web版のみ実装。Expo版は未反映）
- 種別: 仕様変更（UI文言・アイコン・情報設計）
- 上書きする判断: [`20260823-ai-wording-outcome-based.md`](20260823-ai-wording-outcome-based.md) の一部（下記「過去の判断との関係」）

## 課題（Why）

「AI機能をもっと使いやすい位置・認識しやすい場所に」という相談から始まったが、実際に求められていたのは2つだった。

1. **AI感をなくす** — 手段（AI）ではなく動作・成果で見せる。記号も含めて
2. **みんなの馴染みのあるデザインに寄せる** — 見慣れない形は、それ自体が使われない理由になる

前回（8/23）は文言から「AI」を外す対応表を作ったが、**語形が揃っておらず**（「日報にまとめる」「帳票出力」「次の散布はいつ？」の3形が混在）、**記号は手つかず**だった。

## 調査（`docs/research/ai-placement-jp-apps-2026-09.md`）

国内の大規模アプリ25機能を数えた結果、**想定と違っていたことが3つ**あった。

| 実測 | 意味 |
|---|---|
| 機能名は**体言止めが約9割**（22/25）。「〜する」終止形・問いかけ形は**0件** | 「次の散布はいつ？」は国内の慣行の外 |
| **「AI」語は約7割が名前に出している** | AI語を隠すのは国内の多数派ではない。ただし Yahoo!ニュースが「コメントAI要約（β版）」→「ヤフコメまとめ」でAI語を削除、あすけんが「AIおまかせ記録」と併存で「話して記録」を出すなど**揺り戻しも観測できる** |
| **✨きらめきアイコンは国内事例で1件も確認できず**。国内の特徴はキャラクター委譲（未来さん／マーキュリーさん／にゃんチャレAI） | farm-app は Sparkles を3箇所で使用していた＝国内の見た目からむしろ外れていた |

日本語UIライティングの規範は**国内で割れている**（GitHubの一次ソースで確認）: SmartHR Design System は「ボタンラベルには**動詞の終止形**を使用する」、Mozilla日本語ローカライズは「ボタンラベルは**体言止め**を原則とする」。両者が一致するのは**「画面タイトル・項目名は名詞」**の一点のみ。

## 決めたこと

### 1. 語形のルール（`CLAUDE.md` の規約に明記）

| 種類 | 形 |
|---|---|
| 押すと処理が走るボタン | 動詞（日報にまとめる／写真で調べる／話して記録） |
| 画面名・タブ名・カード見出し・シート見出し | 体言止め（次の散布時期／ふりかえり） |
| 別画面へ移動するだけの行 | 体言止め（帳票出力） |
| 問いかけ形 | **使わない** |

国内の指針が割れている以上、farm-app として1つ決めて記録に残す。両者が一致している「画面タイトル・項目名＝名詞」は必ず守る。

### 2. AI語は入口から外し、履歴と注意書きには残す（非対称にする）

「誰が書いたか」を全部隠すと不誠実になる。**日常の操作からはAI色を抜き、仕組みを知りたい場所（分析タブのAI出力履歴）と、誤ると実害が出る注意書き（農薬・診断）では明示する。**農薬・診断の注意書きは一字も変えていない。

### 3. ✨Sparkles を廃止し、記号の衝突を解く

| 変更前 | 変更後 | 理由 |
|---|---|---|
| `Sparkles`（日報・音声構造化・分析履歴の3箇所） | 日報→`FileText` / 音声構造化→`Mic` / 分析履歴→`History` | Sparkles は「AIです」と名乗る記号そのもの。国内事例で不在 |
| `FlaskConical`（病害虫診断 **と** 使用農薬の両方） | 診断→`Bug` / 農薬→`FlaskConical` のまま | 同じ記号が別の意味に使われていた。`Bug` は分析タブ「病害虫診断の発生傾向」と意味が揃う |
| `Wind`（防除助言 **と** トーストの成功アイコン） | トースト成功→`Check` | 同上 |

### 4. 文言の変更（Web版）

| 変更前 | 変更後 |
|---|---|
| 次の散布はいつ？ | **次の散布時期**（ホームのボタン・シート見出し） |
| 助言を確認 | **散布時期を調べる** |
| AIでフォームに自動入力 ／ AIで整理中… | **メモから項目を埋める** ／ 整理中… |
| AIでフォームに反映しました（トースト） | **メモから項目を埋めました** |
| AI整理に失敗しました（トースト） | **項目を埋められませんでした** |
| 日報を生成 ／ 生成中… ／ もう一度生成 | **日報にまとめる** ／ まとめ中… ／ もう一度まとめる |
| 写真を撮影・選択すると、病害虫の可能性をAIが診断します | **写真から病害虫の可能性を絞り込みます。確定診断ではありません。** |
| 記録に聞いてみる | **記録に聞く**（シート見出しと同じ語に統一） |

最後の1つは文言統一だけでなく**欠落の修正**でもある。Web版の単体診断シートには「確定診断ではない」旨がなく、Expo版にはあった。

### 5. 配置

1. **`＋記録` シート最上部に入力手段の3択**（話して記録／写真で調べる／手で入力）。音声メモ構造化は仕様書が「入力摩擦を減らす最も直接的な打ち手」と位置づけているのに、**6機能でいちばん深い場所**にあった（「詳細を入力」を開き、メモ欄までスクロールし、しかもAI振り分けボタンはメモが空だと画面に存在しない＝押す前にあることが分からない）。あすけんが「＋」の直下に「話して記録」を置いているのと同じ形にする。**既存のメモ欄の音声ボタンは残す**（入口を増やしただけ）
2. **ホームに「ふりかえり」カード1枚**（今日の記録◯件→日報にまとめる／記録に聞く／帳票出力）。3つとも「記録しない日に用がある機能」なのに、記録タブの奥にあった。カードを3枚増やすとホームが second 記録一覧になるので1枚に3行
3. **タブ名「記録」→「カレンダー」**（アイコンも `PenLine`→`CalendarDays`）。タブの中身はカレンダーと記録一覧で**どちらも見るだけ**、作るのは FAB「＋記録」。**名前だけが「書く場所」を指していた**うえ、FABと名前が衝突していた
4. ホームの「写真で病害虫を調べる」を tertiary → **soft** に格上げ

## 検討した代替案

- **キャラクターに委譲する（未来さん型）** → 今回は見送り。国内で最も実績のある手だが、擬人化は「このアプリはAIです」と名乗るのと同じで、AI感をなくす目的と正面から矛盾する。キャラ設計と語り口統一のコストも別途かかる。将来の選択肢として調査に残した
- **AI語を徹底的に隠す（履歴からも消す）** → 見送り。自動生成された文章を人が書いたものと誤解されるリスクを負うことになる
- **国内多数派に合わせて「AI」を出す** → 見送り。汎用AIと差がつかない訴求になる（8/23 の判断を維持）
- **問いかけ形を増やして差別化する** → 見送り。「見慣れない形」は馴染みのなさと表裏で、今回の目的と逆方向

## 影響範囲

- **DB / 権限 / API**: なし。`ai_outputs.kind` などの内部識別子も未変更
- **既存機能**: 削除なし。メモ欄の音声ボタン・記録一覧の各ボタンはすべて残っている（規約どおり）。「記録に聞く」「帳票出力」はホームからも開けるようになっただけ
- **既存利用者への影響**: タブ名の変更が唯一「慣れを崩す」項目
- **ストア審査 / 規制**: なし。農薬・診断の注意書きは文面・位置とも不変。日本にAI表示の法的義務は現時点でない（AI新法は理念法で努力義務・罰則なし）が、分析タブでAI由来であることを明示し続ける方針は維持

## プレモータム（半年後に失敗していたとしたら）

1. **3択が「余計な1段」になった。** 手で入力したいだけの人が毎回3択を通ることになり、記録の速度が落ちた。→「手で入力」を選んだら畳む実装にはしたが、選択を記憶していないので毎回出る。実利用で嫌がられたら既定を記憶する
2. **タブ名を変えたせいで既存利用者が迷った。** 本番の利用者は5人（全員admin）なので影響は限定的だが、混乱が出たら戻せる1行
3. **体言止めに寄せた結果、何が起きるボタンか分からなくなった。**「次の散布時期」は押すと助言が出るが、名前からは分からない。→ ボタンは動詞のまま残す規則にしてあるが、この1つは問いかけ形の廃止を優先して体言止めにした。要観察
4. **効果が測れないまま。** `ai_outputs` は全11件がすべて開発時の動作確認で、本番の worker は0人。**今回も、良くなったことも悪くなったことも測れない**
