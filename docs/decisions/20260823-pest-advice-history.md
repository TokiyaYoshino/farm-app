# 防除助言に自農場の防除履歴を注入する

- 日付: 2026-08-23
- 状態: 採用
- 種別: 仕様変更

## 課題（Why）

競合調査（2026-08）で、残った差別化が1つだけであることが分かった。

> **記録する場所と、AIに聞く場所が、同一プロダクト内にある。**

- 栽培アシストAI（農林中金アグリウェブ、月1,100円）: 情報サービスの有料オプション。記録は「登録・投入」が必要
- アグリハブ「AI栽培レポート」: 記録からレポートへの一方通行。対話ではない
- 汎用生成AI（ChatGPT / Gemini）: 「今週の天気でぶどうのべと病どうする？」は**無料で聞ける**

つまり「AIが使えること」自体に課金価値は無い。課金できるのは**その農家自身の記録を読んだうえで答える**部分だけ。

ところが実装を確認すると、その唯一の差別化が既存2機能の谷間に落ちていた。

| API | 天気を見る | 自農場の記録を見る |
|---|---|---|
| `api/pest-control-advice.ts`（防除助言） | ○ | **×** |
| `api/search-chat.ts`（記録検索） | × | ○ |

防除助言は Open-Meteo の予報と、任意で選んだ農薬の FAMIC 適用情報しか見ておらず、**その農場が前回いつ何を撒いたかを一切参照していなかった**。この状態の出力は汎用生成AIと区別がつかない。

## 決めたこと

`api/pest-control-advice.ts` に `sprayHistory`（クライアントで整形済みの自農場の防除記録）を渡し、助言に反映させる。

整形は `src/lib/pesticideUsage.ts` の `formatSprayHistoryForPrompt()` に集約（Expo版は同ファイルのコピー）。渡す内容は4つ。

1. **前回の散布からの経過日数**
2. **直近の散布履歴**（新しい順・既定12件）
3. **同じ商品を繰り返し使っている組み合わせ**
4. **昨年の同時期**（今日の1年前 ±14日）の防除内容

プロンプト側では、記録に触れるとき「あなたの記録では」と明示させ、一般論と区別させる。記録を読んでいることが利用者に伝わらないと差別化にならないため、UI の説明文にも「この農場の防除記録も踏まえて提案します」と明記した（T2 と併せて実施）。

### 「同一系統薬剤の連用」は実装しない（重要）

引き継ぎ資料の T1 は「同一系統薬剤の連用」を助言に反映するよう求めていたが、**farm-app のデータでは判定できないため実装しない**。

- `pesticide_registrations` は FAMIC 登録適用部（商品 x 作物 x 病害虫の適用行）のみで、**有効成分・RACコードの列を取り込んでいない**（`api/pesticide-registration.ts` の `COL` 定義）
- `src/lib/pesticideUsage.ts` は既に「商品単位の集計。同一有効成分を含む他剤との合算はしない（次段の課題）」と明記しており、本件も同じ制約下にある

したがって出せるのは**商品名の一致による連用**までとし、プロンプトで次を禁じた。

- 「同一系統の連用になっている」「系統をローテーションできている/できていない」といった系統・成分に基づく断定
- 記録が無い期間を「散布していない」と断定すること（記録し忘れと区別できないため）

同じ商品名の繰り返しは事実として指摘してよいが、それが系統の重複にあたるかは**製品ラベルの有効成分表示で確認するよう促す**。`summarizeUsage` が「上限に達していない」を「使用可」と言わないのと同じ非対称性を踏襲している。

## 検討した代替案

- **案B: 有効成分の列を FAMIC から追加取得して系統判定まで実装する** → 見送り。登録適用部CSVに成分列が無く、別データ源（登録番号→成分の突合）が要る。RACコードに至っては FAMIC が配布していない。**間違った系統判定は使用者を誤った防除設計に導く**ため、データが揃うまで判定不可に倒す
- **案C: 助言を作付け単位に作り替え、作物ごとに防除履歴を渡す** → 見送り（今回は範囲外）。現在の防除助言は農場単位の「今週いつ撒けるか」であり、作付け単位の相談は既に `api/advise.ts`（農業エージェント）が担当している。two機能の役割が重複する
- **現状維持** → 見送り。唯一の差別化が実装されていない状態になる

## 影響範囲

- **DB / 権限**: 変更なし。新テーブル・新カラムなし。RLSへの影響なし
- **既存機能**:
  - `api/pest-control-advice.ts` は `sprayHistory` を**任意パラメータ**として受ける。未指定なら従来どおり天気だけで助言する（この場合は「記録を見たかのように書かない」指示をプロンプトに入れている）ため、後方互換
  - `src/lib/pesticideUsage.ts` は追記のみ。既存の `summarizeUsage` / `formatPesticideUsageForPrompt` は未変更
  - Web版・Expo版の両方の呼び出し元を接続済み
- **ストア審査 / 規制・業界固有の実務**:
  - 農薬使用基準の遵守は**法的義務**（農薬取締法）。今回の変更で使用回数・使用時期の判定を AI に肩代わりさせてはいない。基準に関わる数値は従来どおり FAMIC 原文を渡し、決定的な判定は `summarizeUsage` 側に残している
  - 「必ず製品ラベルの表示を確認する」よう促す既存の指示は維持

## プレモータム（半年後に失敗していたとしたら、何が起きたか）

1. **記録が薄いまま出したので差別化が発揮されなかった。** 本番の散布記録は6件（うち1件は農薬が未記録）。前回散布・昨年同時期が「記録なし」ばかりになり、汎用AIとの差が利用者に伝わらない。→ 差別化の実現は**記録が貯まっていること**に依存する。worker アカウント未整備（`docs/handoff-input-redesign.md`）の解消が前提条件になる
2. **AI が禁止を破って系統の連用を断定し、誤った防除設計に導いた。** プロンプトの禁止は絶対ではない。→ 将来、出力の後段フィルタ（「系統」「ローテーション」の語を含む断定を検出）を検討する余地がある
3. **文字数上限で履歴が黙って落ち、「載っていない＝撒いていない」と読まれた。** → 打ち切り時は件数・節数を必ず明記する実装にし、テストで固定した
