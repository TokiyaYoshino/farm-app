# ポジションを「記録を知っているAI」から「今日から使えて、使うほど自分の畑の話になる」へ

- 日付: 2026-09-22
- 状態: 採用
- 種別: ポジショニング・訴求文言（ストア名／サブタイトル／オンボーディング）
- 関連: `20260922-onboarding-and-signup.md`（文言の適用先）、`docs/research/app-naming-2026-09.md`（名前）、`20260823-ai-wording-outcome-based.md`（AI語）、`20260907-national-references.md`（国の資料）、`20260906-advice-reply-tone.md`（集計の受け渡し）

## 課題（Why）

名前の検討で「**あなたの記録を知っている AI**」をサブタイトル案に出した。
オーナーの指摘で**この案の欠陥が分かった**。

> 記録がないと AI が効果を発揮しないのでは？ってなる。
> 記録を溜めなきゃいけないというのは、かなりのマイナス。

**正しい。** ストアでこの文を読むのは**まだ1件も記録が無い人**で、
「記録を持っている人向けのアプリ」と読める。**DL 直後にいちばん離脱する形**の言い方だった。
畑らく日記の実測では DL の75%が消える（`dl-target-20k-2026-09.md`）。

## 調べたら、プロダクトは既に正しい形をしていた

`api/advise.ts` は**記録ゼロの経路を明示的に持っている**（248〜275行）。

```
hasRecords が false のとき:
「作業記録は渡されていない。過去の作業実績を知っている前提で書かないこと
（『前回の防除から』等と書かない）」
```

そして**記録がゼロでも渡している材料が3つある**。

| 層 | 材料 | 記録が要るか |
|---|---|---|
| **1. 初日から** | 農水省 総合防除実践マニュアル（**出典URL付き**・`src/data/maffIpm.ts`）／天気（Open-Meteo・気象庁警報）／農薬登録情報（FAMIC 原文） | **不要** |
| **2. 数件溜まると** | 前回の散布からの日数／今年の作業回数／同一商品の連用／**使用回数と上限の並記** | 数件から効く |
| **3. 1シーズン溜まると** | 昨年同時期比／年次の振り返り／**助言と作業実績の照合**（`adviceMatch.ts`） | 1年 |

**＝ 直すのは製品ではなく言い方だけ。**

## 決めたこと

### 1.「溜めるほど良くなる」を主語にしない

オーナーの提案（「記録がなくても、溜めていくことでさらに良くなる見せ方」）は正しいが、
**語順を間違えると逆効果になる。**

| | 読まれ方 |
|---|---|
| ✗ **あなたの記録を知っているAI** | 記録が要る。持っていない自分は対象外 |
| ✗ **記録を溜めるほど賢くなるAI** | **今は賢くない**、と読める |
| ○ **今日から聞ける。使うほど、あなたの畑の話になる** | 今すぐ価値がある＋育つことも伝わる |

**規則: 初日の価値を主語に置き、成長は述語で言う。**
「溜めるほど」を文頭に置いた瞬間、現在価値の否定になる。

### 2. サブタイトル（30文字枠）

**採用: 「農薬も防除も今日から相談。記録するほど詳しくなる」**（24文字）

- 「今日から」で**記録ゼロでも使えること**を最初に言う
- 「農薬も防除も」で**具体的に何を聞けるか**を示す（ChatGPT との差ではなく、用事の提示）
- 「記録するほど詳しくなる」で**溜める動機**を述語に置く
- 問いかけ形を使わない・カタカナ語を使わない（`CLAUDE.md`）

次点: 「はじめから使える。記録するほど答えが具体的になる」（24文字）

### 3. ChatGPT との差は「賢さ」ではなく「材料」だと言い切る

オーナーの整理（「ChatGPT は何でも聞けるが、アウトプットの差をつけたい。
相談の結果や溜まったデータを参照して回答する」）はそのまま採る。
`docs/research/app-naming-2026-09.md` 12章の結論と一致している——
**farm-app の差は モデルの賢さではなく、渡す材料と間違えない設計**。

訴求でも「AIが優れている」とは言わない。**「何を見て答えているか」で言う。**

### 4. 約束を画面で見せる（実装・小）

言い方を変えるだけでは、**育つという約束が確かめられない**。
相談の返答に既にある「前提」の畳み（`src/App.tsx:5895-5910`・`sources` / `limits`）を使って、
**いま何を参照したかを常に出す**。

```
記録0件のとき  : 参照 — 国の防除マニュアル（出典URL）／今日の天気
記録12件のとき : 参照 — 国の防除マニュアル／今日の天気／あなたの記録12件
1年経ったとき  : 参照 — …／あなたの記録148件／昨年の同時期
```

**件数が増えていくのが見えること自体が、溜める動機になる。**
新しい仕組みは要らない（`crop_advice_messages.sources` は実装済み）。

**この実装はアプリ名の決定後**（オンボーディング作業の再開と同時）に行う。

## 検討した代替案

- **案B: 初回に見本データを入れておく**（記録がある状態から始める） → 見送り。
  自分の畑の話でない数字が最初に出ると、**画面とAIの数字が食い違わない**という
  farm-app の設計原則（`20260906-advice-reply-tone.md`）を入口で壊す。
  デモモードは「デモを見る」として**明示的に分けてある**（`20260909-demo-mode.md`）
- **案C: 記録が無いうちはAIを出さない** → 見送り。初日の価値が消え、
  「記録アプリ＋おまけのAI」になる。取りたいポジション（農業×AIエージェント）と逆
- **現状維持（「あなたの記録を知っているAI」）** → 見送り。上記のとおりDL直後に最も効く離脱要因

## 影響範囲

- **DB / RLS**: なし
- **既存機能**: なし（`api/advise.ts` の記録ゼロ経路は既存。実装は4節の表示のみ）
- **AppStore**: サブタイトル（30文字）とキーワード欄の文言。**名前の決定とセットで確定する**
- **オンボーディング**: 紹介3枚目（`src/components/Onboarding.tsx` / `expo-prototype/screens/OnboardingScreen.tsx`）の
  本文が「前回の散布からの日数や、今年の作業の回数をふまえた答えが返ります」となっており、
  **記録がある前提で書かれている。名前の決定後に上の規則で書き直す**（未実施）
- **法規・農業実務**: なし。ただし「初日から答える」層は**国の資料と天気と農薬登録情報だけ**で、
  自農場の使用回数は含まれない。**初日の回答で使用基準の遵守を保証しない**点は従来どおり

## プレモータム（半年後に失敗していたとしたら）

1. **「今日から聞ける」と言ったのに、初日の回答が一般論すぎて期待外れだった。**
   → 1層目の品質（国の資料が無い作物は推論のまま・`20260906-regional-calendar-gate.md` で
   残り3作目が未取り込み）が、そのまま訴求の裏付けになる。**資料の作物数を増やすことが訴求の担保**
2. **「参照」の表示が常に同じで、育っている感じがしなかった。**
   → 件数と種類が実際に増える設計になっているか、実装時に確かめる
3. **言い方だけ変えて、記録が増えない。** → 記録を増やすのは配布と入力UXの仕事で、
   訴求の仕事ではない（`20260922-marketing-before-store.md` の施策A）。混同しない

## 追記（2026-09-22）: 国の防除マニュアルの網羅 — **上限は11作目・残り9本**

「今日から聞ける」と言う以上、1層目の品質が訴求の担保になる、と上に書いた。
オーナーの判断で**国の防除マニュアルの網羅を優先項目に上げる**。

### 網羅の範囲は有限（ここが重要）

農水省「総合防除実践マニュアル」が扱うのは**11作目で打ち止め**。

| | 作目 |
|---|---|
| **取り込み済み（2）** | キャベツ／ぶどう |
| **残り（9）** | **イネ／ネギ／施設キュウリ／露地ナス／トマト／イチゴ／カンキツ／リンゴ／ナシ** |

**「網羅」は無限の作業ではなく、9本のPDFを取り込むこと。** `scripts/fetch-maff-ipm.mjs` に
URL を足して1回走らせれば終わる（PDF抽出は実装済み・ライセンスは公共データ利用規約で商用可）。

**カンキツが入っている**点は本番の作付けに直接効く。

### 11作目で全部は覆えない — 訴求の限界を正確に言う

本番の作付けのうち**ほうれん草・にんにく・たまねぎはマニュアルが存在しない**
（`20260906-regional-calendar-gate.md`）。**近い作物で代用しない**方針は維持する
（ネギ編があるからといって たまねぎ・にんにく に当てない）。

ただし**1層目は防除マニュアルだけではない**。

| 1層目の材料 | 作物を問わず効くか |
|---|---|
| 天気（Open-Meteo・気象庁警報） | **全作物** |
| 農薬登録情報（FAMIC 原文・総使用回数・希釈倍数） | **全農薬＝実質全作物** |
| 国の防除マニュアル | **11作目のみ** |

**だからサブタイトル「農薬も防除も今日から相談」は正確。**
「農薬」は FAMIC で作物を問わず初日から答えられ、「防除」は11作目で深くなる。
**逆に「どんな作物でも詳しく答えます」とは言えない。**

### この環境からは取り込めない（未実施の理由）

`www.maff.go.jp:443` が**egress ポリシーで 403（CONNECT 拒否）**。
プロキシの状態にも `connect_rejected / www.maff.go.jp:443` が記録されている。
**ポリシー拒否は再試行しない**運用なので、**取り込みはオーナーの手元で実行する。**

```
# 9本のURLを scripts/fetch-maff-ipm.mjs の TARGETS に足してから
npm i -D pdfjs-dist
node scripts/fetch-maff-ipm.mjs
```

**URL は推測で埋めない。** `index-NN.pdf` の番号を取り違えると**他作物の基準を提示する**
ことになり、`20260824-plain-language-and-crop-mapping.md` が禁じた誤紐付けと同じ種類の
事故になる。一覧ページ（https://www.maff.go.jp/j/syouan/syokubo/gaicyu/g_ipm/ ）から
**作目名とリンクの対を目で確認して**入れる。
