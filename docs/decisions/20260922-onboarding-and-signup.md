# 起動直後のオンボーディングとセルフサインアップを 0.1.0 に入れる

- 日付: 2026-09-22
- 状態: 採用
- 種別: 新機能（申請前の追加スコープ）
- 関連: `20260912-release-line.md`（リリース線・今回その「機能開発ゼロ」を意図的に破る）、`20260824-no-manual-test.md`（説明は最後の手段）、`20260909-demo-mode.md`（デモデータ）、`20260907-rls-bootstrap-fallback.md`（組織解決）、`20260922-marketing-before-store.md`（配布計画）

## 課題（Why）

**ストアからDLした人は100%詰む。** 起動すると `src/App.tsx:2930-2978` の
ログイン画面（タイトル＋ID＋パスワード）がいきなり出るだけで、

1. **何のアプリか分からない**（説明が1行も無い）
2. **アカウントを作る手段が無い**。作成は管理者のみ（`invForm` → `api/set-user-auth`、`requireAdmin`）

★1レビューが付く典型で、調査（`dl-target-20k-2026-09.md`）の
「★4未満だと提携の話が始まらない」に直撃する。

## 決めたこと

**0.1.0 に、ようこそ画面・チュートリアル・セルフサインアップ・アカウント削除を入れる。**

`20260912-release-line.md` は「App Store に必要な機能開発はゼロ」と線を引いていたが、
**その判定は「アカウントは管理者が配る」前提で書かれていた**。ストア公開は不特定多数への
配布なので前提が変わる。**今回は意図的にこの線を破る**（破ったことを記録するのがこの節の目的）。

### 入れるもの

| # | 画面・機能 | 中身 |
|---|---|---|
| 1 | ようこそ | 何ができるか3行。[はじめる]（primary）/[ログイン]/[デモを見る] |
| 2 | チュートリアル | 3枚。**記録する → 使いすぎを防ぐ → 相談する**。各1画面1メッセージ。いつでもスキップ可 |
| 3 | サインアップ | 農場名・お名前・ユーザーID・パスワード。**組織＋管理者を同時に作る**（`api/signup.ts`） |
| 4 | デモを見る | 認証なしで `demoData` を描く。**既存のデモモードをランタイムに解禁**する |
| 5 | アカウント削除 | メニュー内。**5.1.1(v) で必須**（下記） |

### チュートリアルの中身を「操作説明」にしない

`20260824-no-manual-test.md` は説明を**最後の手段**に置いている。それと矛盾させないため、
**チュートリアルは操作手順を教えない。** 「何ができるか」だけを見せ、**どこを押すかは書かない**。

- ✗「右上の＋ボタンを押すと記録できます」（操作説明＝no-manual-test が禁じている側）
- ○「その日やったことを、写真と一緒に残せます」（価値の提示＝ストア文脈の穴を埋める側）

判断基準: **その文がアプリを触らないと意味を成さないなら操作説明で、入れない。**

### App Store 5.1.1(v): アカウント削除は「付いてくる」

**アプリ内でアカウント作成を提供するなら、アプリ内からのアカウント削除が必須。**
招待制の今は発生していない要件で、サインアップを足した瞬間に申請物になる。

削除の仕様は役割で分ける。**破壊的操作なので確認モーダルを挟む**（`CLAUDE.md` の danger 規約）。

| 誰が | 何が消えるか |
|---|---|
| worker | 自分の `users` 行と Auth ユーザーのみ。**記録は組織に残す**（農薬の使用回数の集計が欠けると法令記録の正確性が崩れるため） |
| admin（他に管理者がいる） | 同上 |
| admin（組織で最後の1人） | **組織ごと消す。** 残すと誰も入れない組織と、宙に浮いた記録だけが残る |

**記録を残す選択を明示する。** Apple が求めるのは「アカウントの削除」であって
「組織の業務記録の削除」ではない。削除画面に**何が消えて何が残るかを書く**。

### 越境アクセス実地テストが、これで必須になった

サインアップは **`organizations` に行を増やす機能**そのもの。
`20260922-marketing-before-store.md` で「A-2（他農場へ配る）の唯一の前提」としていた
越境アクセス実地テストが、**申請の前提に繰り上がる**。

理由: 公開した瞬間に2組織目・3組織目が自動で生まれる。RLS が組織で切れていなければ、
**他人の農場の農薬使用履歴が読める**。`20260907-rls-bootstrap-fallback.md` の
フォールバック（`users.auth_id` から `organization_id` を引く）は入っているが、
**新規作成された組織で実地に確かめたことはまだ一度も無い。**

**サインアップで作った2組織目そのものを、越境テストの被験体にする。** テストのために
組織を用意する手間が消えるので、順序としてはむしろ都合がよい。

## 検討した代替案

- **案B: ようこそ1画面だけ入れ、サインアップは 0.2.0**（当初の推奨） → **採用せず。**
  オーナーの判断で、ストアから来た人が自分で始められる状態を 0.1.0 で作る。
  申請は後ろ倒しになるが、「DLしても何もできないアプリ」を出す損失の方が大きいという判断
- **案C: 招待コード制**（管理者が発行したコードでのみ登録可） → 見送り。ストアから来た人には
  コードが無いので、詰む構造が変わらない。配布が手渡しに戻るだけ
- **案D: チュートリアルを動画・GIFにする** → 見送り。高齢層中心・通信環境が悪い圃場で開く前提に合わない

## 影響範囲

- **DB**: 新規テーブルなし。`organizations` と `users` に行が増える経路が1本増えるだけ
- **RLS**: ポリシー変更なし。作成は service_role（`api/signup.ts`）で行い、
  **anon に insert 権限を与えない**。`users_select_login_lookup`（anon・`qual=true`）は
  今回広げない（`20260907-rls-bootstrap-fallback.md` が却下した拡大に当たるため）
- **既存機能**: 削除なし。招待（`api/set-user-auth`）はそのまま残す。
  **管理者が worker を作る経路と、本人が組織を作る経路が併存する**
- **AppStore**: 5.1.1(v)（削除必須）が新たに発生。2.1（デモアカウント）は
  「デモを見る」で審査員が中身を見られるため軽くなる。4.2（機能が最小限）への反論材料にもなる
- **API**: 新規2本。`api/signup.ts` は**唯一の未認証エンドポイント**になるので、
  乱用対策（入力検証・作成レートの上限）を同ファイル内に持たせる
- **法規・農業実務**: 削除時に**作業記録を消さない**方針が農薬の使用回数の集計（法的義務である
  使用基準の遵守支援）を守る。人が抜けても記録は組織に残す

## プレモータム（半年後に失敗していたとしたら）

1. **公開したサインアップが荒らされ、空の組織が数千件できた。** `api/signup.ts` が唯一の
   未認証口で、しかも Auth ユーザーを作る。**入力検証とレート上限を最初から入れる**のはこのため
2. **越境テストを「後で」にしたまま公開し、他農場の記録が読めた。** 本ログで申請の前提に
   繰り上げたのはこれを防ぐため。**サインアップの動作確認と越境テストを同じ作業として行う**
3. **チュートリアルが操作説明に育ち、no-manual-test の診断が形骸化した。** 上の判断基準
   （アプリを触らないと意味を成さない文は入れない）を残したのはこのため
4. **アカウント削除で組織の記録ごと消え、復旧できなかった。** 最後の管理者のときだけ
   組織を消す設計にし、削除画面に何が消えるかを書く
