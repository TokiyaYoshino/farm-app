## 追記（同日・第2段）: スレッドに道具を入れた

第1段はスレッドの器だけで、日報・散布時期・診断・記録に聞く はまだ外にあった。結果もスレッドに残らないので「主題ごとに全部溜まる」が未完成だった。ここを繋いだ。

### 決めたこと

**道具は入力欄の上にボタンで並べる**（会話で頼むと動く方式は採らない）。何ができるか見えていて、外したときに原因も分かるため。押すと**既存のシートがそのまま開く**（`api/*` は無変更）。変えたのは「どのスレッドから開いたか」を `toolThreadId` で覚え、結果が出たらそのスレッドに1発言として書き足すところだけ。

**日報は専用スレッド1本**（`advice_threads.system_key = 'daily_report'`）。日報は日付単位、スレッドは主題単位で粒度が違うため混ぜない。カレンダー・記録一覧・相談タブのどこから作っても行き先は同じ1本になる。**起動時には作らず、最初に日報を作ったときに作る**（使っていない人の一覧を汚さない）。

これで **過去の日報を見返す場所が初めてできた**。従来は `ai_outputs` に落ちるだけで画面から読み返せなかった。

### 残した入口

写真の隣の診断（記録一覧・記録詳細）、カレンダーの日付からの日報、記録一覧の日報は残した。その画面を見ている瞬間にしか意味がない入口で、消すと不便になる。**相談タブから開いたときだけスレッドに残る**という非対称にした。

### 実装中に見つけて直したこと

道具行を最初は横スクロールにしたが、これは `20260823-ai-information-architecture.md` が NN/g を根拠に「埋没」と名指しした形そのもの（画面外の道具は存在しないのと同じ）。**折り返し表示に変えた**。4つとも1画面に収まっている。

### 未解決

- **タブが5つある**（ホーム / カレンダー / 相談 / 分析 / 管理）。「カレンダーと記録一覧を別タブに」を入れると6つになるため保留
- **「記録に聞く」と相談本体の役割が重なって見える。** 前者は記録だけを根拠にし（記録に無いことは答えない）、後者は一般知識で補う、という誠実性の原則の違いがある（`spec-ai-features.md` 2章）。道具として並べるとこの差が利用者に見えない
- **Expo版は未反映**

## 追記（同日・第3段）: 相談タブに「引き」を足した

### なぜ

集約は構造として通ったが、**相談タブは「行かないと何も起きない場所」**という弱点が残っていた。行く理由が「思い出したとき」しかなく、これは 2026-08-23 の ADR が「AIを独立させるとわざわざ行く場所になり使われない」と心配した状態そのもの。ChatGPT に人が戻るのは自分から用があるからだが、農作業アプリで毎日その動機が湧くとは考えにくい。

### 決めたこと

**相談から出た「やること」の未実施件数を、ナビの「相談」タブにバッジで出す。** 行く理由を「思い出したとき」から「放置できないものがある」に変える。

判定は新設していない。`src/lib/adviceMatch.ts` の `matchActions` / `countMatches` をそのまま使う（ホームの作付け中カードと同じ計算なので、**画面ごとに数が食い違わない**）。

あわせて**スレッド一覧の行バッジをスレッド単位の集計に切り替えた**。従来は `crop_id` ベースで数えていたため、**作付けに紐づかない主題スレッドではバッジが出なかった**（`crop_id` が null になり集計から落ちていた）。

### 実装

- `adviceCountsByThread`（`Record<threadId, AdviceAction[]>`）を起動時の一括取得で作る。既存の `adviceCounts`（crop_id ベース・ホーム用）はそのまま残す
- `threadTodo(thread)`: 作付けが紐づいていればその作物の記録、なければ農場全体の記録と照合して `pending + overdue` を返す
- ナビは `navItems` に任意の `badge` を持たせ、0 のときは出さない。見た目は既存の通知ベルのバッジに揃えた

### やらなかったこと

- **「未読」は作らない。** 書き込むのは基本的に本人で、未読の概念が成立しない（本番の worker は0人）。複数人で使い始めてから考える
- **ホームに横断の「やること」カードは足さない。** ホームは既に長く、作付け中カードに同じ情報がある
- **プッシュ通知には繋げない。** 別の判断が要る（`docs/push-notifications.md`）

### 検証（デモ）

- ナビの「相談」に `2`、スレッド一覧は「トマトの病害虫」＝やること1・「今年の防除計画」（作付けなし）＝やること1・「日報」＝バッジなし。合計が一致
- **`work_type` が作業記録の語彙に無い助言（照合不可）は数に入らない**ことも確認した。「照合不可」は未実施という意味ではないため（`spec-crop-advice-agent.md` の原則どおり）

### 注意

`scripts/migrations/2026-09-09-advice-threads.sql` が未適用のあいだ、`crop_advice_actions.thread_id` が無いので**本番ではスレッド単位の集計が空になりバッジが出ない**（デモでは出る）。SQL の適用が先。
