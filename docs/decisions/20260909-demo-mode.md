# 認証なしで実画面を確認できるデモモードを入れる

- 日付: 2026-09-09
- 状態: 採用
- 種別: 開発環境の仕組み（本番コードに分岐が残るため記録する）

## 課題（Why）

UI の変更を入れても**実画面を一度も確認できていなかった**。検証が型チェック・ビルド・grep と静的モック止まりで、「ローカルで立てて見せてほしい」に応えられない。障害は3段あった。

1. `.env` が無く `createClient` が**モジュール評価中に throw**（`supabaseUrl is required.`）。`main.tsx` の ErrorBoundary は `render()` の中でしか効かないので捕捉されず**画面が真っ白**になる
2. 環境変数を埋めても Supabase セッションが無く、ログイン画面で止まる
3. ログインを通しても実DBが無く全 state が空

`supabase/` に config.toml もマイグレーションも無く CLI も未インストールなので、ローカル Supabase での代替は現状できない。

## 決めたこと

`VITE_DEMO_MODE=1` のときだけ、認証とデータ取得を迂回して偽データで描画する。**既定 off。**

- 偽データとフラグは `src/lib/demoData.ts` に隔離。既存の型は変更していない
- 起動は `npm run demo`
- 作物は**トマト・きゅうり**、地名は**現在地**、農薬は**ダコニール1000**（`CLAUDE.md` の規約どおり、特定の地域・品目を使わない）
- 相対日付で作ってあるので、いつ起動しても「今日の記録3件」「前回の散布から12日」が成立する

### 本番事故を防ぐ3つの仕掛け

1. **既定 off**。Vercel に `VITE_DEMO_MODE` を設定しない限り死にコード
2. **DEMO 時は Supabase クライアントを必ずダミーURL（`https://demo.invalid`）にする。** 本番キーが置かれた状態でデモを起動しても、本番DBに書き込めない。`createClient` を3ファイル（`App.tsx` / `AnalyticsView.tsx` / `GanttChart.tsx`）とも同じ形に揃えたのはこのため
3. **画面に「デモデータ」バッジを常時表示。** 本番に紛れ込んだら一目で分かる

## 検討した代替案

- **一時的に改変して撮影し、コミットしない** → 見送り。次に見せるときに同じ作業をやり直すことになる
- **本番の Supabase に繋いで実アカウントでログイン** → 見送り。本番の anon key を開発環境に置くことになり、スクショに実在の人名・圃場名が写る
- **ローカル Supabase（`supabase start`）** → 現状不可（config.toml もマイグレーションも無く、CLI 未インストール）

## 影響範囲

- **DB / 権限 / API**: なし
- **既存機能**: 削除なし。DEMO 以外の経路は従来どおり（分岐は `import.meta.env.VITE_DEMO_MODE === "1"` の比較のみ）
- **バンドル**: 偽データが同梱される（数KB）
- **型**: 既存の interface は未変更。`authSession` のダミーだけ `as unknown as AuthSession` を使っている（`Session` 型の必須フィールドが多いため）。**型の穴が1つ本番コードに残る**

## プレモータム（半年後に失敗していたとしたら）

1. **`VITE_DEMO_MODE` が本番環境に設定され、全利用者に偽データが出た。** → バッジで気づけるが、設定そのものは防げない。Vercel の環境変数を触るときの注意点
2. **DEMO 分岐が増殖して本番の経路と食い違った。** 今は state 初期値と2つの early return だけだが、画面が増えるたびに分岐を足すと保守できなくなる
3. **偽データで見た目を確認して満足し、実データ特有の崩れ（長い作物名・記録0件・大量データ）を見落とした。** → 空状態の確認用にデータを空にした変種が要る

## 検証

```
npx tsc --noEmit -p tsconfig.app.json    # clean
npm run build                            # 成功（DEMO 未設定でも壊れていない）
npm run demo                             # 起動 → 375px で全画面を撮影
```

ホーム・記録シート（3択）・カレンダー・記録一覧・検索文脈・日報／散布時期／診断／記録に聞くの各シート・分析タブを撮影して確認済み。

**この環境での制約**: Open-Meteo と Supabase への通信はブロックされるため、**天気カードは表示されない**（`wxAuto` が null になり非表示になる仕様どおりの挙動）。`/api/*` も届かないので、AIの応答そのものは確認できない（シートが開いて文言とボタンが正しいところまでを確認対象とした）。
