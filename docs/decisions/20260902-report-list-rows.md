# 記録一覧を「カードの積み上げ」から「1枚のカードに行」へ

日付: 2026-09-02
状態: 実装済み

## 背景 / Why

記録一覧（レポートタブ）は1件＝1枚のソフトカードで、各カードが
ヘッダ行＋区切り線＋メタ行＋メモ＋写真原寸＋ボタン2つを持っていた。
33件で **7.2画面ぶんのスクロール**になる（`docs/decisions/20260823-ai-information-architecture.md`
のプレモータム2番目「記録一覧の密度問題を放置したため、そもそも記録一覧まで到達されなかった」）。

新機能ではなく、**`CLAUDE.md` のレイアウト規則が既に「理想」と書いている形の未消化分の回収**にあたる。

> リスト: 個別カードでなく1枚のカードに hairline 区切りの行、が理想（移行中は個別ソフトカードも可）

解く課題（JTBD）: 「先週なにをやったか、ざっと見て思い出したい」。
1件を読み込む前に、**まず一覧できる**ことが要る。

## 決めたこと

### 1. 1枚のカードに hairline 区切りの行を積む

1行 = 1記録。行全体をタップで詳細シート（従来の「詳細を見る」ボタンと同じ遷移先）。

| 行の中身 | 置き場所 |
|---|---|
| 作物ドット・作物名・圃場 | 1行目 左 |
| 作業種別チップ・コメント数・日付・`⋮` | 1行目 右 |
| 量 / 時間 / 担当 / 農薬 / 天気 | 2行目（従来と同じ並び） |
| メモ | 3行目・**1行で省略**（全文は詳細シート） |
| 写真 | 4行目・**40px のサムネイル**（従来は原寸・最大220px） |

### 2. ボタン2つは行から出す

- 「詳細を見る」→ **行タップ**に統合（同じ操作に2つの入口を置かない）
- 「コピーして作成」→ `⋮` メニューへ。**削除と同じ場所に集約**し、全員が使える
  （削除は従来どおり管理者と本人のみ。`⋮` 自体を全行に出すのが変更点）

### 3. 「この写真で病害虫を調べる」はラベル付きのまま残す

`20260823-ai-information-architecture.md` で**写真の直下に置いたばかり**の導線なので、
アイコンや `⋮` に畳まない（同ログが案Cとして却下した「埋没」そのものになる）。
サムネイルの右に**文字ラベルのまま**並べる。写真を持つ記録は少数なので、
密度への影響は小さいと判断した。

### 4. フィルタチップ行を折り返す

`overflowX:auto` をやめて `flexWrap:wrap` にする。375px で4つ目の「担当」が
画面外に切れており、**存在に気づけない**状態だった。ボタン行で同じ問題を
`flexWrap` で解いた前例（同ログ）に揃える。

## 検討した代替案

- **日付でグルーピングして見出し行を挟む** → 見送り。走査性は上がるが、
  行の高さを揃えることの効果を先に測りたい。必要なら次段で足せる
- **写真を行から消す** → 却下。写真は「思い出す」ための最短の手がかり。サムネイルで残す
- **`⋮` にすべて畳んで行を1行にする** → 却下。担当と量が見えないと一覧の意味がない
- **現状維持** → 却下。7.2画面は一覧として機能していない

## 影響範囲

- **DB / 権限**: なし。表示のみの変更
- **既存機能**: 削除なし。詳細・コピー・削除・写真診断はすべて到達可能（置き場所のみ変更）
- **入力UX**: 変更なし（入力フォームには触れていない）
- **ストア審査 / 規制**: なし

## プレモータム（半年後に失敗していたとしたら）

1. **行タップで詳細が開くと気づかれなかった。** ラベル付きボタンを消したため、
   タップできること自体が伝わらない。→ `⋮` が行ごとに出るので操作対象であることは示せるが、
   無マニュアルテスト（`20260824-no-manual-test.md` の必達3つ）で確認するまで確証はない
2. **「コピーして作成」の利用が落ちた。** 1タップ増えた。→ コピーは既存記録を見つけてから使う
   機能なので詳細シート側でも足りるはずだが、実績を見るまで分からない
3. **密度を上げた結果、走査はできるが読めなくなった。** メモが1行省略になったため、
   メモを読ませる運用だと詳細を開く回数が増える

## 過去の判断との関係

- `CLAUDE.md` のレイアウト規則: **その未消化分の回収**（新しい判断ではない）
- `docs/decisions/20260823-ai-information-architecture.md`: 「未着手（第2段階以降）」の
  1番目と4番目を実施。写真直下の診断導線はラベル付きのまま維持し、覆していない
- 矛盾・上書きする判断はなし

## 検証

```
npx tsc --noEmit -p tsconfig.app.json   # clean
npm run build                           # 成功
npx eslint src/App.tsx                  # 変更箇所に新規の指摘なし（既存warning 1件のみ）
```

375px × 812px（実寸）で、旧マークアップと新マークアップを同一データで並べて計測した。
33件・**メモ60%・写真20%という仮定**（本番の実データは18件で、写真の実比率は未計測）:

| | 高さ | 画面数 |
|---|---|---|
| 旧（個別カード33枚） | 7,299px | 9.0 画面 |
| 新（1枚のカードに33行） | 3,069px | 3.8 画面 |

**58%削減**。フィルタ行を含め横スクロールは発生しない（`scrollWidth <= clientWidth`）。

**未検証**: 実データ・実ログインでの見え方（本番のユーザーは全員 admin で、
写真の実比率も未計測）。行タップで詳細が開くことに気づけるかは、
無マニュアルテスト（`20260824-no-manual-test.md`）で確認する。
