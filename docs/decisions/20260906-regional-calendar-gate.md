# 「防除暦」の取り込みは成立しない。国の防除マニュアルなら取り込める

- 日付: 2026-09-06
- 状態: 採用（暦は不可・国の資料は可能。着手は先送り）
- 種別: 調査・意思決定（外部データの取り込み）

## 課題（Why）

相談機能の返答のうち、一般的な栽培知識（作業の段取り・時期）だけが参照元を持たず LLM の推論のままだった（`docs/decisions/20260906-advice-reply-tone.md`）。農薬の使用基準は FAMIC 原文、自農場の事実は自分の DB という一次情報があるのに、3層目だけが推測になっている。

オーナーから「推論では農業エージェントとして成立しないので参照元を探す必要があるのでは」という指摘があり、いま画面で「地域の栽培暦を優先してください」と誘導している当のもの＝**都道府県が公開する防除暦・栽培暦**を取り込む方向を検討した。着手の順序は「安く殺せるものから」で、法務ゲート → 対象の確定 → 一次情報の形と更新 → 設計 → 検証、と合意している。

## 調べて分かったこと

### 1. そもそも「防除暦」は公的機関から出ていない（京都に限らない）

これが一番大きい。当初は「都道府県が防除暦を公開している」という前提で始めたが、実際に公開されているのは次の2種類で、**どちらも暦ではない**。

| 種類 | 中身 | 例 |
|---|---|---|
| **防除指針** | 作物ごとの「どんな病害虫がいて、どう防ぐか」 | [東京都病害虫防除指針](https://www.sangyo-rodo.metro.tokyo.lg.jp/nourin/shoku/boujyo/guideline/r6)（キャベツ・タマネギ・ネギ・ブドウ・ウメ等）、[千葉県](https://www.pref.chiba.lg.jp/annou/shokubo/bojoshishin.html) |
| **発生予察情報** | 「今この病害虫が出ている」という時系列 | [京都府病害虫防除所](https://www.pref.kyoto.jp/byogai/)（発生予報・注意報・特殊報） |

東京都の指針は時期について**発生予察情報へのリンク参照**にしており、「いつ何をやるか」は書いていない。**「いつ」まで含んだ暦はJAが作成・配布していることが多く、その場合は農協の著作物で使えない。**

### 2. 京都府のホームページには包括的な二次利用の許諾が無い

[京都府ホームページの著作権](https://www.pref.kyoto.jp/copyright.html)は「『私的使用のための複製』や『引用』など著作権法上認められた場合を除き、無断で複製・転用することはできません」とあり、政府標準利用規約／公共データ利用規約（CC BY 4.0 互換）を採用していない。**これは京都府固有の事情**で、他県には採用しているところもある（東京都の指針ページには利用規約の記載が無く、県ごとに確認が要る）。

### 3. 国の資料は取り込める

[農林水産省ウェブサイトの利用条件](https://www.maff.go.jp/j/use/link.html)は**公共データ利用規約（第1.0版・CC BY 4.0 互換）**に準拠し、出典表示（「出典:農林水産省ウェブサイト(URL)」）と加工時の明記をすれば、**複製・改変・商用利用ができる**。**写真・画像は第三者の権利を含むことが多く例外**なので取り込まない。

[総合防除実践マニュアル](https://www.maff.go.jp/j/syouan/syokubo/gaicyu/g_ipm/)は**イネ・キャベツ・ネギ・施設キュウリ・露地ナス・トマト・イチゴ・カンキツ・リンゴ・ナシ・ブドウ**の11作目ぶんが PDF で公開されており、本番の作付け（ほうれん草・にんにく・たまねぎ・キャベツ・ぶどう）のうち**キャベツとブドウが直接該当**する。

## 決めたこと

### 「防除暦を取り込む」は取り下げる

暦という形の一次情報が公的機関に存在しない以上、設計に進む意味が無い。JAの暦は著作権上使えない。

### 国の防除マニュアルの取り込みは「可能」として残す

ライセンスは通り、対象作目もこの農場と重なる。ただし**埋まるのは「何を・どう」であって「いつ」ではない**。

ここが今回の整理の要点で、**「いつ」を外部データで埋めようとしたのが間違いだった**。「いつ」は自農場の記録と天気で埋めるのが筋で、そこは既にやっている（`20260906-advice-reply-tone.md` の `aggregates`・天気予報の受け渡し）。外部の一次情報に期待すべきなのは「この作物にはどんな病害虫がいて、どう防ぐか」の側。

### 着手は先送りする

`docs/roadmap.md` の短期は入力UX改善で、本件は長期側。やるなら**1作目（キャベツ）だけを構造化して渡し、いまの推論と比較する**（`20260906-advice-reply-tone.md` と同じやり方）ところから。効果が出なければ捨てる。

国のマニュアルは暦と違って毎年改訂されるものではないため、**更新運用の負担は暦より軽い**——当初いちばん死にやすいと見ていた3番目のゲートは、国の資料に限れば緩い。

## 到達点（理想形）と、そこへの道筋

目指す形は「**都道府県ごとの指針を格納し、アプリの位置情報から該当県のものをエージェントが参照する**」。地域差を埋めるという当初の動機にそのまま応え、マルチテナントで他地域の利用者が増えるほど効く。

**位置情報→都道府県の解決は、すでに部品がある。** `api/pest-control-advice.ts` の `resolveJmaAreaCode` が国土地理院の逆ジオコーダで緯度経度から JIS 都道府県コードを取っている（今は気象庁の警報取得に使用）。指針の県判定に流用できるので、この部分はほぼタダ。

ボトルネックは県数に比例する3つ。

1. **ライセンスが県ごとに違う**。47県を個別確認する必要があり、全県は揃わない。**京都府は現状使えない**ので、県別から始めるとオーナー自身の農場で動かないものになる
2. **形式もバラバラ**。各県PDFで構成・粒度が違い、パースのコストが県数に比例する
3. **毎年の改訂**（東京都は「令和8年版」）。1〜数件ならリマインドで回るが、47県×毎年は個人開発では回らない

したがって順序は「**国を土台に置き、県別は使える県だけ後から足す**」。位置情報で「その県の指針があれば県、無ければ国にフォールバック」する設計にすれば、県のカバレッジに穴があっても体験が壊れない。国のマニュアルは改訂頻度が低いため、3のゲートを最初から踏まずに済む。

## 検討した代替案

- **他県の防除指針を使う** → 見送り。利用規約が県ごとに違い明記の無いものが多いうえ、**他県の指針を別地域の農場に当てるのは農学的に筋が悪い**（地域差を埋めたくて始めた話なので本末転倒）。マルチテナントで当該地域の利用者が増えたときに、その県のぶんを確認して足すのが順当
- **京都府に利用許諾を申請する** → 見送り。そもそも暦が無いので申請しても得られない。予察情報の全文利用が要るなら別途
- **予察情報をリンクで誘導する** → 引用の範囲を超えないので著作権の問題は生じず、価値の芯（今なにが出ているか）は拾える。ただし `docs/decision-log.md`（2026-07-31）で「PDF中心でAPIが無く自動化が脆い」として一度分離した項目でもある。やるならリンク提示だけの小さい形から
- **web検索を都度繋いで拾う** → 却下。出典が固定されず追跡できないうえ、法令に関わる情報で一次情報の正確な引用を保証できない

## 影響範囲

- **DB / 権限 / 既存機能**: なし（着手しないため）
- **相談機能**: 3層目（一般的な栽培知識）は当面 LLM の推論のまま。画面では「目安」と明示し、地域の指導機関を優先するよう誘導している現状を維持する
- **ストア審査 / 規制**: なし。取り込む場合は出典表示と加工明記が条件になる（PDL1.0）
