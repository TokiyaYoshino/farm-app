# ADR: ネイティブ化フレームワークにCapacitorを採用

- 日付: 2026-07-31
- 状態: 採用

## 背景・コンテキスト

AppStore申請の最短ルートを検討する中で、素のWebView（既存Webアプリをそのまま包むだけ）は審査ガイドライン4.2（Minimum Functionality）で確実にリジェクトされることを確認した。ネイティブ化が必須という前提のもと、roadmap.mdでは「React Native/Expo方向で検討中」としていたが、既存React資産（`src/App.tsx`以下のロジック・UIコンポーネント、`src/ui/tokens.ts`のデザイントークン）をそのまま再利用できるCapacitorを対抗案として比較した。

## 決定

**Capacitor**で既存Webアプリをネイティブシェル化する。素のWebViewと違い、Push通知・カメラ・GPS・オフラインキャッシュをCapacitorの公式プラグインで実装し、4.2 Minimum Functionality要件（ネイティブ機能を実際に持つこと）を満たす方針とする。

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| Capacitor（採用） | 既存React/UIコードをほぼそのまま流用でき実装コストが低い。既存デザイン（Soft Widget、ボトムナビ3タブ）が既にモバイル寄りで「サイトの焼き直し」感が出にくい。ロジック層（Supabase呼び出し）も無改修で使える | 審査通過には各画面でネイティブプラグインの実利用が必須（サボると4.2リジェクト）。オフライン時に白画面にならないようService Worker/キャッシュ実装が別途必要 |
| Expo（React Native書き直し） | UIを最初からネイティブ実装するため審査通過の確実性が高い。EAS Buildでクラウドビルド完結、Mac不要 | UI層を丸ごと再実装する必要がありボリューム大。Web版とネイティブ版でUIコードが分岐し、以後の二重メンテが発生 |
| 素のWebViewラップ | 実装コストが最小 | ガイドライン4.2で却下がほぼ確実。検討対象外 |

## 選定理由

- **実装コスト・保守性を最優先**（`technical-decisions.md`の個人開発方針どおり）。farm-appは既にWebで全機能が動いており、Expoでの書き直しは「機能実装が終わった後」に別プロジェクト規模の再実装を挟むことになり、最短ルートという目的に反する
- Mac実機を保有しているため、Capacitorのビルド運用（Xcodeでのアーカイブ・署名）に伴うクラウドMac CIの追加コストが発生しない。Expoの「Mac不要」という優位性が今回は効かない
- 既存UIが既にモバイル最適化されたデザイン（Soft Widget、ボトムナビ）であるため、Capacitor化した際に「ただのPCサイト」に見えるリスクが元々低い

## 影響

- 変更・移行が必要な既存コード:
  - Capacitor導入（`@capacitor/core`, `@capacitor/ios`）とネイティブプロジェクト生成
  - Push通知（`@capacitor/push-notifications`）、カメラ（`@capacitor/camera`）、GPS（`@capacitor/geolocation`）のネイティブプラグイン実装への置き換え
  - オフライン下書き用のローカルキャッシュ（`@capacitor/preferences`または`@capacitor/filesystem`）と、機内モードでも白画面にならないフォールバック実装
  - `src/App.tsx`のロジック・UI分離は引き続き将来課題として残る（本ADRのスコープ外）
- 将来この決定を覆しにくくする要因（ロックイン）:
  - Capacitorプラグインへの依存が増えるほど、将来React Native等へ乗り換える際の書き直しコストが上がる
  - Web版とアプリ版でコードベースを共有し続ける設計になるため、アプリ版だけの独自ネイティブUI（例: ネイティブらしいジェスチャー操作）を後から追加する場合はコストが上がる

## 再検討のトリガー

- Capacitorプラグインだけでは4.2リジェクトが解消しない、または審査で繰り返し指摘を受けた場合
- 外部展開が進みユーザー数・利用組織数が大きく拡大し、ネイティブ体験の差別化（アプリ版とWeb版の明確な機能差）が競争上必要になった場合
- App.tsxの肥大化がCapacitor運用の支障になるレベルまで進んだ場合（ロジック分離のタイミングと合わせて再検討）
