# 事業定義を「経験の差」で確定する

- 日付: 2026-09-28
- 状態: 採用
- 種別: 事業方針（ポジショニング）
- 本文: `docs/business-definition.md`
- 関連: `20260823-pricing-plan-review.md`（論点2に答える）、`20260912-release-line.md`

## 課題（Why）

App Store 0.1.0 は「必要な機能開発ゼロ」と判定済み（09-12）なのに、審査に進めていない。
docs を通読すると、想定する「この人」が2か月で4回入れ替わっていた。

| 時期 | 出典 | この人 |
|---|---|---|
| 2026-07 | roadmap 事業戦略サマリー | 従業員のいる農業法人 |
| 2026-08-09 | competitor-gap-analysis | 新規就農者 |
| 2026-08-23 | pricing-plan-review | 個人農家（Team の課金理由が崩れて保留） |
| 2026-08〜09 | roadmap 完了済み各項 | 記録している農家全般（「記録と相談が同じ場所」） |

定義が無いため、ストア掲載文（サブタイトルが今も「チームで共有」）もスクショの順も決められない。

## 決めたこと

> 経験の長さが違う人で畑を回している農家の、「いつ・何を・どの農薬で」という判断が
> 一人ひとりの記憶と勘に頼っている課題を、畑の記録と農薬の登録情報を根拠に、
> 誰が聞いても同じ答えが返るようにして解決する。

- 切り口は**年齢ではなく経験**（オーナーの実感＋レビューで高齢者言及0件）
- 主役にしない: チーム進捗管理（補助として残す）、防除記録の提出書類（仮説 H3 で検証）、売上管理（作らない）
- 最初の検証場所はオーナー自身の農場。worker 配布がそのまま検証の開始になる

## 検討した代替案

- A チーム進捗管理: 競合の無料版と重複し差が弱い → 補助に格下げ
- C 防除記録と提出書類を入口にする: オーナーの農場でも提出の有無が「分からない・一部だけ」→ 仮説へ
- 詳細は `docs/business-definition.md`「選ばなかった定義」

## 影響範囲

- DB / 画面 / 権限: なし（機能の削除・追加なし）
- ストア掲載: サブタイトル・説明文冒頭・スクショ順の差し替え案を `business-definition.md` に記載。
  `docs/app-store-submission.md` への反映はオーナー確認後
- 料金: `20260823-pricing-plan-review.md` 論点2（課金軸を「蓄積データの活用範囲」へ）と同じ向き。
  料金表そのものは本ログでは決めない（保留のまま）

## プレモータム

1. **H1・H2 が両方外れる**（ベテランは記憶で困っておらず、新人も聞いていない）→ 定義を見直す。否定条件は本文に書いた
2. **5回目の入れ替え**が起きる → 変えるときはこのログを覆す新しいログを書き、理由を残す。検証結果なしに変えない
3. **記録が溜まらず答えが薄い**（コールドスタート）→ 国の防除マニュアルと農薬登録情報で初日から答えられる範囲はある。記録の件数は数える対象に入れた

## 過去の判断との関係

- roadmap「事業戦略サマリー（2026-07 確定）」のポジショニング（法人・チーム機能主軸）を置き換える
- 「記録と相談が同じ場所」という差別化判断（2026-08-23 以降）は維持し、それに「誰の」を足した
- `20260912-release-line.md` のリリース3条件・3問ルールは変えない
