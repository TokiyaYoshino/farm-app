# データのインポート／エクスポート機能

- 日付: 2026-08-23
- 状態: **保留（前提が未検証のため着手しない）**
- 種別: 新機能

## 課題（Why）

競合調査（2026-08）を受けて、初期ユーザー獲得のため「他サービスからのデータ移行支援」を検討している。アグリハブは「システム移行費0円キャンペーン」で他社からの乗り換えを取りに来ており、こちらも移行障壁を下げたい。

あわせて、自社データのエクスポートはロックインを嫌う農家への安心材料になり、むしろ売りにできる。

## なぜ保留なのか（着手前に確認すべきこと）

**移行元からデータを構造化形式で出せるかが未確認**。ここが崩れると施策そのものが成立しない。

- アグリハブのフリープランで CSV 等の**構造化形式**のエクスポートができるか
  - 有料プランの「圃場情報出力」はフリーでは不可。帳票の印刷出力はできるが、**それは紙であって構造化データではない**
- アグリノートのエクスポート可否と形式

**もし構造化データで出せないなら、移行支援は「PDFからの手打ち」になり工数が跳ね上がる。** 先に確認せず実装すると、CSVインポート機能を作ったのに流し込む元データが存在しない、という事態になる。

## 決めたこと（確認が取れた場合の想定。現時点では未着手）

- 汎用CSVインポート（圃場・作付け・作業記録・防除記録）。列マッピングをUIで指定できる形が現実的
- 自社データの CSV / JSON エクスポート

### 移行支援施策の設計上の注意（先に決めておく）

「100社まで無料」は一人では捌けない（1社あたり半日換算で400時間超）。**先着10社程度に絞る。** 目的は囲い込みではなく、**実データを見て入力の様子を観察すること＝ユーザーリサーチ**。

## 影響範囲（着手時に再評価）

- **DB / 権限**: インポートは全テーブルに書き込む経路になる。マルチテナント化の途中であり、`organization_id` の付与漏れが即座に越境事故になる。**RLS実ポリシー化（`docs/rls-rollout.md`、未実施）より後に着手すべき**
- **既存機能**: 記録の一括生成は既存の集計（`metrics.ts` / `pesticideUsage.ts`）の前提（1記録＝1作業）を崩しうる
- **規制・業界固有の実務**: 農薬記録を外部から取り込む場合、**取り込んだ数値の正しさをこちらが保証できない**。使用回数の判定に流用すると誤判定の原因になるため、取り込み元を記録として残す設計が要る

## プレモータム（半年後に失敗していたとしたら、何が起きたか）

1. **エクスポート可否を確認せずCSVインポートを作り、流し込む元データが存在しなかった。**（＝本ログが保留にしている理由そのもの）
2. **移行支援を広く受けすぎて開発が止まった。** 先着10社の制限を守れなかった
3. **インポート経路が `organization_id` を取りこぼし、他組織のデータと混ざった。** RLS未適用の状態で一括書き込み経路を開けたため
