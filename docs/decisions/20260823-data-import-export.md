# データのインポート／エクスポート機能

- 日付: 2026-08-23
- 状態: **前提は確認済み・着手可（ただし RLS 実ポリシー化より後）**
- 種別: 新機能

> **2026-08-23 追記: 前提の確認が取れた。** 保留の理由だった「移行元から構造化データを出せるか」は
> **両社とも出せる**ことを確認した（下記「前提の確認結果」）。したがって「PDFからの手打ちになる」
> という最悪シナリオは回避され、施策の組み直しは不要。
> 残る着手条件は RLS 実ポリシー化（`docs/rls-rollout.md`、未実施）のみ。

## 課題（Why）

競合調査（2026-08）を受けて、初期ユーザー獲得のため「他サービスからのデータ移行支援」を検討している。アグリハブは「システム移行費0円キャンペーン」で他社からの乗り換えを取りに来ており、こちらも移行障壁を下げたい。

あわせて、自社データのエクスポートはロックインを嫌う農家への安心材料になり、むしろ売りにできる。

## 前提の確認結果（2026-08-23 実施）

当初「移行元からデータを構造化形式で出せるか」が未確認で、崩れれば施策ごと組み直しになるため保留にしていた。**確認の結果、両社とも構造化データを出せる。**

| 移行元 | エクスポート | 形式 | 出力内容 |
|---|---|---|---|
| **アグリノート** | ○ ブラウザ版「全記録の出力」 | **CSV / Excel(.xlsx)** | 作業記録・圃場情報・収穫記録・生育記録・収支データ |
| **アグリハブ** | ○「その他 > CSV出力 > 年月の選択」 | **CSV** | 作業日・作業内容・**農薬の散布量・希釈倍率**・販売個数・金額・肥料使用量・積算気温・積算日照時間・積算降水量 |

### 分かったことの含意

1. **「PDFからの手打ち」シナリオは回避された。** 汎用CSVインポートに流し込む元データが実在する
2. **アグリハブのCSVには農薬の散布量・希釈倍率が含まれる。** ノウレコの防除記録・使用回数チェックに直接マッピングできる項目が揃っている
3. **移行のハードルは形式ではなく列の対応付けに移る。** 列マッピングUIの必要性が裏付けられた
4. **逆に、移行障壁が低い＝こちらからも簡単に出ていける。** エクスポートを備えること自体は差別化にならず、「無いと不利」な当たり前品質（Kano）と位置づけるべき

### 残る未確認（着手時に確認する）

- アグリハブのCSV出力が**フリープランでも使えるか**（サポート記事にプラン制限の記載が見当たらず、料金ページは 403 で取得できなかった）。有料プランの「圃場情報出力」は別項目のため、記録のCSV出力とは区別されている可能性が高い
- 実際の列名・文字コード・日付書式（実ファイルを1つ入手するのが最短）

## 決めたこと（確認が取れた場合の想定。現時点では未着手）

- 汎用CSVインポート（圃場・作付け・作業記録・防除記録）。列マッピングをUIで指定できる形が現実的
- 自社データの CSV / JSON エクスポート

### 移行支援施策の設計上の注意（先に決めておく）

「100社まで無料」は一人では捌けない（1社あたり半日換算で400時間超）。**先着10社程度に絞る。** 目的は囲い込みではなく、**実データを見て入力の様子を観察すること＝ユーザーリサーチ**。

## 影響範囲（着手時に再評価）

- **DB / 権限**: インポートは全テーブルに書き込む経路になる。マルチテナント化の途中であり、`organization_id` の付与漏れが即座に越境事故になる。**RLS実ポリシー化（`docs/rls-rollout.md`、未実施）より後に着手すべき**
- **既存機能**: 記録の一括生成は既存の集計（`metrics.ts` / `pesticideUsage.ts`）の前提（1記録＝1作業）を崩しうる
- **規制・業界固有の実務**: 農薬記録を外部から取り込む場合、**取り込んだ数値の正しさをこちらが保証できない**。使用回数の判定に流用すると誤判定の原因になるため、取り込み元を記録として残す設計が要る

## プレモータム（半年後に失敗していたとしたら、何が起きたか）

1. **エクスポート可否を確認せずCSVインポートを作り、流し込む元データが存在しなかった。**（＝本ログが保留にしている理由そのもの）
2. **移行支援を広く受けすぎて開発が止まった。** 先着10社の制限を守れなかった
3. **インポート経路が `organization_id` を取りこぼし、他組織のデータと混ざった。** RLS未適用の状態で一括書き込み経路を開けたため
