# 検証: Expoネイティブ実装でSoft Widgetデザインがどこまで再現できるか

- 日付: 2026-08-01
- 状態: 進行中
- 種別: 検証（実験）

## 背景（Why）
AppStore公開の技術方針として、既存Web（React/Vite）をWebViewでラップする案とExpo/React Nativeでネイティブ実装し直す案を比較検討した。WebViewラップはApp Store審査ガイドライン4.2（Minimum Functionality）でリジェクトされる定番パターンであることが判明済み（`docs/roadmap.md` 経由で参照する運用ノウハウに詳細あり）ため、正式リリースはExpoネイティブ実装が前提になる。
残る不確実性は「現行の Soft Widget デザイン（`src/ui/tokens.ts` の色・影・角丸、ピルボタン等）が React Native でどこまで見た目を保ったまま再現できるか」。これを本格着手前に小さく検証する。

## 仮説
「ダッシュボードと作業記録の2画面をExpo/React Nativeで組み直しても、`src/ui/tokens.ts` の色・角丸はそのまま使え、影（box-shadow → shadow*/elevation）とフォントレンダリングの差分だけ調整すれば、現行Web版とほぼ同じ見た目に到達できるはずだ」

## デザイン方針（重要な制約）
**これはリデザインではなく移植（ポーティング）**。現行Web版（React）の見た目からは意図的に変えない。配色・角丸・ボタン形状・レイアウト密度・ラベル小/値大といった現行の Soft Widget スタイルをそのまま踏襲すること。
- `tokens.ts` の値（`C` / `SHADOW` / `RADIUS`）は数値を変更せず、RNのAPIに合わせて形式だけ変換する（影の分解等）
- 「RNらしい見た目に寄せる」「Material/iOS標準UIに寄せる」といった独自のアレンジはしない
- どうしても同じ値では再現できない箇所（影の質感等プラットフォーム制約によるもの）が出た場合は、**黙って変更せず**「結果と判断」欄に差分として記録し、判断を仰ぐ

## 最小の試し方（本実装ではない）
1. 新規Expoプロジェクトを別ディレクトリ（同一リポジトリ内 `expo-prototype/` 等、隣接ワークツリー可）に作成
2. 上記2画面のみをRNコンポーネントで再構築。データは**モックデータで良い**（後述の理由でSupabase接続は本検証には不要）
3. `tokens.ts` の値をそのまま移植し、影は iOS/Android それぞれで `shadowColor/shadowOffset/shadowOpacity/shadowRadius` と `elevation` に分解
4. Expo Go またはシミュレータでスクリーンショットを取得し、現行Web版の同画面スクリーンショットと並べて比較
5. ズレが出た箇所（影の濃さ、角丸の見え方、フォントウェイト等）を記録

## 判定基準
- 主要な視覚要素（色・角丸・ボタン形状・カード階層）が違和感なく再現できる → **本実装（Aパターン）に進む根拠として採用**
- 影やレイアウトの再現に想定以上の作り込みが必要と分かった → 工数見積もりを更新し、着手時期（マルチテナント化完了後）の判断材料にする

## Supabase接続について（データが必要な場合のみ）
本検証はビジュアル再現の確認が目的のため、モックデータでの実施を推奨（外部の認証情報を持ち出す必要がなく、スコープも小さく保てる）。
実データで確認したい場合のみ、`.env` に以下2つの環境変数が必要（**リポジトリには含まれない**ため、Vercelプロジェクト設定 or Supabaseダッシュボードから別途取得すること。このセッションも値は保持していない）：
- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_ANON_KEY`
（`src/App.tsx:44-46` 等で参照されている変数名。anonキーはRLSで保護されるクライアント用キーであり、サービスロールキーではない）

## 結果と判断

### 実施内容（2026-08-02 時点）
当初スコープ（ダッシュボード＋作業記録）の試作で Expo Go 表示まで確認後、オーナー指示によりスコープを全画面に拡張した。`expo-prototype/` に以下を実装済み・TypeScript 型チェック通過：

- ホーム / 記録（カレンダー月週切替・日別シート・詳細・予定追加編集削除、記録一覧・検索・フィルタ・詳細シート）/ 分析（KPI・収穫グラフ・作業時間内訳・GDD・散布図、計画ガント）/ 管理（作物・圃場・農薬）/ クイック記録フォーム / コメントスレッド（@メンション対応）
- `tokens.ts` の色・角丸・作業種別/作物カラーは数値無変更で移植。`lib/metrics.ts` も無変更で流用（純粋TSのため）
- データはモック（2025/2026 の2年分。前年比・目標達成率・kg以外除外の注記が実際に描画される）

### Web版と同じ値では再現できなかった箇所（プラットフォーム制約による差分）
方針の「黙って変更しない」に従い記録する。判断を仰ぎたい：

1. **影の多重指定**: Web の `SHADOW.card` は box-shadow 2つの重ね（1px2px .04 + 8px24px .06）。RN は影1つのみのため、大きい方を採用し opacity を .06→.08 に補正。Android は elevation 近似でさらに質感が変わる。
2. **`<select>` の代替**: 作物・圃場・作業種別等のネイティブ select は RN に無い。試作はタップローテーション／チップ横並びで代替（見た目は同一）。本実装では BottomSheet ピッカー推奨。
3. **date/time input**: テキスト入力で代替。本実装では `@react-native-community/datetimepicker`。
4. **アイコン**: lucide-react → `@expo/vector-icons` Feather（lucide の派生元でほぼ同字形）。`lucide-react-native` 導入で完全一致可能。
5. **グラフ**: recharts は React DOM 依存のため `react-native-svg` で軽量自作（`expo-prototype/ui/charts.tsx`）。凡例・グリッド破線・色は合わせたが、ツールチップ（タップで値表示）は未実装。本実装では victory-native も選択肢。
6. **和文フォント**: System フォント同士だが iOS（ヒラギノ）とブラウザで字間が微差。

### 判定
主要な視覚要素（色・角丸・ピルボタン・カード階層・well/row の入れ子）は RN で問題なく再現できた。**本実装（Aパターン＝Expoネイティブ移植）に進む根拠として採用できる**。上記差分のうち 1・6 は許容範囲か実機比較で最終確認、2・3・5 は本実装時のコンポーネント選定事項。
