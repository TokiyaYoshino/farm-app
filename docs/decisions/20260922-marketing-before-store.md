# マーケ施策を「獲得数」ではなく「提携が始められる実績」に置く

- 日付: 2026-09-22
- 状態: 採用
- 種別: リリース計画・事業判断（獲得チャネル）
- 関連: `docs/research/dl-target-20k-2026-09.md`（調査）、`20260912-release-line.md`（リリース線）、`docs/handoff-input-redesign.md` 2章（実測）、`20260823-pricing-plan-review.md`（収益目標の論点）

## 課題（Why）

「DUNS 番号がまだ取れていないので、App Store 以外のマーケ施策を決めたい」という相談。
調べると、**前提が2つ崩れた**。

| # | 事実 | 出典 |
|---|---|---|
| 1 | **Web版は 2026-09-10 に本番リリース済み**。配れる製品は既にあり、App Store は配布経路の1つでしかない | `20260909-web-release-and-rollback.md` |
| 2 | App Store 0.1.0 の目的は「審査を通すこと」であって配布量ではない | `20260912-release-line.md` |
| 3 | 本番の worker は **0人**・記録18件（4.5か月）・AI呼び出しは開発時の確認のみ | `handoff-input-redesign.md` 2章 |
| 4 | 伸びた競合4件が4件とも、成長の説明変数を**既存チャネル（JA・農機・農薬メーカー）への接続**と説明。UI改善や機能追加を挙げた事例はゼロ | `dl-target-20k-2026-09.md` 4章 |
| 5 | ★2→★4 でDL率5.4倍。ただし**流入が無ければ乗数は効かない**。★評価が本当に効くのは「提携の話が始まる資格要件」として | 同 5・6章 |

**結論: DUNS 待ちはマーケの制約になっていない。** そして今いちばん外しやすいのは、
マーケを「新規獲得（広告・露出・SNS）」と読むこと。**外部ユーザー0・記録18件の状態で流入を作ると、
定着せず、★評価という提携の資格要件をむしろ削る。**

リポジトリは3回（`handoff-input-redesign.md` 08-09 / `20260909-advice-tab-keep-with-exit-criteria.md` /
`20260912-release-line.md`）「使う人を増やすことがどのUI改善よりも先」と書いていて、**1か月以上未実行**。

## 決めたこと

### 1. 今期のKPIを DL数 → 実利用組織数 に差し替える

業界の主要プレイヤーは全社が登録者数・利用組織数で語っている（アグリノート「3万組織」/ アグリハブ「登録者5万人」/ KSAS「会員26,400人」）。
畑らく日記の実測では **DLの75%が消える**。DL数を追うと、定着への投資が指標に反映されない。

**今期（〜2026-12）の目標**

| 指標 | 現在 | 目標 |
|---|---|---|
| 実利用組織 | 1（霧珠ファーム） | **3** |
| worker アカウント（入力実績あり） | **0** | **5人** |
| 月間の作業記録 | 約4件 | **100件** |
| `ai_outputs.entry_point` | ほぼ0 | **n≧30**（配置凍結の解除条件） |

「1年で2万DL」は取り下げない。ただし**今期の作業指標にはしない**（2万DL ≒ 実ユーザ5千人 ≒ 全経営体の0.6%。母数から見て営業の数字であり、1年で作る数字ではない）。

### 2. 施策A（最優先・今週着手）— 配布を実行する

| | やること | 技術的前提 |
|---|---|---|
| **A-1** | 霧珠ファームの **worker アカウントを作って現場に渡す** | **なし。今日できる** |
| **A-2** | **近隣農家2〜3軒**へ Web版のURLを手渡しで配る | **2組織目の越境アクセス実地テスト1本だけ** |

**実行のブロッカーは DUNS ではなく A-2 の越境テスト。** `docs/roadmap.md` が「他農場へ配る前の必須項目」と
明記しているものが、そのまま今期マーケの律速になる。ここが唯一の技術作業。

A の成果物は獲得数ではなく **①実利用組織3件 ②凍結解除に足るデータ ③施策Bで出せる事例**。

### 3. 施策B（10月・種まき）— 既存チャネルへ1件ずつ接触

JAのアクセラレータ／県の農業改良普及センター／地域の農機販売店。**各1件**でよい。
持っていくのは機能一覧ではなく A で出た事例。アグリハブも
「口コミの実ユーザー → JAアクセラレータ採択 → 一気に増えた」の順序で、**事例が先**。

募集時期が律速になりうるので、**A と並行して応募窓口の開閉時期だけ先に調べる**（調査のみ、応募は事例が出てから）。

### 4. 予算（月1〜3万円）の使い道

| 用途 | 配分 | 理由 |
|---|---|---|
| **訪問の実費・導入時の謝礼** | **ほぼ全部** | n を増やすのに最も直接的。A-2 の成否がここで決まる |
| 手渡し用の紙1枚（A4） | 印刷実費のみ | A と B の両方で使い回す。凝らない |
| 検索広告・PR配信・展示会出展 | **0円（打たない）** | 事例ゼロの段階では定着せず、★評価を削る。**実利用組織3件が出てから再検討** |

### 5. 今回やらないと明言するもの（Won't this time）

- **有料広告・PR配信**（PR TIMES等）→ 事例3件まで凍結
- **農業WEEK出展**（2024実績 出展893社）→ 費用が個人開発の規模に合わず、事例ゼロでは名刺も活きない
- **SNS運用・公開ツール・オウンドメディア記事** → 工数が出る。A・B が動いてから再検討（見送りであって却下ではない）
- **Google Play への迂回** → 個人アカウントは新規にテスター要件があり、結局「使う人を集める」が前提。**順序が A と同じなので、先に A をやる**（正確な要件は着手時に要確認）
- **AI導線の配置の詰め** → `20260912-release-line.md` の凍結（n≧30）を維持。**4回目の「効果は未検証」を作らない**

## DUNS・法人名義について（オーナーの Why への回答）

DUNS を取りに行っている理由は「**個人開発はスケールしない／事業化しにくいのではないか**」という懸念だった。
これは正しい懸念だが、**Apple の登録名義はその律速ではない**。分けて考える。

| 懸念 | 実際に効くもの | Apple の名義が効くか |
|---|---|---|
| 事業として続かない | 獲得チャネル・実利用者・継続率 | **効かない** |
| Team プラン（月2,980円）の Web 契約ができない | 決済（Stripe）。個人事業主でも契約できる | **効かない** |
| JA・農機メーカーと提携できない | 実績と事例（調査4章）。★4も資格要件 | **効かない** |
| ストアの販売者名が個人の本名で出る | ここだけは本当に効く（B2B の信頼） | **効く** |

**そして名義は後から移せる。** 個人→法人はアカウント種別の変更またはアプリの譲渡という経路が用意されている
（条件は申請前に要確認）。**IAP・サブスクを入れる前の今が、移すコストが最も低い時期**。
逆に DUNS を待つ分は取り返せない。

**決定: 法人化そのものは事業判断として切り離し、マーケ施策の前提条件にしない。**
App Store の名義（個人で先に出すか、DUNS を待つか）はこのログでは決めず、上表を材料に別途決める。
どちらを選んでも、施策A・B は今週から動く。

## 検討した代替案

- **案B: 先に露出を作る（広告・PR・SNS・展示会）** → 見送り。調査4章の通り、伸びた事例4件が4件とも説明変数を外部チャネルに置いており、露出単体で伸びた事例が見つからない。加えて定着前の流入は★評価を削り、**提携の資格要件を自分で壊す**
- **案C: DUNS が出るまでマーケは待つ** → 見送り。Web版が出ている以上、待つ理由が無い。待つ間に失うのは時間だけでなく、n≧30 に届かないことで**配置の凍結が解除されない**という二次被害がある
- **案D: 公開ツール（ログイン不要の農薬使用回数チェッカー）で検索流入を作る** → **保留**。FAMIC データと `pesticideUsage.ts` が既にあるので筋は良いが、工数が出るうえ母数82.8万・高齢層中心の市場で検索流入がどれだけ立つか不明。**A で実利用3件を作ってから改めて評価する**
- **現状維持（施策を決めない）** → 見送り。「使う人を増やすのが先」が1か月以上未実行という現状そのもの

## 影響範囲

- **DB / RLS**: A-2 の前提として**2組織目での越境アクセス実地テストが必須**（`docs/multitenancy-progress.md` の手順）。新規スキーマ変更は無し
- **既存機能**: なし（コード変更を伴わない決定）
- **AppStore / 法規・農業実務**: 審査への影響なし。他農場へ配る時点で、他組織の農薬・防除記録が越境しないことが法規記録の正確性に直結するため、越境テストは省略不可

## プレモータム（半年後に失敗していたとしたら）

1. **A-2 の越境テストが「後でやる」のまま半年経ち、配布が自農場の worker だけで止まる。** 結果 n は増えず、施策B に持っていく事例も無く、配置の凍結も解けない。**A-2 の前提1本を今週の作業として切り出すこと自体が対策**
2. **配ったが使われない。** 渡して終わりにすると畑らく日記と同じ75%が消える。導入時に必達3タスク（`20260824-no-manual-test.md`）をその場で一緒にやるところまでを配布の定義に含める
3. **予算を広告に流用してしまう。** 月1〜3万は少額なので「試しに広告を」となりやすいが、事例ゼロで打つと最も効果が薄い使い方になる。**解禁条件（実利用組織3件）を上に明記したのはこのため**

## 過去の判断との関係

- `20260912-release-line.md` の凍結（`entry_point` n≧30 まで配置を触らない）を**維持**し、その n を作る手段を初めて具体化した
- `docs/roadmap.md`「保留・未着手：90〜130組織の獲得チャネル（JA・地域法人営業など）」に**初めて着手順序を与えた**
- `20260823-pricing-plan-review.md`（保留中）は**動かさない**。課金軸の決定には実利用データが要り、本ログの施策A がその材料を作る側にある

## 追記（2026-09-22）: 名義は個人で進める／worker はストアを待たない

上の本文で「名義はこのログでは決めない」としていた2点が、同日の相談で決まった。

### 1. Apple Developer は個人名義で登録する（DUNS を待たない）

| 論点 | 判断 |
|---|---|
| **開業届は要るか** | **不要。** Apple の個人（Individual）登録に、開業届や事業者であることの要件は無い。必要なのは Apple ID・本人確認・年会費 $99 |
| **販売者名** | 本人の法的氏名で出る。屋号（霧珠ファーム）で出したければ「開業届＋屋号での DUNS 取得」という経路があるが、**それは待つ判断に戻るので 0.1.0 では取らない** |
| **税務** | 0.1.0 は無料アプリ・IAP 未実装で収益ゼロ。**今やることは無い。** 開業届は収益が立って青色申告を取る時点で検討すれば足りる（課金導線＝Stripe / IAP を入れる時に税務情報と入金口座の登録が要る。細部は税務署・税理士に確認する） |
| **後から法人へ** | 移せる（種別変更 or アプリ譲渡。条件は申請前に要確認）。**IAP・サブスクを入れる前の今が最も条件が軽い** |

### 2. worker への配布は App Store 公開を待たない

「worker にはリリース後にストアから DL してもらう方がいいのでは」に対する判断。**待つと詰む。**

1. **リリース判定条件とデッドロックになる。** `20260912-release-line.md` の申請条件3は
   「**worker アカウントが1つ以上あり、admin 以外の入力が1件以上ある**」。
   worker の利用は**申請の前提**であって申請後の話ではない。ストアを待つと条件3が永遠に埋まらない
2. **待つ必要がない。** Web版は既に PWA として構成済み（`public/manifest.webmanifest` が
   `display: standalone`、`apple-mobile-web-app-capable` あり）。**「ホーム画面に追加」でアイコンが付き、
   ブラウザのバーが消える。** worker 側の体験はアプリとほぼ同じで、渡すのはURL1本
3. **歩留まりが見えなくなる。** 畑らく日記の実測で DL の75%が消える。身近な worker にストア経由で
   入れてもらうのは、その75%に自分から入りに行く経路。**手渡しでその場で必達3タスクまで
   一緒にやる**のが、本ログのプレモータム2への対策そのもの

**決めた順序**

```
今週  Web版のURLを渡す（ホーム画面に追加まで一緒にやる）
 ↓    → 申請条件3が埋まる
申請  App Store 0.1.0
 ↓
公開後 ストア版へ乗り換えてもらう（同じ Supabase・同じ api/* を見ているのでデータは繋がったまま）
```

TestFlight（内部テスターは審査なしで即日配信可・`docs/testflight-guide.md`）は
この中間に置けるが、**Apple Developer 登録の後**なので今週の配布には間に合わない。
「先に Web で配る」を置き換えるものではない。

### 3. 配布前に直す小さな1件（実装作業）

`index.html` の `apple-touch-icon` が **SVG を指している**（`/app-icon.svg`）。
**iOS Safari は apple-touch-icon に SVG を受け付けない**ため、「ホーム画面に追加」で
アイコンがページのサムネイルになる。PNG（180×180）を1枚用意して差し替える。

手渡しで入れてもらう計画の見た目に直結するので、**配布前に直す**。
`20260912-release-line.md` の3問には当たらない（審査でも必達3タスクでも落ちない）が、
本ログの施策A の実行に直接効くため、この1件だけ例外として先に処理する。
