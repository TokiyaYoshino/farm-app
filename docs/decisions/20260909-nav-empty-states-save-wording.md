# 「管理」タブの改称・空状態のCTA・保存文言の見直し

- 日付: 2026-09-09
- 状態: 採用（Web版のみ）
- 種別: 仕様変更（UI文言・情報設計）
- 根拠: [`docs/research/ai-placement-jp-apps-2026-09.md`](../research/ai-placement-jp-apps-2026-09.md) の国内アプリUX調査

## 課題（Why）

国内の大規模アプリと farm-app を照合して出た差分のうち、本人が実装を選んだ3点。

| 差分 | 根拠の強さ |
|---|---|
| 機能名「管理」を第一階層タブに置いている | **比較的強い**。国内は人称（マイページ／アカウント）か包括名（メニュー）で、機能名を置く例が見つからなかった。メルカリはマイページを下タブ→右上に降格させている |
| 空状態にCTAが無い（「予定はありません」等のテキスト1行のみ） | 一般論との食い違い（国内アプリ実物の空状態は取得できず）。ただし**新規利用者が最初に見るのは空の画面**という点は動かない |
| 保存文言が「保存する」固定 | 中。Zaim「入力する」、あすけん「完了」「記録」、弥生「保存して次へ」→最後だけ「保存」 |

## 決めたこと

### 1. タブ名「管理」→「メニュー」

**「マイページ」は採らなかった。** 中身が圃場・作物・農薬・ユーザーの登録で、個人のページではないため実態とずれる。また人物アイコンにするとヘッダ右上のユーザー切替と記号が衝突する（`CLAUDE.md`「同じアイコンを別の意味に使わない」）。アイコンは `Settings` のまま。

### 2. 空状態に次の操作を置く

- 記録一覧（記録0件）→「**最初の記録をつける**」
- 作物詳細の作業報告（0件）→「**記録をつける**」＋「この作付けの作業を記録すると、ここに並びます」
- カレンダーの今日の予定（0件）→「**今日の作業を記録**」

絞り込み結果が0件のときはCTAを出さない（操作は「条件をクリア」で、既に別に置いてある）。

### 3. 保存文言

- `＋記録` の主ボタン: 「保存する」→ **「記録する」**（このアプリの動詞に合わせる）
- **「記録して続けて入力」を追加**（弥生の「保存して次へ」型）。畑を回りながら複数件入れる場面を想定し、保存後もシートを開いたまま、**作物・圃場・日付は据え置き、1件ごとに変わるもの（メモ・数量・作業時間）だけ空にする**
- 目標収量などのインライン保存は「保存」のまま（体言止め・短さ優先）

## 影響範囲

- **DB / 権限 / API**: なし
- **既存機能**: 削除なし。`addReport` に `keepOpen` 引数を足しただけで、既定の挙動は従来どおり（保存 → シートを閉じ → ホームへ）
- **既存利用者**: タブ名の変更が唯一「慣れを崩す」項目。本番の利用者は5人（全員admin）

## 検証

`npx tsc --noEmit` clean / `npm run build` 成功。デモで、ナビが「ホーム / カレンダー / 相談 / 分析 / メニュー」になり、`＋記録` に「記録する」「記録して続けて入力」が並ぶことを確認。

**未検証**: 「記録して続けて入力」で2件目以降が意図どおり保存されるか（デモは Supabase に書けないため、保存そのものは動かせない）。**本番かプレビューでの確認が要る。**
