# 農薬の散布前チェック（適用情報＋使用実績の提示）

- 日付: 2026-08-05
- 状態: 決定
- 種別: 機能追加

## 背景（Why）

farm-app の作業報告は、農薬取締法の省令が定める帳簿記載5項目（**努力義務**）とほぼ1:1で対応済み。一方で、法的**義務**である使用基準（適用作物・希釈倍数・使用時期・総使用回数）の遵守支援は空白のままになっている。法的な重みは義務側の方が大きい。

必要なデータは既に持っている。FAMIC 登録適用部を `pesticide_registrations` に取り込み済みで、使用実績との突き合わせロジックも `src/App.tsx` の `formatPesticideLimits`（AI記録検索チャット用）に存在する。しかし**それは AI チャットのプロンプト文字列を組み立てるためだけに使われており、農薬を選ぶ画面には何も表示していない**。

競合アグリハブ（3万5千人）は「農薬を撒く前にアプリを開くことで誤使用を防ぐ」を機能の核に据え、使用回数の上限超過を「NG」と明示判定する散布管理を提供している。ここが空白のままでは、農薬管理を重視する層からはシェアを取れない。

## 決定

B案を採用する。

1. **集計単位は作付け（`crops`）**。年単位にはしない（総使用回数は生育期間中の上限のため）
2. **作物名の FAMIC 対応は手動紐付け**（`crops` に列を追加）。文字列の自動マッチングはしない
3. **判定は非対称**。超過の疑いのみ警告し、「OK・安全」とは決して表示しない
4. **表示場所は農薬管理タブの既存 FAMIC パネル＋作業報告フォーム**
5. **成分ベースのカウントは今回スコープ外**（商品単位である旨を画面に明示する）

## 選択肢と比較

| 案 | 内容 | 判断 |
|---|---|---|
| A | 商品単位・判定なし・原文提示のみ | 最小コストだが、競合が「NG」を出している以上ユーザー体験として後退 |
| **B** | **作付け単位＋手動紐付け＋超過側のみ警告** | **採用** |
| C | B＋成分ベースカウント | 法令上は最も正確だが、FAMIC 登録基本部（連番0）の取得・パースが新規に必要でコストが跳ねる。次段 |

## 判定を非対称にする理由

FAMIC の `total_count` は「14回以内(土壌灌注は2回以内…)」のような自然文を含み、数値化できないケースがある（`docs/db-schema.md` で正規化禁止を決定済み）。また作物名の紐付けが未設定の作物では適用行を特定できない。

これらの場合に「OK」と表示すると、**使用者を法令違反に導く**。判定できない側は必ず「判定不可・ラベルを確認」にフォールバックし、安全側に倒す。誤って警告を出さないことより、誤って安心させることの方が有害という整理。

## 影響範囲

- **DB**: `crops` に `famic_crop_name`（text, nullable）を追加。RLS は現状 `allow_all` のままなので新規ポリシーは不要だが、追加時に確認する（CLAUDE.md 規約）
- **既存機能**: 削除なし。農薬管理タブの適用情報パネルへの追記と、作業報告フォームへの表示追加
- **AppStore**: 法令に関わる表示のため「最終的な正は製品ラベルの表示」の注記を必須とする（既存パネルには `src/App.tsx:2943` に実装済み。新規表示にも同じ注記を入れる）

## 既知の制約（次段の課題）

- **成分ベース合算をしない**ため、使用回数は過小評価になりうる。画面に「商品単位の集計」と明示する
- **多年生果樹**では `crops.start_date` が数年前になるため、集計期間は「作付け開始日以降、ただし1年を超える場合は直近1年」とし、**集計期間を画面に必ず併記**する。作付けの終了・リセット操作の導入は次段
- **予定（`schedules`）への農薬選択追加は次段**。`schedules` に農薬列がなく、`addSchedule`・CalendarView の予定フォーム・`scheduleToReport` への波及が大きいため今回は見送る。これにより本機能は「撒いた後の記録時」と「農薬管理タブでの事前確認」の2箇所で機能し、予定入力時の確認は次段で実現する

## 過去の判断との関係

- `docs/db-schema.md` の「FAMIC 原文を数値正規化しない」方針を踏襲する
- 収穫量の集計ルールを `src/lib/metrics.ts` に集約した前例（roadmap 2026-08）に倣い、農薬の使用回数集計も `src/lib/` に集約して全画面で統一する
- `docs/roadmap.md`「競合の得意領域では正面から戦わない」との関係: 本件は新規に競合領域へ参入するものではなく、**既に投資済みの FAMIC 連携を出力していない状態の解消**であるため、この方針と衝突しない

## 調査の限界（記録として）

競合アグリハブの設計は、公式ヘルプ記事の検索スニペット経由で把握したもので、**実画面は確認できていない**（本セッションの egress ポリシーが App Store・Google Play・APPLION・アグリハブ公式サポートをいずれもブロックしたため）。「作付け単位で管理」「成分の数だけ使用回数をカウント」「上限超過は NG 表示」はヘルプ記事の記述に基づくが、UI の細部は未確認。
