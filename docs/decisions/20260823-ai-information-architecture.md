# AI機能の導線を「独立ボタン行」から「意図の生まれる場所」へ移す

- 日付: 2026-08-23
- 状態: 採用（第1段階を実装済み。第2段階以降は未着手）
- 種別: 仕様変更（情報設計・導線）

## 課題（Why）

機能はどれも競合レビュー調査に裏付けられて作ったのにニーズが体感できない、という相談から。実測すると原因は機能の有無ではなく**置き場所**だった。

### 実測（375px モバイル幅）

| 画面 | 実測値 |
|---|---|
| ホーム | カード7枚・全長 1,081px（1.3画面） |
| **記録一覧** | **カード33枚・1件あたり中央値167px・全長 5,875px（7.2画面）・1件につきボタン3個** |

### AI機能の到達手順（改修前）

| 機能 | 手順 | 判定 |
|---|---|---|
| 音声メモ構造化 | 記録フォームのメモ欄に内蔵 | 良い（文脈に埋まっている） |
| 次の散布はいつ？ | ホーム最上部（2026-08-23 に改善済み） | 良い |
| 日報にまとめる | 記録タブ →「記録一覧」に切替 → **横スクロール** | 画面外 |
| 記録に聞く | 同上 | 画面外 |
| 写真で診断 | 同上 | 画面外 |
| 農業エージェント | **Web版に存在しない**（Expo のみ） | 欠落 |

記録タブの既定表示は**カレンダー**なので、3機能は「タブを開く → 表示を切り替える → 横スクロールする」まで到達できなかった。

### 調査で分かったこと

- NN/g の Amazon Rufus 調査: [利用者はAI機能があると期待していないため気づかない](https://www.nngroup.com/articles/discoverability-ai-amazon/)。失敗要因は「非標準の位置」「意味の伝わらないラベル」「密なページ下部への埋没」。**farm-app の3機能は3つとも該当していた**
- [チャット窓として後付けするのではなく、既存インターフェースに文脈として埋め込む](https://medium.com/design-bootcamp/the-designers-playbook-for-ai-products-4549c3d1b648)
- [文脈的な手がかりが「これが何で、なぜ重要か」を補強する](https://www.eleken.co/blog-posts/make-ai-features-discoverable)

## 決めたこと

### 「AIタブ」「AIメニュー」は作らない

機能を1か所に集めるのは直感的だが、調査の結論は逆で、**AIを独立させるほど「わざわざ行く場所」になり使われない**。代わりに利用者の意図が生まれる場所へ分散させる。

| 利用者の意図 | 改修前 | 改修後 |
|---|---|---|
| 今日なにをすべき？ | 天気カード内の小さなリンク | ホーム「今日の一手」カード（実装済み） |
| **去年いつ撒いた？** | AI検索ボタン（画面外） | **検索窓の文脈**。語を入れたときだけ出し、0件のときは淡色を敷いて前に出す |
| この症状はなに？ | AI画像診断（画面外） | **写真の直下**。記録を作らず調べる経路はホームに残す |
| 今日の作業をまとめたい | 画面外 | 出力系2つ（日報・帳票）に整理し折り返し表示 |

**検索窓との統合が要**。検索して見つからなかった瞬間が、記録をAIに聞きたい瞬間そのもので、そこに出せば探させる必要がない。

### 第1段階として実装した範囲

- 記録一覧のボタン行から「記録に聞く」「写真で診断」を外し、性質の同じ出力系2つだけを残して `flexWrap` で折り返し（横スクロール解消）
- 検索語入力時に「「〜」について記録に聞いてみる」、0件時は「見つからないときは記録に聞いてみる」を淡色カードで表示
- 記録一覧の写真直下に「この写真で病害虫を調べる」
- ホームの「今日の一手」カードに「写真で病害虫を調べる」（記録を伴わない経路）

## 検討した代替案

- **案B: ボトムナビに「AI」タブを追加** → 却下。調査の結論と正面から反する。5タブ目は既存4タブの認知負荷も上げる
- **案C: ボタン行を「…」のオーバーフローメニューにまとめる** → 却下。横スクロールより更に隠れる。NN/g の指摘（埋没）そのもの
- **案D: ラベルを目立たせるだけ（色・サイズ）** → 却下。位置が意図と合っていない問題は色では解けない
- **現状維持** → 却下。差別化の中核が画面外にある

## 影響範囲

- **DB / 権限**: なし
- **既存機能**: 削除なし（CLAUDE.md の規約）。「写真で診断」「記録に聞く」はどちらも到達経路が変わっただけで、シート本体・API は未変更。記録詳細シート内の診断ボタンも従来どおり残している
- **ストア審査 / 規制**: なし

## プレモータム（半年後に失敗していたとしたら、何が起きたか）

1. **文脈に埋めた結果、逆に誰も見つけられなくなった。** 「記録に聞く」は検索語を入れないと出ないため、検索を使わない利用者には存在しない機能になる。→ 利用実績（`ai_outputs`）で検証できるが、現状は母数がゼロなので当面は分からない
2. **記録一覧の密度問題を放置したため、そもそも記録一覧まで到達されなかった。** 7.2画面ぶんのスクロールは残っている（第2段階・未着手）
3. **Web版に農業エージェントが無いままだった。** 最強の差別化が片方のプラットフォームにしか無い状態が続いた

## 未着手（第2段階以降）

優先順に記載する。

1. **記録一覧のリスト化**: 個別カード33枚 → 1枚のカードに hairline 区切りの行。**これは `CLAUDE.md` のレイアウト規則が既に「理想」として明記している形**で、移行が済んでいないだけ。7.2画面 → 2〜3画面になる見込み。調査でも[構造が浅く1行で済む項目はリストが勝ち、競合する複数ボタンは迷いと誤タップを生む](https://medium.com/tygodesign/choosing-lists-or-cards-2c9a47773edc)と一致
2. **農業エージェントの Web 版移植**: `api/advise.ts` は共通なので UI の新規実装のみ
3. **マネタイズ導線**: `docs/roadmap.md` の Free 日次上限は設計のみで未実装。**上限に達した瞬間＝価値を体験し切った瞬間**なので、アップグレード導線はそこに置く。料金ページに置くのは弱い。ただし課金軸自体が要再検討のため、`docs/decisions/20260823-pricing-plan-review.md` の決着が先
4. **フィルタチップ行の横スクロール**: 「担当」が画面外に切れている。今回のスコープ外だが同種の問題
