# 画面から専門用語を排除し、作物名は自動で当てる

- 日付: 2026-08-24
- 状態: 採用
- 種別: 仕様変更（UI文言・自動化）

## 課題（Why）

農薬の使いすぎチェック（総使用回数の遵守支援）は、作付けの作物名を「農薬ラベル上の作物名」に対応づけないと動かない。以前はこれを利用者に手入力させ、未設定の理由を76文字の説明文で書いていた。

**結果、本番の作付けは7件すべて未設定＝チェックが全件死んでいた。**

これは説明文の長さの問題ではなかった。引き継ぎ資料 T0（無マニュアルテスト）の言うとおり:

> 今回の作物名マッピングは、説明文を76文字書いた結果ああなった典型例で、**正解は自動で当てて聞かないことだった**

あわせて画面全体に内部用語が漏れていた。実測で **UI上の「FAMIC」が12箇所以上**（Web・アプリ両方）。しかも「未設定だと判定できない」という**機能が止まる理由の説明そのもの**に使われていたため、詰まった利用者が回復できない構造だった。40字超の文言が10本以上、最長68字。Web版とアプリ版で文言が食い違う箇所もあった。

**この機能の価値は高い。** ラベル記載の使用基準の遵守は農薬取締法上の**法的義務**（違反は罰則対象になり得る）で、帳簿への記録は努力義務にとどまる。ノウレコの中で数少ない「義務の側に効く」機能でありながら、伝わらないまま死んでいた。

## 決めたこと

### 1. 作物名は自動で当てる（`src/lib/cropAlias.ts` を新設）

当てにいくのは**2つだけ**。

1. **正規化しての完全一致** — NFKC ＋ カタカナ→ひらがな ＋ 長音・中黒の除去。推測ではなく同一表記の吸収（`ｷｬﾍﾞﾂ` ＝ `キャベツ`）
2. **人が作った別名表** — 漢字↔かなは辞書が要るため機械的に導けない（`ほうれん草`→`ほうれんそう`、`南高梅`→`うめ`）。`expo-prototype/scripts/link-famic-crop-names.mjs` の人手の表を起点に主要作物へ広げた

どちらにも当たらなければ**自動確定せず候補を出す**。類似度による推測は入れない。

**候補は自組織の農薬登録情報に実在する作物名だけ**を出す。存在しない名前を設定しても使いすぎチェックは動かず、「設定したのに見張られない」という最悪の誤解を生むため。

起動時に作物名の列だけを読む。適用情報の本体は農薬パネルを開いたときの遅延ロードだが、それを待つと「利用者が農薬画面を開くまで自動で当たらない」ことになり、聞かずに済ませるという目的を果たせない。

### 2. 画面から専門用語を排除（Web・アプリ両方）

| 出さない語 | 言い換え |
|---|---|
| FAMIC 作物名 | 農薬の数え方 |
| 判定不可 / 判定できません | 見張れません |
| 総使用回数 | 使える回数 |
| 照合 | 記録を確認 |
| 実施済み / 未実施 | やった / まだ |
| マスタ検索 | 検索から選ぶ |

**共通ロジック側（`src/lib/pesticideUsage.ts` の `verdictMessage`、`src/lib/adviceMatch.ts` の `statusLabel`/`matchDetail`）から直した**ので、Web とアプリに同時に効く。Web/アプリで食い違っていた文言も揃えた。

未設定時の警告色をやめ、当たっていれば `農薬の数え方：ほうれんそう` の1行だけ出す。

### 3. 「使えない」とは書かない

`no_matching_row`（名前は設定したが、その農薬の適用にその作物が無い）の文言を「この作物では使えない農薬かもしれません」とは書かない。ラベルが「果樹類」のような括りで書かれていると作物名が文字列として一致しないだけで、実際には使えることがある。**判定できないことと、使えないことは別**なので、判定不可のまま留める。

## 以前の判断を覆している（重要）

`docs/db-schema.md:26` と `scripts/migrations/2026-08-05-crops-famic-crop-name.sql:5-8` に、こう明記されている:

> 文字列の自動マッチングは誤判定を生むため実装しない

**これを、上記2つの範囲に限って覆す。**

覆す理由:
- 元の判断が防ぎたかったのは「**似ているから当てる**」（部分一致・類似度）で、それは今回も入れていない
- 今回入れたのは「同一表記の吸収」と「人が引いて書き写した表」で、どちらも推測ではない
- 手入力に委ねた結果、**本番で7件すべて未設定になり機能が完全に死んだ**。誤判定を恐れて何も判定しないより、確実な範囲で当てて残りは選ばせるほうが、法的義務の遵守支援として実効性がある

覆していない部分:
- 使用回数の判定ロジックそのものは従来どおり決定的ロジック（`summarizeUsage`）で行い、AI に投げていない
- 判定は非対称のまま。「超過の疑い」だけを警告し「OK・安全」とは決して表示しない
- 最終的な正はラベルの表示、という注記は維持

## 検討した代替案

- **案B: 説明文を短くするだけ** → 却下。76字を14字にしても、手入力させる限り未設定は残る。実際に7件すべて未設定だった
- **案C: 類似度（編集距離）で当てる** → 却下。「うめ」と「うめ以外のかんきつ」のような、**似ているが正反対のもの**が実在する。法的義務に効く機能で誤判定は許容できない
- **案D: 全作物のマスタを外部から取り込む** → 保留。FAMIC は作物名の一覧を単体で配布しておらず、適用部CSVから抽出すると巨大になる。自組織の登録農薬に実在する名前だけで足りる（使いすぎチェックの対象はそれだけ）
- **現状維持** → 却下。機能が死んでいる

## 影響範囲

- **DB / 権限**: スキーマ変更なし。`crops.famic_crop_name` の値を自動で埋めるようになる（既存列の更新のみ）
- **既存機能**: 削除なし。手動で選び直す導線は残している。判定ロジック（`summarizeUsage`）は未変更
- **規制・業界固有の実務**: 農薬取締法の使用基準に関わる。誤った対応づけは使用者を違反に導くため、当てにいく範囲を「確実な2つ」に絞った。ラベルが最終的な正である旨の注記は維持

## プレモータム（半年後に失敗していたとしたら、何が起きたか）

1. ~~**別名表が誤っていて、違う作物として数えていた。**~~ → **2026-08-27 に実際に起きていた。** FAMIC 登録適用部の全 58,591 行から作物名 1,323 種を抽出して突き合わせたところ、**6件が誤っていた**（下記「追記」）。テストに実在確認を組み込んで再発を防いだ
2. **自動で当たったことに気づかず、利用者が確認しないまま信用した。** 警告色をやめて1行にしたぶん、目に入りにくくなった。→ 押せば選び直せる状態は保っているが、能動的な確認は促していない
3. **候補に該当作物が無い状態が放置された。** 本番の実データでは、ほうれん草・にんにく・たまねぎに適用のある農薬が登録されておらず、自動でも手動でも当てられない。この3件は今も見張れていない。→ 「農薬を登録して適用情報を見る」を促す文言は置いたが、**そこから先は利用者の行動待ち**
4. **アグリハブの特許に触れていた。** 「農薬の登録情報の設定なしで自動計算」が請求の核心なら、自動化はその方向へ近づく。→ 下記「要ユーザー対応」参照

## 追記（2026-08-27）: 別名表を実データで検証し、6件の誤りを修正した

「人が引いて書き写したもの」と書いていたが、実際には農薬登録情報と突き合わせていなかった。FAMIC 登録適用部（`https://www.acis.famic.go.jp/ddata/`）の全 58,591 行から作物名 **1,323 種**を抽出して検証したところ、**6件が誤っていた**。

### 実在しないため削除（3件）

当たらないので実害は無いが、当たると思って書いていた。

| 誤り | 実際 |
|---|---|
| 唐辛子 → とうがらし | 「とうがらし」単体は無い。実在は「とうがらし類」「甘長とうがらし」等 |
| 檸檬 → レモン | FAMIC に「レモン」という登録作物名が無い |
| 麦 → こむぎ | 総称。大麦/小麦/裸麦に分かれ、どれか1つに決め打ちできない |

### 実在する別の作物へ飛ばしていたため削除（3件・**こちらが危険**）

| 誤り | なぜ危険か |
|---|---|
| 温州みかん → みかん | 「温州みかん」も「みかん」も**別々に実在する**。飛ばすと静かに別作物として数える |
| 稲 → 水稲 | 「稲」「水稲」は別の登録名として実在 |
| 米 → 水稲 | 「米」も独立して実在 |

**後者3件は「実在しないから当たらない＝安全」という理屈が効かない種類の誤り**で、実データと突き合わせなければ見つけられなかった。プレモータム1で懸念した「表の1行の誤りが使用回数の誤判定になる」が、実際に3件存在していた。
