# アカウントの形: 誰でも登録すると自分の農場ができる（個人＝1人の農場）

- 日付: 2026-10-01
- 状態: 採用（0.1.0 に入れる）
- **2026-10-08 一部を覆した**: アプリから登録できるのは個人（1人の環境）。チームは申請制（`20261008-pricing-per-person.md`）
- 種別: 仕様変更（認証・組織・権限）
- 関連: `20261001-pricing-freemium.md`（農場ごとの課金）、`docs/owner-decisions.md` B1・B2、`docs/multitenancy-progress.md`

## 課題（Why）

- 有料を 0.1.0 から入れる（`20261001-pricing-freemium.md`）。ところが今は**アプリ内で登録も組織の作成もできない**（利用者は管理者が Web から発行するだけ）。ストアから落とした知らない人は始められず、お金を払う入口が無い
- 本番で、オーナーの農場ともう1つの農場（`org='asuka'`・利用者1人）が**同じ `organization_id` に同居**している。RLS は `organization_id` で判定するため、API を直接叩けば互いのデータが読める

## 決めたこと

オーナーの方針: **個人は本人だけの環境。法人などは管理者が組織を作り、その下に利用者を置く。**

これを**1つの仕組み**で実現し、見え方だけ変える。

| | 個人 | 法人など |
|---|---|---|
| 中身 | 登録すると組織（農場）が1つでき、本人がその管理者になる | 同じ。管理者が利用者を加える |
| 見え方 | 組織の中が本人1人。**管理・招待の画面は出さない** | 利用者を加えた時点で管理の画面が出る |
| 課金 | 農場ごと月980円（本人1人の農場） | 農場ごと月980円 |

- 個人で始めた人が後から人を雇っても、作り直しは要らない
- 課金の単位（農場）と組織の単位が一致する

### B1: 同居している2農場は分ける

`asuka` を別の組織に移す。本番 DB への書き込みなので、手順（SQL）を用意し、**実行前にオーナーの確認を取る**。分けた後、外から匿名キーで越境できないことを確かめる（`feedback: RLSは外から匿名キーで確かめる`）。

## 0.1.0 に必要になる開発

- アプリ内の新規登録（登録と同時に組織を作り、本人を管理者にする）
- 管理者がアプリ内で利用者を加える画面（今は Web のみ）
- **アプリ内でのアカウント削除**（Apple ガイドライン 5.1.1(v)。アプリ内で作れるようになるため必須になる）。組織の最後の1人が削除するときの扱い（組織ごと削除するか）も決める
- 組織を作る処理のサーバー側の実装と RLS（新しい組織が他の組織を読めないこと）

## 影響範囲

- DB: `organizations` への行の追加がアプリから起きるようになる。作成は必ずサーバー側（`set-user-auth` と同じ流儀）で行い、クライアントに組織の作成権限を渡さない
- 既存機能: Web の管理画面からの発行は残す（削除しない）
- 審査: 5.1.1(v) が「対象外かもしれない」から「必須」に変わる（`20260912-release-line.md` 既知課題の最終行を解消する方向）
- `20260912-release-line.md` の「App Store に必要な機能開発はゼロ」は、料金と本件で**成り立たなくなった**。0.1.0 の範囲は別途まとめ直す
