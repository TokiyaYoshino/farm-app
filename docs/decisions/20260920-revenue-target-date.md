# 収益目標の期日を2027年3月末へ移す（額・課金対象は据え置き）

- 日付: 2026-09-20
- 状態: **採用**
- 種別: リリース計画（目標設定）
- 関連: [`20260920-pricing-data-scope.md`](20260920-pricing-data-scope.md)（課金軸の決定）、`docs/research/dr-2026-09/`

## 課題（Why）

課金軸は 2026-09-20 に決まったが、**収益目標の期日（2026年12月末・月30万円）は未決のまま**残っていた。調査（DR-04 / DR-08 / DR-09 / DR-10 / DR-12）は一貫してこの期日に不利な材料を出しており、判断を先送りすると「出せたが売れなかった」という最も情報量の少ない結果になる。

## 決めたこと

| | 旧 | 新 |
|---|---|---|
| 期日 | 2026年12月末 | **2027年3月31日** |
| 目標額 | 月30万円 | **月30万円（据え置き）** |
| 課金対象 | 個人 Pro 980円 | **個人 Pro 980円のみ（据え置き）** |

**期日だけを動かし、額と課金対象は変えない。** 組織単位の契約（導入支援＋伴走）を足す案は検討したうえで**採らない**（オーナー判断）。

### 3月末を選んだ理由

1. **確定申告シーズン（1月〜3/15）がまるごと期間の内側に入る。** 帳票出力は Pro 側に置いたので（`20260920-pricing-data-scope.md`）、**課金理由が年間で最も強くなる期間を、ピークに着地するのではなく使い切った上で数えられる**。記録アプリで最強の継続要因は外部提出要件（DR-12 §3.2）で、確定申告はその中で唯一「全農家に毎年来る」もの。
2. **Apple の45日ルールの制約が外れる。** 12月着金を狙う場合は「会計10月中に売上を立てる」＝10/10前後までに申請という最もきつい縛りがあった（DR-06 §8.3）。3月末ならこれが消え、申請を急いで1往復リジェクトを食うリスクを負わなくてよい。
3. 12月は稲作・露地・果樹が農閑期で、記録のニーズが年間で最も低い（DR-08 §7）。一般のサブスクでも12〜1月は解約が増える時期。

## この期日・額が要求する数値（明示しておく）

2026-09-20 → 2027-03-31 は **約6.3か月（約27週）**。月次チャーン5%・均等獲得で計算する。

| 段 | 値 |
|---|---|
| 3月末に**残す**有料件数 | 307件 |
| 必要な**累積**有料獲得 | **約361件** |
| 必要な無料登録（転換率5% / 4% / 3%） | 7,200人 / **9,000人** / 12,000人 |
| **週あたりの無料登録** | 263人 / **328人** / 438人 |
| 週あたりの有料転換 | **約13件** |

**比較対象**: アグリハブは会員登録6,000人に1年10か月（約95週）＝**週約63人**（DR-01）。しかもその成長は、2018〜2020年のTwitterオーガニックリーチとJAアクセラレータ第2期という**どちらも再現できない条件**に支えられていた。

> **必要ペースはアグリハブのピーク期の約5倍。** 予算ゼロの確定チャネルで見込めるのは10週で1桁〜数十インストール（DR-04 §3）で、必要量とは約100倍の開きがある。

本ログはこのギャップを**解消していない**。オーナーの判断として目標を据え置き、代わりに下記のチェックポイントで早期に誤りを検出する設計にした。

## チェックポイント（下回ったら必ず何かを変える）

**「頑張る」では通過できない線を先に置く。** 各時点で下回ったら、期日・額・課金対象のいずれかを必ず見直す。見直しを先送りしない。

| 日付 | 見るもの | 下回ったときの発動内容 |
|---|---|---|
| 2026-10-31 | ① App Store 0.1.0 が審査を通っている ② 媒介者（JA営農指導員・普及センター等）の面談3件 ③ 事前予約（出たら契約すると言った人）10件 | **③が0件なら、支払意思の実在から疑う。** 獲得施策より先に、断られた理由の分類をやり直す |
| 2026-11-30 | ① 無料登録 累積500人 ② 媒介者経由の一斉案内が1本決まっている | **②が無ければ桁が変わる経路が存在しない。** 組織契約か額の見直しを再提案する |
| 2026-12-31 | ① 有料 **40件**（307件の13%） ② **確定申告向けの帳票が動いている** | ②が未完なら、期日を申告期に合わせた利点を丸ごと失う。最優先で戻す |
| 2027-01-31 | 有料 **100件**（307件の33%） | **ここを下回ると3月末の307件は算術的に不可能**（残2か月で3倍が必要）。期日・額・課金対象のどれかを必ず変える |
| 2027-03-31 | 有料 307件 | 達成 or 未達の確定 |

1/31 の100件を「まだ生きている線」に置いたのは、そこから申告期の残り1.5か月で3倍まではまだ物語が書けるが、それ以下は書けないため。

## 検討した代替案

- **2027年2月末** → 見送り。確定申告（3/15）の直前で課金理由が最も強い瞬間ではあるが、**申告期のピークに着地しようとする形**になり、申告需要を使い切る前に数えることになる。3月末なら申告期がまるごと内側に入る
- **2027年4月末（DR-08 の第1推奨）** → 見送り。農業の年度始まりで春作業の立ち上がりと重なる利点はあるが、確定申告という**唯一の全農家共通の外部提出要件**の直後に1か月余分に置くだけで、その1か月が効く根拠がない
- **額を月10万円（個人102件）に下げる** → 見送り（オーナー判断）。必要な無料登録が2,000〜3,400人まで下がり、媒介者ルートが1本通れば射程に入る水準だった
- **組織契約（導入支援＋伴走、月2〜5万円）を足して10組織で達成する** → 見送り（オーナー判断）。10件は1件ずつ会って決められる数で、307件は会って決められない数。`docs/roadmap.md` の「アプリは単体の収益源ではなく、将来の農業コンサル事業に向けた関係構築・データ蓄積の入口」という位置づけとも整合したが、採らない
- **現状維持（12月末）** → 見送り。農閑期・解約期にあたり、かつ Apple の45日ルールで申請日程が最もきつくなる

## 影響範囲

- **DB / RLS**: なし
- **既存機能**: なし。ただし**帳票出力の中身が期日に直結するようになった**。現状は農薬使用履歴CSVのみで（`src/App.tsx` の「農薬使用履歴 帳票出力」）、**確定申告（農業所得）向けの出力が存在しない**。3月末を期日に置く以上、**2027年1月までにこれが動いている必要がある**（申告期の入口に間に合わせる）
- **AppStore / 法規・農業実務**: 45日ルールの制約が外れるため、申請日程の逼迫が解消。`20260912-release-line.md` の3条件は変更しない
- **他の計画**: 「0.1.0 に課金を載せるか」の判断（無料で先に出すか）は、12月着金の縛りが消えたことで**急がなくてよくなった**。別途判断する

## プレモータム（半年後に失敗していたとしたら、何が起きたか）

1. **チェックポイントを置いたのに、下回っても発動しなかった。** 「あと少しで届く」と判断を先送りし、3月末に初めて未達を確定させた。本ログを置いた意味が消える最も可能性の高い失敗
2. **確定申告を課金理由にしたのに、申告向けの帳票が1月に間に合わなかった。** 農薬使用履歴CSVのままで申告期を迎え、期日を申告期に合わせた利点を使えなかった
3. **必要ペース週328人が最初から一度も出ず、6か月かけて「予算ゼロでは無理」という既知の結論を再確認しただけだった。** その間、支払意思の検証（10者ヒアリング・事前予約）に時間を割かなかった
