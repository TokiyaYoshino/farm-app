# 全機能の棚卸し（各機能がある意味の問い直し）

- 日付: 2026-10-10
- 状態: 棚卸しのみ（**画面は変えない**）
- きっかけ: オーナー「各機能がある意味を問い直したい。特に圃場マップっていらなくない」

## なぜ今、表にするか

圃場マップだけを決めても、同じ問いがガント・タイマー・カレンダーで必ずまた出る。
1機能ずつ議論すると毎回ゼロから考え直すことになるので、事業定義（`docs/business-definition.md`）の
課題番号（W1〜W5 / F1〜F4 / P1〜P3）に全機能を一度当て、判定を1か所に置く。

## 前提（覆さないもの）

- **機能は削除しない**（CLAUDE.md）。判定は「どこに置くか」だけ
- **UI配置は凍結中**（`20260912-release-line.md`）。3問（審査／必達3タスク／法令記録・数字の食い違い）に当たらない変更は既知課題に積み、次のリリースでまとめて見る
- 使われ方の証拠は**既存の計測だけ**を使う（`reports` 件数、`ai_outputs.entry_point`）。新しい計測は作らない

## 判定の区分

| 区分 | 意味 |
|---|---|
| **前に出す** | 事業定義の中核（◎）に答える。ホームか各タブの先頭に置く |
| **そのまま** | 課題に答えている。今の置き場所で妥当 |
| **奥に下げる候補** | 課題への寄与が補助的、または毎日使わないのに目立つ場所にある |
| **基盤** | 単体では答えないが、他の機能の材料になる。前に出さないが消せない |

## 圃場マップについての結論

- **要らない、ではない。** 新人・季節の手伝いが「D圃場ってどこ」と聞く場面（F4）には効く。
  事業定義の「毎年同じ説明をする」の手当てとしては筋が通る
- **ただしホームに置く理由が無い。** ホームの3枚のうち、判断の答え（前回の散布・使用回数・次の作業）に
  つながらない行はこれだけ。毎日開く画面に、初日に1回だけ見るものが並んでいる
- **3問の判定**: ①審査✗ ②必達3タスク✗ ③食い違い✗ → **今は直さない**。
  `20260912-release-line.md` の既知課題に積み、次のリリースで「管理＞圃場の一覧の上にマップを開く行」へ移す
- 位置の登録（#17）は天気の自動取得に使っているので、マップと一緒に下げない

## 確かめること（判定を確定させるデータ）

| 何を | どこで | 判定がどう変わるか |
|---|---|---|
| 位置が登録済みの圃場の数 | 本番 `fields.lat IS NOT NULL` | ほぼ0なら、マップは開いても空。#14 を下げることに迷いは無くなる |
| タイマー経由の記録の件数 | `reports`（タイマー終了で作った下書きかの区別が取れるか要確認） | ほぼ0なら #11 もホームから下げる候補に入れる |
| 計画（ガント）のチケット件数 | 本番 `tickets` | 0なら #15 は分析タブから外す候補 |

いずれも本番DBの読み取りだけで済む。worker を配った後（リリース条件3）に見直すのが本来の時期。
