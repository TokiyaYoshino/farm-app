# 意思決定ログ

## 2026-07-31: AI出力の永続化と外部情報インプット（第1弾）／外部データ源の実物検証

- **背景**: AI機能5本の出力がすべて `useState` で使い捨てになっており、分析画面（`AnalyticsView.tsx`）はAI出力を一切参照していなかった。またAIの判断材料が「自農場の記録＋Open-Meteoの3日予報」に限られていた
- **決定した範囲**: 土台（`ai_outputs`）＋出力の保存/履歴＋分析への診断集計＋外部情報2種（気象の拡充・農薬登録情報）。**病害虫発生予察情報の取り込みと「AIに分析を読ませて総括させる」機能は次段の別仕様**（和歌山県の予察情報はPDFのみでAPIが無く、自動化が脆いため分離した）
- **外部提供はしない**: `/api/*` のAI系5本は無認証、RLSは全テーブル `allow_all` のままのため（`docs/adr-001-multitenancy-and-ai.md` §1 穴A）、AI出力を外に出す口（公開API・共有リンク・エクスポート）は本件で一切開けない。新テーブル3本も既存に合わせて `allow_all` を置き、RLS実ポリシー化で一斉に切り替える

### 実物検証の結果（2026-07-31 実施）

| 項目 | 実測 |
|---|---|
| FAMIC 登録適用部一 `R0807221.zip` | ZIP 684KB → CSV 10.0MB / 58,590行 / 25列 |
| FAMIC 登録適用部二 `R0807222.zip` | ZIP 460KB → CSV 8.1MB / 41,746行 |
| CSVの文字コード | CP932（Shift_JIS）。`TextDecoder('shift_jis')` が Node 24 で標準対応のため追加依存は不要 |
| ZIP形式 | 単一ファイルのDeflate。`zlib.inflateRawSync` で解凍可 |
| ファイル名 | 日付入りで更新ごとに変わる（月2回更新）。`index2.htm`（**UTF-8**、CSV本体とは別）から `datacsv/R\d+\.zip` を抽出して解決する |
| FAMIC の CORS | ヘッダ無し → ブラウザから直接取得不可。**サーバー側（Vercel Function）必須** |
| 気象庁 警報JSON `bosai/warning/data/warning/300000.json`（和歌山） | 200 OK / `access-control-allow-origin: *` → **クライアントから直接取得可** |

- **取得方式の確定**: 計画時は「数十万行で重すぎればローカルスクリプト方式に振り替える」としていたが、実測で計10万行・18MBと軽く、Vercel Function 内で処理可能と確認できたため **Function方式で確定**（`api/pesticide-registration.ts`）。スクリプト方式への振り替えは不要
- **気象警報の採用**: 計画時は「公式ドキュメントの無いエンドポイントのため到達性次第で見送る」としていたが、CORS許可付きで安定して取得できたため**採用**し、Open-Meteo と同じくクライアント側で取得する
- **副次的な発見**: 適用部CSVに「農薬の名称」列があるため、登録番号を知らなくても**名前から登録番号を引き当てられる**。農薬マスタ側に番号を手入力させずに済むUIにした

## 2026-07-28: マルチテナント化RLS対応ブランチでのローカル/リモートmain分岐の発見と対応

- **発見**: `claude/multitenancy-rls`ブランチ着手時、ローカル`main`が`origin/main`から9コミット遅れて分岐していたことが判明。
  ローカル`main`には2026-07-22決定のマルチテナント化ステップ1・2（本ログの下の項目）が反映されておらず、
  代わりに`origin/main`側には無いAI機能7コミット分（AI日報PoC・音声メモ・記録検索チャット・天気防除助言・画像診断・価格体系ドキュメント等）が
  ローカルのみに存在していた（origin未push）
- **原因（推定）**: 別々のworktree/セッションで並行作業した結果、同じ基点から2つの系列に分岐したまま一方がpushされずに残っていたと見られる
- **対応**: `origin/main`を正としてマージ・統合した（`organizations`テーブル・`organization_id`列は既に本番適用済みのため、フォールバック実装は不要と判断しorigin/main側の実装を採用）。ローカルmain固有のAI機能7コミットの扱いは本ログでは決定していない（要ユーザー対応、詳細は`docs/multitenancy-progress.md`参照）
- **今回追加した対応**: `api/notify-line.ts`のorganization_idパラメータ化（origin/mainには無かった）、越境アクセス確認用の手動テストチェックリスト（`docs/multitenancy-progress.md`）

## 2026-07-22: login_idの一意性方式 / マルチテナント化ステップ1着手
