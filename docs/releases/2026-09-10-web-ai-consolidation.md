## 規約に追加したもの（以後守る）

`CLAUDE.md` に反映済み。

- **ボタンは動詞、見出しは体言止め。** 国内25機能を数えた結果、「〜する」終止形も問いかけ形も0件。✗「次の散布はいつ？」→ ○「次の散布時期」
- **入口に「AI」の語を出さない。** ただし分析タブの出力履歴と農薬・診断の注意書きでは明示する（全部隠すと不誠実）
- **同じアイコンを別の意味に使わない**
- **サンプルデータに特定の地域・品目を使わない**
- **カタカナ語より漢字語を優先**（利用者に高齢層が多いため）

## 画面に出ない変更

- **AIの日次上限。** 従来は歯止めが1行も無かった。画像診断20回/日・その他50回/日、fail-open。`search-chat` だけは保存が無く数えられないので上限の外
- **導線の記録（`ai_outputs.entry_point`）。** 情報設計の変更は3回続けて「効果は未検証」で終わっていた。`kind` では代用できない（診断は4か所から出る）
- **移行SQL未適用でも壊れない起動時判定。** テーブルが無ければ相談タブごと出さない
- **デモモード。** `npm run demo` で認証も本番DBも介さず画面を確認できる（既定 off）

## リリースで踏んだ4点

1. **ガードは事故を防いだが、沈黙した。** SQL未適用の間は以前と同じ画面が出るだけで済んだが、オーナーからは「変わってない」としか見えず、理由を知る手段が画面に無かった
2. **その間、AIの利用ログが静かに落ち続けていた。** `entry_point` の列が無く insert が失敗。保存処理はコンソールに出すだけ。「壊れないから順序は後でもよい」と書いたが、計測は欠けていた
3. **移行SQLが相談を4件取りこぼした。** スキーマ定義ファイルの `crop_id not null` を信じたが、実テーブルは制約が付く前に作られていた。**定義ファイルと実テーブルは一致しない**
4. **同じ取りこぼしが再発する作りだった。** やること側も作付け経由で移行していた。親の発言を辿る方式に変更。確認クエリも1本しか無く、切り分けに往復を要した

## 残っているもの

### 作業者を招く前

- [ ] Vercel Production の `OPENAI_API_KEY` を確認（Development にしか無い疑い。未設定ならAI機能が全滅）
- [ ] 日次上限の 429 を本番で1回確認（fail-open なので、効いていなくても画面に何も出ない）

### 別の農家に配る前・必須

- [ ] **RLS を実ポリシーにする。** 今は全テーブル `allow_all`。今回作った穴ではないが、相談の会話全文が anon キー経由で読める対象に加わった。3系統＋Auth Hook 有効化＋越境テストが要る別作業。新しい `advice_threads` のポリシーも忘れずに（`docs/rls-rollout.md`）

### 保留中

- Expo版への反映（指示により未着手）
- カレンダーと記録一覧の分割（6タブになるため見送り）
- **相談タブの撤退条件（30日後に判断）** — AI呼び出し全体に占める `thread` ＋ `thread_tool` の割合で決める。20%未満なら降ろす / 40%超なら確定。撤退はナビ定義の1行を消すだけ

## 外部事例との関係

外部事例は不利だった。Amazon はボトムナビのチャットタブを2026年5月にやめており、国内でナビにAI相談タブを置いた例は1件も確認できなかった。それでも進めたのは、設計の起点が外部調査ではなく実際に触って出た「入口が多すぎて使いにくい」だったため。
