## 1. いま何が終わっているか

「ホーム用汎用AIアシスタント」は `docs/decisions/20260906-general-advice-entry.md` で2つの要求に分解された。

1. **農業エージェントの汎用化**（作物を登録していないと入口すら出ない）→ 完了（2026-09-06）
2. **入口を1つにまとめる** → **機能面は完了（2026-09-08）**。相談の窓に持ち込まれる3つの用事（知識・記録・写真）がそこで完結するか、正しい場所へ渡るようになった

**残っているのは配置の問題だけ。** 機能はあるが、置き場所は 2026-08-23 の情報設計（`20260823-ai-information-architecture.md`）の第1段階のままで、そこに橋渡しの導線が足された状態。

## 2. 現在の配置（実測・2026-09-08 時点）

### Web版ホーム（`src/App.tsx` tab === "home"）

縦順。**AI の起点が3つある。**

| 位置 | 要素 | 種別 |
|---|---|---|
| 1 | 天気カード | AIなし |
| 2 | **今日の一手** — 「前回の散布から◯日」（記録から計算・API不要） | — |
| 2a | └ ボタン「次の散布はいつ？」 | `soft` / 防除助言 |
| 2b | └ ボタン「写真で病害虫を調べる」 | `tertiary` / 画像診断 |
| 3 | **相談する** | — |
| 3a | └ ボタン「畑全体のことを相談する」 | **`primary`（ホーム唯一）** / 相談 |
| 3b | └ 「作付け中」リスト（作物ごと・やることバッジ） | 相談 |
| 4 | 統計カード / 予定 / 新着コメント / 記録一覧への導線 / 圃場マップ | AIなし |

### Web版 記録タブ

| 位置 | 要素 |
|---|---|
| 件数行 | 「日報にまとめる」（出力系） |
| 検索欄に文字が入っているときだけ | 「記録に聞いてみる」（淡色カード） |
| 各記録カードの写真の直下 | 「この写真で病害虫を調べる」 |
| 記録詳細シートの診断結果の下 | **「この結果をもとに相談する」**（今回追加） |

### Web版 相談シート（縦に長い）

対象セレクタ（`select`：畑全体／各作物）→ やること一覧 → スレッド → 農薬ラベルの注意書き（常設）→ **写真の添付表示**（あるとき）→ **「写真で調べる」**（`tertiary`）→ 入力欄＋送信

assistant の吹き出しの中身: 本文 → **「記録を調べる:「〈検索語〉」」**（今回追加・`secondary`）→ 見ておくこと → 農薬の登録情報 → 「この回答の前提（N件）を見る」（折りたたみ）

### Expo版

ホーム: 今日の一手 → 「相談する」カード（今回 Web と同じ振り分けに）。記録タブ: 日報／記録に聞く／写真で診断。橋渡しの相手（記録検索・画像診断シート）は **ホームと記録タブの両方に同居させた**（画面をまたげないため）。

**Web との差**（意図的に範囲外）: ホームの「作付け中」カードの未実施バッジが無い / 分析タブそのものが無い。

## 3. 動かせない制約（過去の判断・覆すなら理由が要る）

| 制約 | 出典 |
|---|---|
| **「AIタブ」「AIメニュー」は作らない**。独立させるほど「わざわざ行く場所」になり使われない（NN/g の Amazon Rufus 調査） | `20260823-ai-information-architecture.md` |
| **UI文言に「AI」を出さない**。汎用生成AIが競合なので「AIが使える」こと自体に課金価値が無い | `20260823-ai-wording-outcome-based.md` |
| **ホームの primary ボタンは1画面1個** | `CLAUDE.md` デザイントークン |
| **既存機能を削除しない**（ナビから外しても tab コンテンツは残す） | `CLAUDE.md` |
| **新カードを増やさない**（「今日の一手」の位置とホームの縦幅を守る） | `20260906-general-advice-entry.md` |
| 説明文を書きたくなったら、まず書かずに済ませる方法を検討する（①聞かない→②初期値・例示→③空状態の一行→④`?`） | `20260824-no-manual-test.md` |
| カードは影で描き border は使わない／深い角丸／完全ピルのボタン | `CLAUDE.md`・`docs/design-brief-widget.md` |

## 4. 詰めたい論点（配置の未決事項）

### 4-1. ホームに AI の起点が3つ並んでいる 🔴 最重要

「相談＝1つの窓」にしたのに、ホームには **「次の散布はいつ？」「写真で病害虫を調べる」「相談する」** が独立して並ぶ。3つとも AI で、うち2つは相談の窓からも到達できる（写真は「写真で調べる」、防除は相談で聞ける）。

- 統合するのか、役割で分けたままにするのか
- 分けるなら、利用者から見た違いを何と説明するか（「今日の一手」＝提案／「相談する」＝質問、という軸は成立するか）
- `20260906-general-advice-entry.md` は「新カードは作らない」と決めているので、**減らす方向**の検討になる

### 4-2. 「写真で調べる」が2箇所にある

ホームの「今日の一手」内と、相談シートの入力欄の上。後者は今回足した。重複を許すのか、どちらかに寄せるのか。

### 4-3. 記録検索の独立した入口は要るか

「記録に聞いてみる」は **検索欄に文字を入れないと現れない**（`20260823-ai-information-architecture.md` のプレモータム1が「検索を使わない利用者には存在しない機能になる」と自分で指摘済み）。相談からの導線ができた今、独立の入口をどうするか。

### 4-4. 相談シートの縦の長さ

対象セレクタ＋やること＋スレッド＋注意書き＋添付＋写真ボタン＋入力欄。スレッドが伸びるほど入力欄までが遠い。やることの畳み方、対象セレクタの置き場所（上部固定か、シート内スクロールか）。

### 4-5. 「記録を調べる」ボタンの位置

いま assistant の吹き出しの**中**、本文の直後・「見ておくこと」の前。吹き出し内に操作を置くのが適切か、吹き出しの外（下）に出すか。

### 4-6. 記録一覧のリスト化（第2段階①・未着手）

`20260823-ai-information-architecture.md` の第2段階の**最優先項目**で、いまも未着手。`docs/design-record-list.html` が**未追跡のまま存在**しており（この作業とは別スレッド）、「1件ずつのカードをやめて1枚に行を積む」「7.2画面 → 2〜3画面」の検討が途中。CLAUDE.md のレイアウト規則が既に「理想」として明記している形。

### 4-7. Expo と Web の情報設計のずれ

Expo にはホームの未実施バッジと分析タブが無い。UI/UX を詰めるとき、Expo を Web に合わせるのか、モバイルは別の設計にするのか。

## 5. 効果の測定について（設計判断の材料が無いことの明示）

**本番の利用実績はゼロに近い。** `ai_outputs` の呼び出しは開発時の動作確認のみ、本番ユーザーは5人で全員 admin、worker は0人（`docs/handoff-input-redesign.md`）。記録は18件・4.5か月。

→ **配置の良し悪しを実データで判断できない。** 過去2回の情報設計の変更（2026-08-23 / 09-06）も同じ制約下で、どちらも「効果は未検証」のまま。今回もその前提で議論する必要がある。

測れるようにはなっている（後から SQL で見られる）:
- `ai_outputs.input_summary` — 相談の対象（作物／畑全体）、記録件数、写真添付の有無、質問文
- `ai_outputs.output_json` — `recordSearchQuery` が入っているか＝記録検索へ渡した割合（過剰ルーティングの指標）
