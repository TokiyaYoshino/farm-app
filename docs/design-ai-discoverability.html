ノウレコ / 情報設計

AI機能を「探させる」のをやめる

機能はどれも競合レビュー調査から作ったのに、使われている実感がない。原因は機能の有無ではなく 置き場所だった。3つのAI機能は「タブを開く → 表示を切り替える → 横スクロールする」の先にあり、 375px幅では画面外に消えていた。

NN/g の Amazon Rufus 調査が同じ失敗を記録している。利用者はAI機能があると期待していないため気づかない ——「正直まったく気づかなかった。すごく役立つのに完全に見落とした」。失敗要因は 非標準の位置・意味の伝わらないラベル・密なページへの埋没で、ノウレコの3機能は3つとも該当していた。

02置き直しの原則

調査で一貫していたのは「AIを独立させるほど、わざわざ行く場所になって使われない」だった。

✗ AIタブは作らない

1か所に集めるのは直感的だが逆効果。独立したチャット窓として後付けせず、既存の画面に文脈として埋め込む。5タブ目は既存4タブの認知負荷も上げる。

意図が生まれる場所に置く

検索して見つからなかった瞬間が、記録をAIに聞きたい瞬間そのもの。「この葉なんだろう」と思うのは写真を見ている瞬間で、フィルタ行を探している瞬間ではない。

技術ではなく用事で名づける

「AI検索」ではなく「記録に聞く」。「AI画像診断」ではなく「写真で病害虫を調べる」。何が起きるかがラベルだけで分かる状態にする。

作付けの相談（Web版・新規）

最強の差別化がWeb版に存在しない欠落を埋める。api/advise.ts は共通なのでUIの新規実装だけで済む。

要点は助言が作業記録と照合されること。「未実施」と「照合できない」を混ぜず、農薬の数値はAIに書かせず登録情報の原文を別枠で出す。言ったことの実施を追えなければ、ただのチャットになる。

04実装の順

  1. 記録一覧のリスト化 — 個別カード33枚（1件167px・全長5,875px＝画面7.2個分）を、1枚のカードに区切り線の行へ。CLAUDE.md が既に「理想」と明記している形の未消化分で、2〜3画面に縮む。
  2. 作付け中カード＋エージェントのWeb移植 — 差別化がアプリ側にしか無い欠落を埋める。APIは共通。
  3. 日報をカレンダーの日付へ — 単独では効果が小さいので、カレンダー側の日付選択と併せて実装する。
  4. マネタイズ導線 — 無料枠の上限に達した瞬間＝価値を体験し切った瞬間に置く。料金ページに置くのは弱い。ただし課金軸そのものが再検討中のため、その決着が先。
