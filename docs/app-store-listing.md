```
作業・使った農薬・写真・その日の天気を1件にまとめて記録できます。貯まった記録は前年との比較や農薬の使用回数の確認に返ります。農場の管理者がアカウントを発行して使う業務用アプリです。
```

### 説明文

```
農作業レポートは、農場の作業記録を「後で使える形」で残すためのアプリです。

その日の作業・使った農薬・撮った写真・そのときの天気を1件にまとめて記録し、
貯まった記録を前年との比較や農薬の使用回数の確認に返します。

■ 作業の記録
・作業の種別、数量、作業時間、圃場、作物をその場で1枚のシートに記録
・写真の添付（その場で撮影、または端末から選択）
・使った農薬と散布量の記録
・記録した日時の天気を自動で取得
・手が塞がっているときは音声での入力
・前の記録をもとに作る（同じ作業の繰り返しを1回の操作に）

■ 前年との比較
・収穫量、目標の達成率、作業時間、防除の回数を前年の同じ時期と並べて表示
・今年・前年・目標を重ねた収穫量の推移
・作業時間の内訳（作業の種別ごと、担当者ごと）

■ 農薬の使用回数の確認
・登録された適用情報と自分の記録を突き合わせ、使用回数が上限を超えている疑いがあるときに知らせます
・残りの回数は表示しません。最終的な判断は農薬ラベルの記載によります

■ 現場の相談
・自分の農場の記録と、国が公開している防除マニュアルを踏まえた回答
・写真から病害虫を調べる
・助言された作業は、その後の作業記録と照合して実施済みかどうかを表示

■ チームで使う
・担当者ごとの週の予定と実績
・記録へのコメントと通知
・計画の一覧（ガント）

■ 圃場
・現在地から圃場の位置を登録
・地図上で圃場を確認

【ご利用にあたって】
本アプリは農場の業務用です。アカウントは農場の管理者が発行します。
一般の方がご自身で登録してご利用いただくことはできません。

相談・日報・画像診断の回答はAIが生成した参考情報であり、病害虫の判定や
防除の可否を保証するものではありません。実際の防除にあたっては、農薬ラベルの
記載とお住まいの地域の指導機関の情報をご確認ください。
```

## 3. スクリーンショット（6.7インチ・5枚）

**検索結果に出るのは先頭3枚**なので、順序は「何のアプリか → 何が返ってくるか」で組む。
`docs/research/competitor-app-reviews-2026-08.md` の「5★を分けるのは記録の出口があるか」に従い、
2枚目以降を出口に割く。**「かんたん」「やさしい」は使わない**（同調査で高齢者への言及は89件中0件）。

| # | 画面 | キャプション（体言止め・15字前後） | なぜこれか |
|---|---|---|---|
| 1 | ホーム（今日の予定・天気・相談の入口） | その日の作業が1画面に | 何のアプリかを最初に示す |
| 2 | 記録の入力シート（写真・農薬・天気つき） | 作業・農薬・写真を1件に | 毎日触る中心機能 |
| 3 | 分析（前年同時期比のKPIと収穫量の推移） | 前年と並べて振り返る | 高評価が最も挙げた出口 |
| 4 | 農薬の使用回数（超過の疑いの表示） | 使用回数の超過を事前に | 5★が繰り返し褒めた出口。法令側の価値 |
| 5 | 相談スレッド（記録と資料に基づく回答） | 記録を踏まえた助言 | 唯一の削除理由（次の作業が分からない）への答え |

### 撮影条件（守らないとリジェクト事由になる）

- **Expo の実機またはシミュレータで撮る。Web 版の画面を出さない。**
  見た目が違うのでガイドライン 2.3.3（スクリーンショットが実物と一致）に触れる
  （`docs/decisions/20260912-release-line.md` の同項）

## 4. 審査用情報

### デモアカウント（必須）

ログイン必須のアプリはこれが無いとガイドライン 2.1 で落ちる。
**管理者権限で全機能に到達できるアカウント**を1つ作り、ID とパスワードを記入する。
併せて**作業者権限のアカウントも1つ**用意しておくと、権限差の説明が通しやすい。

### 備考欄に書くこと

```
本アプリは農場の従業員が使う業務用アプリです。アカウントは農場の管理者が発行するため、
審査担当者様がご自身で新規登録することはできません。上記のデモアカウントをご利用ください。

・投稿されたコメントは同一農場のメンバーのみが閲覧でき、外部に公開されません。
・位置情報は、利用者が「現在地から設定」を操作したときにのみ取得します（常時取得なし）。
・アカウントの削除については下記「未解決」を参照。
```

## 5. 未解決（申請前に決着が要る）

### 5.1.1(v) アカウント削除の導線が実装されていない

実測: `src/` `expo-prototype/` `api/` のいずれにも**アカウント削除・退会の導線が1件も無い**。

`docs/app-store-submission.md` 7章は 5.1.1(v) を「ログイン必須の正当性」としか書いていないが、
Apple の 5.1.1(v) は**アプリ内でアカウントを作成できるアプリにアプリ内削除を求める**条項でもある。
farm-app はアカウントを**農場の管理者が発行**する方式なので、この要求から外れる可能性が高いが、
**外れると決めつけて出すのは危ない**（落ちると再提出で1往復増える）。

取りうる手は2つ。**この判断は申請前に要る**＝`20260912-release-line.md` の3問の①に当たる。

| 案 | 中身 | 費用 |
|---|---|---|
| **A（推奨）** | 削除の申し出先を `/about` と審査備考に明記し、組織が発行するアカウントであることを説明する | 文言のみ。数十分 |
| B | アプリ内に削除導線を実装する | 画面＋Supabase の削除処理。記録は組織に帰属するため、何を消して何を残すかの設計が要る |

A で出して、指摘されたら B、が順序として安い。**どちらにせよ、先に本人の判断が要る。**
