## Web版と Expo版の役割分担

App Store に出すのは **Expo 版**。Web 版は消えず、**管理者用のコンソール**として残る。

| | 使う人 | 持っている機能 |
|---|---|---|
| **Expo 版**（App Store） | 現場の作業者・管理者 | 記録・カレンダー・分析・ガント・AI4機能・農薬の使いすぎチェック |
| **Web 版**（kishu-farm.vercel.app） | 管理者のみ | 上記＋**アカウント発行**・帳票出力・農場の場所の設定 |

### マルチテナント化は Expo 側のコード作業ではない

RLS は Supabase 側の設定で、Web とアプリの両方に同時に効く。**アプリ側の変更は不要**。
根拠（2026-09-03 のコード監査）:

- insert 17箇所すべて（Web・Expo とも）が `organization_id` を明示している
- Expo は anon キー＋ユーザーJWT で接続しているため、**ログインし直せば新しい JWT が入る**

つまりアプリでやることは「一度ログアウトして入り直す」だけ。

### Expo 版に無い機能と、出す前に必要かの判定

| 機能 | 出す前に必要か | 理由 |
|---|---|---|
| **下書きの永続化** | **必要** | OSにアプリを落とされると入力が消える。記録アプリとして致命的（`lib/reportDraft.ts` が未コミットのまま失われている） |
| 記録一覧のリスト化 | 推奨 | スクリーンショットを撮る前にやると見栄えが変わる |
| 作業者アカウント作成UI | 不要 | Web の管理画面で発行する運用にする |
| 農場の場所の設定 | 不要 | 同上 |
| 帳票出力（CSV/PDF） | 不要 | 同上。GAP監査向けで、現場が毎日使うものではない |

Guideline 4.2（機能が最小限）に当たる薄さではない。

## 審査中に触ってよいもの・ダメなもの

**アプリは Web と同じバックエンドを共有している。** `expo-prototype/lib/ai.ts:9` の
`API_BASE` は `https://kishu-farm.vercel.app` で、DB も同じ Supabase。
**審査担当の端末が本番のこれを叩く**ので、ここが審査中の唯一の地雷になる。

| 直す場所 | 審査中 | 理由 |
|---|---|---|
| アプリのコード（`expo-prototype/`） | **自由** | 審査対象は提出済みのバイナリだけ。push しても審査中のアプリは変わらない |
| Web版のUI（`src/`） | **自由** | 審査担当は Web を見ない |
| `api/*` と Supabase（スキーマ・RLS・環境変数） | **凍結** | 壊すと審査担当の手元でアプリが動かず、**アプリのバグとしてリジェクトされる** |

- **TestFlight へのアップロードは審査に影響しない。** 審査待ちの間も新しいビルドを配って試せる
- **審査中のビルド差し替えは審査キャンセル＝列の並び直し。** リジェクト時か致命的バグのときだけ
- 承認後は**手動公開**にして日付を選ぶ

→ **RLS を申請前に終わらせる理由がもう一つ**: 申請してしまうと、審査が終わるまで流せなくなる。
