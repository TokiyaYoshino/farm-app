# 事業定義（誰の・どの課題を・どう解決するか）

- 決定日: 2026-09-28（`docs/decisions/20260928-business-definition.md`）
- 位置づけ: 機能・文言・ストア掲載・優先順位で迷ったら、まずここに当てる。
  `docs/roadmap.md` の「事業戦略サマリー（2026-07）」はこの文書で置き換えた

## 一文定義

> **経験の長さが違う人で畑を回している農家の、
> 「いつ・何を・どの農薬で」という判断が一人ひとりの記憶と勘に頼っている課題を、
> 畑の記録と農薬の登録情報を根拠に、誰が聞いても同じ答えが返るようにして解決する事業。**

短く言うと: **ベテランの記憶違いも、新人の「分からない」も、畑の記録が答える。**

| 要素 | 中身 |
|---|---|
| この人 | 経験の長さが違う人が一緒に作業する農家（家族＋手伝い＋新人、など） |
| 課題 | 判断の根拠が**人の頭の中にしか無い**。ベテランは記憶が不確かで、新人にはそもそも無い |
| 解決 | 記録を1か所に集め、その記録と農薬の登録情報から**同じ根拠で答えを返す** |

## この人を「年齢」ではなく「経験」で切る理由

オーナーの実感（2026-09-28）: ずっとやっている人は「覚えている」「感覚でミスる」、
若い人は「何をしていいか分からない」。自分の農場も経験の違う人が混ざっている。

外部の裏付け: 競合レビュー89件（`docs/research/competitor-app-reviews-2026-08.md`）で
**高齢者への言及は0件**。年齢に触れた唯一の例（20代・新規就農）が削除理由にしたのは
「画面が難しい」ではなく「**次にやる作業を教えてくれない**」だった。
→ 困りごとは年齢ではなく**経験の量**で分かれる。

| | ベテラン（経験が長い） | 新人・若手（経験が短い） | 経験の違う人が混ざる農場 |
|---|---|---|---|
| 状態 | 覚えている「つもり」 | 何をしていいか分からない | 人によって判断と記録がバラバラ |
| 起きること | 前回の散布日・今年の使用回数を記憶で判断してズレる。**使用回数の超過は農薬取締法の使用基準違反（義務）** | 毎回だれかに聞く／聞けずに止まる・間違える | ベテランの判断が新人に渡らない。聞かれる側の手も止まる |
| 返すべき答え | 「前回の散布から◯日」「この作付けで今年◯回目」 | 「次にやる作業」「この農薬はこの作物に使えるか」 | 誰が聞いても同じ答え |

## 農家の課題の棚卸し（3層）

根拠: [法]=農薬取締法・使用基準（agriculture スキル legal.md）／[競]=競合レビュー89件／
[統]=2025年農林業センサス／[仮]=仮説・未検証

| 層 | # | 課題 | 根拠 | この定義で扱うか |
|---|---|---|---|---|
| 農作業 | W1 | 記録が二度手間（夕方にまとめ書き・圃場ごとに同じ入力をN回・途中で消える） | [競] 不満2位 | ○ 入口として必須（答えの原料） |
| 農作業 | W2 | この農薬を今撒いていいか（適用作物・使用回数）をラベルと帳面で突き合わせる | [法][競] 5★ | ◎ 中核 |
| 農作業 | W3 | 次に何をすればいいか分からない | [競] 1★の削除理由 | ◎ 中核 |
| 農作業 | W4 | 天気を見て散布日を決める | [仮] | ○ |
| 農作業 | W5 | 誰がどこまでやったか分からない | [仮] | △ 補助 |
| 農業 | F1 | 出荷先から防除記録の提出を求められる（帳簿は努力義務だが取引上は事実上必須） | [法] | △ 仮説 H3 で検証 |
| 農業 | F2 | 去年と比べられない | [競] 5★ | ○ ベテランの記憶の裏付け |
| 農業 | F3 | 売上・コストが見えない | [競] 5★ | ✕ 今はやらない |
| 農業 | F4 | 季節の手伝いが入れ替わり、毎年同じ説明をする | [法] labor | ○ 新人側と同じ根 |
| 農家 | P1 | 判断を一人で抱える | [仮] | ◎ |
| 農家 | P2 | 高齢化（基幹的農業従事者の平均67.7歳）・経験が頭の中にしか無い | [統] | ◎ 根っこそのもの |
| 農家 | P3 | IT不慣れ・説明書を読まない | [仮] 高齢者言及0件 | ○ 無マニュアル方針で対応済み |

**構造**: 課題は「記録を書く苦労（入口）」と「記録から答えが返ってこない（出口）」に分かれる。
入口は競合の無料版（アグリハブ）がほぼ埋めている。5★のレビューは出口に付いている。
farm-app の独自資産は出口側にある——**記録アプリは記録を溜めるが答えない。汎用AIは答えるが、あなたの畑を知らない。**
その間が、この事業の置き場所。

## 選ばなかった定義

| 案 | 内容 | 主役にしない理由 | 扱い |
|---|---|---|---|
| A チーム進捗管理（2026-07 の方針） | 従業員のいる農業法人の「誰がどこまでやったか」 | アグリハブ無料版に作業者管理・人数無制限があり、差が弱い（`20260823-pricing-plan-review.md`）。法人営業の経路も無い | 「混ざる農場」の補助機能として残す |
| B 相談相手だけ | 判断を一人で抱える農家の相談 | 定義の中心として採用。ただし「経験の差」という誰の・なぜを足さないと汎用AIと区別できない | 本定義に統合 |
| C 防除記録と提出書類 | 出荷先に記録を求められる農家 | 痛みは強いが、オーナーの農場でも提出の有無が「分からない・一部だけ」。入口に据える根拠が無い | 仮説 H3 で検証。当たれば入口に戻す |

## 既存機能と課題の対応

**削除する機能は無い**（CLAUDE.md 規約）。この表は「何を前に出して見せるか」を決めるためのもの。

| 機能 | 対応する課題 | ストア・ホームで前に出すか |
|---|---|---|
| 作業報告（農薬・写真・音声メモ）、作業コピー | W1 | ◎ |
| 農薬の散布前チェック（使用回数・適用） | W2 ベテランの記憶違い | ◎ |
| 相談（次にやる作業・記録と登録情報をふまえた答え） | W3・P1 新人の分からない | ◎ |
| 次の散布時期（天気×散布実績） | W4・W2 | ○ |
| 記録に聞く（過去の記録検索） | F2・W2 | ○ |
| 分析（前年同時期比） | F2 | ○ |
| 写真で調べる（病害虫） | W3 | ○ |
| 日報にまとめる | W1・W5 | △ |
| 担当者進捗・計画（ガント）・コメント・メンション・LINE通知 | W5 | △ 補助 |
| 帳票出力 | F1 | △ H3 次第 |
| ダッシュボード・カレンダー・マップ・圃場・作物・農薬マスタ・タイマー | 基盤 | 前に出さない |

## やらないこと（この定義から導かれる）

- **売上・コスト管理**は作らない（F3。レビューでは強い要望だが、判断の根拠という軸から外れる）
- **チーム機能の新規強化**は今はしない。既存のまま残す
- **ストア・入口で「チームで共有」を主語にしない**（現行サブタイトルは差し替える。下記）
- **「OK・安全」と言い切らない**原則は維持（`20260805-pesticide-precheck.md`）。答えるのは根拠であって許可ではない

## 検証すべき仮説

最初の検証場所は**オーナー自身の農場**（経験の違う人が混ざっている）。worker アカウントを配ること
（`20260912-release-line.md` のリリース条件3）がそのまま検証の開始になる。

| # | 仮説 | 確かめ方 | 否定される条件 |
|---|---|---|---|
| H1 | ベテランは前回散布日・使用回数を記憶で判断し、ズレた経験がある | 農場のベテランに「前回あの農薬を撒いたのはいつか」を聞き、記録と照合。「記憶違いで困ったことはあるか」 | 記憶が記録とほぼ一致し、困った経験も無い |
| H2 | 新人は作業前にだれかに聞いており、聞かれる側の時間が取られている | 新人に「今日の作業を決めるとき誰に聞いたか」を1週間メモしてもらう | ほぼ聞いていない（段取りは管理者が全部決めて渡している） |
| H3 | 出荷先から防除記録を求められる農家が多い | 自農場の出荷先に確認＋近隣農家3〜5人に聞く | ほとんど求められていない → C は入口にしない |

**数えるもの**（既存の計測を流用。新しい計測は作らない）
- worker の作業記録件数／週（`reports`）
- 相談・記録検索の呼び出し件数と入口（`ai_outputs.entry_point`。n≧30 で配置の凍結を解く既存ルールと同じ）

H1・H2 の両方が否定されたら、この定義を見直す。

## ストア掲載への写像（2026-09-29 に `docs/app-store-submission.md` へ反映済み）

文言規則（CLAUDE.md）: 入口に「AI」を出さない／成果で書く／問いかけ形を使わない。

| 項目 | 現行 | 提案 |
|---|---|---|
| サブタイトル（30字） | 農場の作業記録をチームで共有 | **畑の記録が、次の作業と農薬の答えになる**（19字） |
| プロモーション用テキスト冒頭 | 作業者がスマホで残した作業・農薬・写真が… | **前回いつ撒いたか、今年何回目か、次に何をするか。畑の記録から、誰が聞いても同じ答えが返ります。** |

説明文の冒頭3行（案）:

```
ベテランの記憶違いも、新人の「分からない」も、畑の記録が答えます。
作業と農薬を記録しておけば、前回の散布からの日数、この作付けでの使用回数、次にやる作業を、
その記録と農薬の登録情報をもとに確かめられます。
```

以降の「■ 作業を記録」以下の本文は現行のままでよい。ただし並びを
**農薬の使用回数 → 相談 → 作業を記録 → …** に入れ替え、「■ チームで使う」は末尾へ。

スクリーンショットの並び（撮り直し不要・既存5枚の順番だけ変える）:
`02-soudan-chat`（答えが返る）→ `03-input`（記録）→ `01-soudan-list` → `04-bunseki`（前年比）→ `05-home`
