# AppStore申請 進行計画

最終更新: 2026-07-31

関連: `docs/decisions/20260731-adr-capacitor-native.md`（ネイティブ化方式）, `docs/multitenancy-progress.md`（マルチテナント化詳細）, `docs/roadmap.md`

## 目標

**8/18 に本審査へ提出**（フルスコープ：マルチテナント化完全対応＋Capacitor全機能移植）。承認まではさらにApple側の審査24〜48時間＋リジェクト時の再提出が乗る。

2026-07-31時点でスコープを「全部やる」で確定（RLS完全対応＋全画面のモバイルQAを両方含める）。2週間での申請は、この完全対応版だと収まらないため約3週間（19日）で計画している。

## 要ユーザー対応（今日中に着手推奨）

1. **Apple Developer Program登録**（Apple ID・支払い情報が必要）
   - 本人確認に数日かかる場合があるため、スケジュール上の最優先事項。ここが遅れるとそのまま8/18目標全体がスライドする
   - 着手後は待ち時間なので、他のタスクと並行して進められる
2. **SupabaseのJWTカスタムクレーム／Auth Hook設定**（ダッシュボード側の作業）
   - RLS実ポリシー化（Task #2）の前提。ダッシュボード作業自体は当日中に完了できるため、Task #1（ブランチ分岐解消）と並行して今日中に終わらせておくと後工程が詰まらない

## スケジュール

| フェーズ | 期間 | 対応Task |
|---|---|---|
| マルチテナント化 完全対応 | 7/31〜8/5（6日） | #1 ブランチ分岐解消 / #2 RLS実ポリシー化(全テーブル) / #3 越境アクセス手動テスト全項目 |

| テスト・提出 | 8/16〜8/18（3日） | #9 TestFlight内部テスト・本審査提出 |

## 経緯（判断の背景）

- 当初「2週間でMVPスコープ（RLS最低限＋アプリ版の画面を絞る）」を提案したが、2026-07-31にオーナーの意向で「全部やりたい」と確定。スコープを削らず約3週間の計画に変更した
- スコープを削らない代わり、Apple Developer Program登録など待ち時間が発生する項目は初日に前倒しして全体の遅延リスクを抑える設計にしている
