## 主な機能
- ダッシュボード（天気・収穫量・作業統計）
- カレンダー（作業報告・予定の表示、フィルター・ソート対応）
- 詳細ビュー（写真・農薬・天気表示）+ コメント機能（吹き出し形式、自分のみ編集可）

- 作物管理（作付け日・最終作業日・目標収穫量、実績vs目標収穫グラフ）
- 圃場管理（GPS位置、作付け履歴表示）
- 農薬管理（種別・希釈倍数・備考）
- 担当者進捗ビュー（週次テーブル、予定×実績自動マッチング、管理者のみ操作可）

- 農薬の散布前チェック（2026-08-05）：帳簿記載5項目（努力義務）は満たす一方、法的義務である使用基準（総使用回数）の遵守支援が空白だったため、`pesticide_registrations` の適用情報と自農場の使用実績を農薬管理タブ・作業報告フォームに表示。集計・判定は `src/lib/pesticideUsage.ts` に集約し、AI記録検索チャットも同じ関数を通す（回答と画面の数字が食い違わないようにするため）。**判定は非対称で「超過の疑い」のみ警告し「OK・安全」とは表示しない**（`total_count` が「14回以内(土壌灌注は2回以内…)」のような自然文を含み数値化できないため、判定不可側に倒す）。集計単位は作付け、期間は作付け開始日以降・1年超なら直近1年。作物と FAMIC 作物名（「ほうれん草」→「ほうれんそう」）は `crops.famic_crop_name` で手動紐付け（自動マッチングは誤判定を生むため実装しない）。成分ベースの合算と予定への農薬選択は次段（`docs/decisions/20260805-pesticide-precheck.md`）

- 防除助言への自農場の防除履歴の注入（2026-08-23）：競合調査で、残った差別化が「記録する場所とAIに聞く場所が同一プロダクト内にある」の一点だけと判明。ところが `api/pest-control-advice.ts` は天気しか見ず、`api/search-chat.ts` は記録しか見ないため、**唯一の差別化が2機能の谷間に落ちていた**。防除助言に前回散布からの経過日数・直近の散布履歴・同一商品の繰り返し・昨年同時期を渡し、「あなたの記録では」と参照させる。整形は `src/lib/pesticideUsage.ts` の `formatSprayHistoryForPrompt` に集約。**「同一系統薬剤の連用」は有効成分・RACコードのデータが無いため実装せず、判定不可に倒した**（`docs/decisions/20260823-pest-advice-history.md`）
- 相談にコードが数えた集計を渡す（2026-09-06）：防除助言は散布履歴を、記録検索は作業回数を受け取っているのに、**差別化の中核である相談だけが生の記録行しか受け取っていなかった**。`aggregates` を足し、`formatSprayHistoryForPrompt` / `formatWorkCountsForPrompt` の出力をそのまま渡す（新しい集計は書かない＝画面と数字が食い違わない）。実測では**渡すだけでは使わず**、「時期・回数の質問では必ず反映する」と明示して初めて「前回の散布から9日経過」と答えるようになった。同じ商品の連用を「だから次も散布」と読み替える危険も塞いだ（`docs/decisions/20260906-advice-reply-tone.md`）
- 相談の返答から文数の固定縛りを外す（2026-09-06）：「2〜3文」「全体500字程度」と縛っていたため、一言で済む質問にも3文書き、手順を聞かれても3文で打ち切っていた。普段使いのAIとの体感差はモデルの賢さより**この事務的な打ち切り方**にある。長さを質問側に合わせさせ、聞き返しは `follow_up_question` としてスキーマに専用枠を作った（プロンプトで「聞き返してよい」と書いても、実測では聞くべきことを `unknowns` に流していた。**置き場のある方へ行く**）。結論を先に述べる原則（`20260829-ai-output-structure.md`）は維持。実測で「摘果のやり方」113字/3文・「木の様子がおかしい」で聞き返しが出ることを確認。同ADRの「問題は総量ではなく配分」を本文側にも適用したもの（`docs/decisions/20260906-advice-reply-tone.md`）
- 相談の入口をホームの主操作に格上げ＋畑全体の相談を追加（2026-09-06）：差別化の根拠が最も強い農業エージェント（`docs/spec-ai-features.md` 8章）の入口が、ホーム下部の小さな一覧に埋もれ、しかも**作物を1件も登録していないと表示すらされなかった**。既存の「作付け中」カードを「相談する」カードへ格上げし（新カードは作らない＝「今日の一手」の位置とホームの縦幅を守る）、`crop_advice_messages`/`crop_advice_actions` の `crop_id` を nullable 化して「畑全体の相談」を追加。**目立つ入口を常に畑全体（＝農薬の登録情報を照合できない側）へ固定しない**よう、行き先は作物0件→畑全体・1件→その作付け・2件以上→畑全体で振り分け、シート内の対象セレクタで切り替える。「AIタブは作らない」判断（`20260823-ai-information-architecture.md`）は覆していない（`docs/decisions/20260906-general-advice-entry.md`）
- 相談を1つの窓にする＝機能間の橋渡し（2026-09-08）：入口を格上げした結果、そこに持ち込まれる用事は「知識」「記録」「写真」の3種類になったのに、果たせるのは知識だけだった（同ADRのプレモータム3が自分で名指ししている未完部分）。2つの側面で解く：**農薬の実績は材料を渡すだけ**（`pesticideUsage`）、**記録の検索はスキーマに枠を作り**（`record_search_query`。`follow_up_question` で「置き場のある方へ行く」ことが実測で分かっているため）、**写真はUIの導線と材料フィールドだけでLLMの判定枠は作らない**（「写真を撮ってください」は最も安易に出る提案なので、枠を作れば過剰に出る）。あわせて**畑全体の相談でも農薬の使用回数だけを解禁**した——作付け単位でコードが数えた実績とラベル原文の上限であり、作物を指定しないと判断できない性質の情報ではないため。ただし**「あと◯回使える」は明文で禁止**する（画面が意図的に残り回数を出していないので、相談だけが言うと数字が食い違い、しかも食い違う方向が「許可」側になる）。Expo版も同時に追随させ、畑全体の相談・集計の受け渡し・国の防除マニュアルまで揃えた（`docs/decisions/20260908-advice-handoff.md`）
- AI機能の訴求文言を成果ベースへ（2026-08-23）：汎用生成AI（ChatGPT等）が実質的な競合であり「AIが使える」こと自体に課金価値が無いため、UI文言から「AI」を前面に出す表現を落とした（AI日報→日報にまとめる、AI検索→記録に聞く、AI画像診断→写真で診断、防除タイミング助言→次の散布はいつ？）。`docs/decisions/20260823-ai-wording-outcome-based.md`

- 作物名の自動一致と専門用語の排除（2026-08-24）：農薬の使いすぎチェックは作付けの作物名を「農薬ラベル上の名前」に対応づけないと動かないが、手入力に委ねた結果**本番7件すべて未設定＝機能が全件死んでいた**。説明文を76文字書いた結果そうなった典型例で、正解は自動で当てて聞かないことだった。当てにいくのは「正規化しての完全一致」と「人が作った別名表」の2つだけで、類似度による推測は入れない（`src/lib/cropAlias.ts`）。あわせて画面から内部用語を排除し、**UI上の「FAMIC」を0件に**（Web・アプリ両方）。文言は共通ロジック側から直したので両方に同時に効く。以前の「文字列の自動マッチングは実装しない」という判断を範囲を限って覆している（`docs/decisions/20260824-plain-language-and-crop-mapping.md`）
- 無マニュアルテストの運用ルール（2026-08-24）：「説明書を読まずに始められて、必要になった瞬間にその場で分かる」を目指す。手当ての優先順は ①そもそも聞かない → ②初期値・例示 → ③空状態の一行 → ④`?`（最後の手段）。**ヘルプ文言を書きたくなったら、まず書かずに済ませる方法を先に検討する**。これは合否を出す門番ではなく詰まりを可視化する診断で、機能の削除・導線の格下げには使わない（`docs/decisions/20260824-no-manual-test.md`）

| | Free ¥0 | Pro ¥980/月 |

- **人数課金（席数）は廃止。** 旧 Team（¥2,980/月/組織、10人まで、超過+¥400/人）は取り下げる。大手3社（アグリハブ・アグリノート・KSAS）はいずれも人数を無料・無制限にしており、人数課金は比較時に最も目立つ弱点になる。組織向けの課金は将来、席数ではなく**組織運用機能**（権限管理・作業者別実績・監査ログ）に寄せる

- **既存利用者は grandfathering**（現 organization は `plan` を据え置き、制限を適用しない）。帳票出力と前年同時期比KPIは既に無料で動いているため

### Free枠のAI機能利用制限（原価管理）
Free会員のAI機能呼び出しは日次上限を設け、転換前に原価だけが膨らむのを防ぐ。競合（アグリノート・アグリハブ）はAI機能の呼び出し回数ではなく圃場数・記録数の上限で課金誘導しており参考値がないため、コスト単価・利用頻度・継続習慣化への影響から独自に設定。Pro 加入で上限を緩和する。

- **この表は2026-07時点の設計値で、実装値とは異なる。** 本番に入っているのは Web版リリース（2026-09-10）の日次上限（画像診断20回/日・その他50回/日・fail-open）で、実装は `api/_auth.ts` の `DAILY_LIMIT`（`docs/decisions/20260909-web-release-and-rollback.md`）。どちらに寄せるかは未整理
- 2026-09-20 の決定により、**日次上限は課金理由ではなく原価管理**として位置づける（`docs/decisions/20260920-pricing-data-scope.md`）

| 機能 | Free上限（2026-07 設計値） | 根拠 |
|---|---|---|
| 病害虫画像診断 | 1日1枚 | Vision API利用で単価最大。実利用でも1日1〜2回で足りる |
| 音声メモ構造化 | 1日5回 | 差別化の核となる日々の記録習慣。文字起こしは無料API・構造化のみ課金で単価が軽いため余裕を持たせ、Free段階での習慣化を優先 |
| 記録検索チャット | 1日3回 | 便利さの体験には数回で十分。日常的なヘビーユースはPro以上への転換フックにする |
| 天気×防除助言 | 1日1回 | 天気データ自体が1日単位、農作業の可否判断も基本1日1回 |

### 実装順序の原則
- マルチテナント化＋Stripe連携が未着手のため、プラン強制は現時点ではできない
- 機能は先にFree相当で全部作る。アクセス判定は1箇所の共通関数（フラグ）を通す形にしておき、マルチテナント化＋Stripe連携が済み次第、そのフラグを実際の課金判定に差し替える
