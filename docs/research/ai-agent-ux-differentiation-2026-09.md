## 1. 問い

> 同じような農業アプリが多くある中で、**自分の記録をもとにベストプラクティスを出し、外部の情報も取ってきて最善策を探る**ものは無いと認識している。この点の質を求めたい。ミリオンDLレベルで、後発かつ差別化が明確なアプリが、UI/UXでどういった項目・表示・デザイン・構成にしているか調べてほしい。

---

## 2. 結論（先に）

1. **「そんな農業アプリは無い」は"半分"正しい。** 部品は全部すでに他社にある（記録からの自動レポート／衛星による病害リスクの先出し／営農チャット／画像診断）。**無いのは、それらを1本の会話に束ね、出典を見せ、助言を作業記録と突き合わせて追いかけるところ**（3章）
2. **後発で勝った7例に共通していたのは「賢さ」ではなく「接地の見せ方」だった。** 出典を答えと同居させる（Perplexity）、参照範囲を常時画面に出す（NotebookLM）、記録そのものに貼る（Strava）、失敗の隣に置く（Duolingo）、採否を選ばせる（Cursor）、判定＋理由＋代替で完結（Yuka）、空欄を出さない（全社）（4・5章）
3. **NN/g は「推論の過程を語らせるな、出典を出せ」と言っている。** 段階的な理由づけは信頼できないため、確実性を装う説明より**根拠の提示**に倒すのが定石 [NN/g](https://www.nngroup.com/articles/explainable-ai/)
4. **外部一次情報の入口は、予察PDFではなく WAGRI だった。** 農研機構の農業特化型生成AI（公設試の栽培マニュアル・栽培暦・営農指導記録でRAG、**汎用AIより正答率+40%**）の **API を WAGRI に搭載予定**と発表されている【公式】。2026-07-31 に「予察情報はPDFのみで脆い」として外部情報を見送った判断の、**別の迂回路**にあたる（7章）

## 3. 前提の検証: 農業アプリのAIは、いまどこまで来ているか

|---|---|---|---|---|---|
| **Agrihub**（アグリハブ） | 4万人【公式】 | **AI栽培レポート**（2025-02）。作物を選び「レポート作成」を押すと**数秒で栽培レポート**。記録から重要ポイントを抽出し次シーズンの示唆を出す。スターター・プレミアム限定 | **使う** | ✗（1クリック生成） | ✗ |
| **KSAS AIチャット**（クボタ） | 農家 約3.2万軒【報道】 | 2025-07 正式版。**KSASの使い方・新規就農情報・営農の簡単な質問**に回答 | **確認できず**（発表に記載なし） | ○ | ✗ |
| **xarvio**（BASF） | ー | 衛星画像×気象×生育データ。**病害の発生リスクが高まる時期を予測してアラート** | 圃場データ（記録より衛星寄り） | ✗（アラート） | ✗ |
| **Plantix** | MAU 100万・累計1億件超の質問【報道】 | 画像診断（30作物・200超の病害虫）＋コミュニティ＋天気＋施肥計算 | ✗（その1枚の写真） | △（コミュニティ） | ✗ |

**farm-app の位置づけ**: 「記録から生成」は Agrihub が、「対話」は KSAS が、「先回りのアラート」は xarvio が、「画像診断」は Plantix が、それぞれ**単独で**持っている。**4つを1本の会話に束ね、さらに「助言 → やること → 作業記録との照合」まで閉じている例は、この調査の範囲で見つからなかった。**

> ただし「無い」は**探して見つからなかった**という意味でしかない。Agrihub・KSAS の実機は触っていない。**差別化の主張を外向けに書く前に、両方を実機で確認すること。**

## 4. 後発で大規模化した7例 — 何を、どう画面に出しているか

### 4.1 Perplexity（対 Google の後発）— 出典を答えと同じ画面に置いた

- 規模: MAU 1億超（2026-04）／アプリ累計DL 8,050万（2025-11）【集計】
- **項目**: 回答本文 / インライン番号引用 / ソースチップ / ソースパネル / 関連する次の問い / 検索範囲のモード
- **表示**: 事実主張ごとに番号付き引用。**ホバーで該当箇所の文脈が開き、ソースパネルは答えの横に出たまま**＝答えを離れずに検証できる。チップは角丸で **発行元ドメインを先頭**に出し、複数出典は `+3` のように畳んで文を汚さない
- **構成**: 「チャット履歴とペルソナ」ではなく「**出典と答え**」を並べる。検索は会話ではなく調べもの、という割り切り
- **含意**: **出典は「詳細」の奥に畳まない。** farm-app が「あなたの記録では」と言うなら、その記録が同じ画面から見えていないと同じ効果は出ない

### 4.2 NotebookLM（Gemini Notebook）— 参照範囲を常時見える場所に置いた

- **項目**: ソース（左）/ 対話（中央）/ スタジオ＝成果物（右）の**3ペイン**
- **表示**: ソースは**チェックボックスで参照範囲を選べる**。回答の引用は**ホバーで引用文、クリックで原文の該当箇所へジャンプ**。回答を「ノートに保存」すると**表もインライン引用も保ったまま**成果物になる
- **構成**: 「材料 → 対話 → 成果物」を**左から右へ**並べた。答えは通過点で、右端に残るものが目的
- **含意**: farm-app の相談も「材料（この作付けの記録・天気・登録農薬）→ 会話 → やること」の3層で、**材料と成果物が両方見えている**のが理想形

### 4.3 Whoop Coach（GPT-4搭載、2023-09）— ボトムナビに Coach を置き、質問例で埋めた

- **項目**: ボトムナビ（Sleep / Recovery / Strain / Stress / Behaviors / **Coach**）／質問例／自分の数値を引用した回答
- **表示**: 「今日はどう鍛えるべき？」「なぜ回復が低い？」「何時に寝るべき？」といった**具体的な質問文**が例として提示される
- **構成**: 24時間の生体データ＋利用者が語った目標や生活の文脈を土台に、**いま居る画面の文脈で答える**
- **含意**: 相談タブをナビに置いた farm-app の構成に、**最も近い先例**（Amazon Rufus の撤退例と対になる材料）

### 4.4 Oura Advisor（2025-03 全会員へ）— 入口を複数持ち、性格と頻度を選ばせた

- **項目**: 入口が複数（Today タブの「＋」とメニュー、**Readiness のインサイト文からそのまま会話へ**）／事前に用意された質問／グラフ入りの回答／**メモリ**
- **表示**: 会話スタイルを **conversational / direct** から選べる。チェックイン頻度も日次〜週次で選べる。回答にグラフ・傾向分析・**動的な話題の提案**が入る
- **構成**: **指標の説明文が会話の入口を兼ねる**（読んで気になったらその場で深掘りできる）
- **含意**: farm-app なら、**農薬の「超過の疑い」警告や天気の注意文が、そのまま相談の入口になる**。今は警告が行き止まり

### 4.5 Strava Athlete Intelligence — AI出力を専用画面に置かず、記録に貼った

- 規模: 1.5億人（2025年中）→ 1.95億人（2026-04）【報道】
- **項目**: 活動詳細の**スタットボックスの直下**に要約 ／「Say More」で詳細展開
- **表示**: アップロードした瞬間に自動生成され、**1タップで読める**。対象は run / ride / walk / hike など種目を限定
- **構成**: AI用の画面を作らず、**記録を見に来た人にだけ、その記録の文脈で出す**。有料転換の目玉として置かれている【報道】
- **含意**: farm-app の**作業報告詳細**に「この記録から読めること」を1行置く余地。相談タブへ行かせなくてよい

### 4.6 Duolingo「Explain My Answer」— 失敗した瞬間の隣に置いた

- **項目**: 誤答時の赤い「Incorrect」バナー内に **［Explain My Answer］と［Continue］の2ボタン**
- **表示**: 押した人にだけ、**その1問の文脈で**説明が出る。押さない自由も残す
- **構成**: AI機能を探しに行かせない。**つまずきの発生地点に置く**。当初 Max（有料）限定だったが後に無料開放【公式】
- **含意**: farm-app なら「使用回数の超過の疑い」「照合できません」の**その場**に「なぜ？／どうする？」を置く

### 4.7 Cursor（対 GitHub Copilot の後発）— 提案を「採否を選べる差分」で出した

- 規模: 0→ARR 20億ドルを24か月未満【集計】。職場採用率 18%（対 Copilot 29%）【集計】
- **項目**: インライン差分（緑＝追加/赤＝削除）／**変更ブロックごとの Accept・Reject**／`@file` `@folder` `@doc` `@db` `@terminal` で文脈を明示的に足す
- **表示**: 散文ではなく**受け入れ/拒否できる単位**。複数ファイルにまたがる提案も塊ごとに採否
- **構成**: 参考になるのは**失敗例もある**こと。差分レビューUIを弱めた更新で「**自社最大のUX上の強みを捨てている**」と公式フォーラムで強く批判された
- **含意**: farm-app の**「やること」カード（実施済み／未実施／やらない）は既にこの形**。ここは競合より前に出ている資産で、**弱めてはいけない**

### 4.8 Yuka（参考・非対話）— 判定＋理由＋代替で1画面完結

- 規模: 6,000万人【報道】
- **項目**: 1〜100のスコア ／ 信号色（赤・橙・薄緑・濃緑）／ 内訳（栄養60%・添加物30%・有機10%）／ **より良い代替品の提案**
- **構成**: 対話に持ち込まない。**スキャン1回で「判定 → 理由 → ではどうするか」まで出し切る**
- **含意**: 「だめ」で終わらせない。共同創業者は「**80歳を超える利用者もいる。とにかく簡単だから**」と述べている【報道】——高齢層が多い farm-app と重なる

### 4.9 あすけん（国内・参考）

- 累計会員 1,200万人超【報道】。AI栄養士「未来さん」が記録直後に助言。**チャットは「AIこんだて提案（β）」として最も絞った形**で提供

## 5. 7例から抽出した設計原則

**「AIを賢くする」原則は1つも出てこなかった。全部「接地を見せる」原則。**

| # | 原則 | 出どころ |
|---|---|---|
| P1 | **出典を答えと同居させる**（畳まない・ホバーで文脈・クリックで原文） | Perplexity / NotebookLM |
| P2 | **参照範囲を常に画面に出す**（何を見て答えたか） | NotebookLM |
| P3 | **空欄を出さない。** 挨拶＋質問チップ4〜6件が2023年以降の標準解。**チップは機能紹介も兼ねる** | 全社標準【業界解説】 |
| P4 | **既存の指標・警告文を、そのまま会話の入口にする** | Oura |
| P5 | **AI出力を専用画面に隔離せず、記録そのものに貼る** | Strava |
| P6 | **つまずきの発生地点に置く**（失敗の隣） | Duolingo |
| P7 | **提案は採否を選べる単位で出す**（散文にしない） | Cursor |
| P8 | **「判定 → 理由 → 代替」で完結させる**（だめで終わらせない） | Yuka |
| P9 | **推論の過程を語らせず、出典を出す。** 段階的な理由づけは信頼できないため、確実性を装う説明を避ける | [NN/g](https://www.nngroup.com/articles/explainable-ai/) |
| P10 | **応答スタイルと頻度を選ばせる**（会話調／簡潔） | Oura |

## 6. farm-app の現在地【実測】

`api/advise.ts` を読んだ結果。**「外部の情報をとってきて探る」は実装されていない。**

| 項目 | 実装 |
|---|---|
| モデル呼び出し | `gpt-4o-mini` / `temperature 0.3` / `max_tokens 1200` / **1リクエスト1回きり** |
| 道具（tool calling） | **0件**。モデルが自分で調べに行く経路が無い |
| 外部データ | 天気（Open-Meteo、クライアントが取得して文字列で渡す）。気象庁警報JSONは防除助言側 |
| 自農場のデータ | クライアントが組み立てて渡す（作業記録・登録農薬の適用行・過去の助言と照合結果） |
| 農薬の数値 | LLMに生成させず FAMIC 原文を `registration_facts` として別枠表示 |

一般知識の部分は**LLMの内部知識で、出典が無い**。ChatGPTに聞くのと質的に同じ＝**差別化にならない部分**。

### 原則ごとの差分

| 原則 | farm-app |
|---|---|
| P1 出典の同居 | △ 農薬登録の原文は表で出る。**それ以外の根拠は画面に無い** |
| P2 参照範囲の開示 | △ 防除助言だけ「使った天気を見る」。**相談スレッドには無い** |
| P3 空欄を出さない | ✗ **空のスレッドが出る** |
| P4 警告を入口に | ✗ 超過の疑い・照合不可が**行き止まり** |
| P5 記録に貼る | ✗ 作業報告詳細にAI出力は出ない |
| P6 失敗の隣 | ✗ |
| P7 採否を選べる提案 | ◎ **実装済み・最大の資産**（やること照合／`dismissed_at`） |
| P8 判定→理由→代替 | △ 非対称判定は資産だが、代替の提示が弱い |
| P9 出典を出す | ✗ 一般知識に出典が無い |
| P10 スタイル選択 | ✗ |

**◎が1つ、△が3つ、✗が6つ。**「質」の伸びしろは、モデルの賢さではなくこの表の✗にある。

## 7. 外部一次情報をどこから取るか

いま取れている3つ（すべて既存資産）:

| 情報源 | 状態 |
|---|---|
| Open-Meteo（実績7日＋予報7日） | 相談・防除助言で利用中 |
| 気象庁 警報JSON（CORS許可あり） | 防除助言で利用中 |
| FAMIC 農薬登録情報（月2回更新・CP932） | Vercel Function 経由 |

**追加候補**:

- **WAGRI 経由の農研機構 農業特化型生成AI API**【公式・搭載予定】。学習元は公設試・JA の栽培マニュアル／栽培暦／営農指導記録という**一般には手に入らない情報**で、汎用AI比 正答率+40%。**farm-app が自前の一般知識で戦うより、この一次情報側に寄せるほうが差別化になる**。要確認: 提供時期・料金・利用条件・出典の返り方
- **病害虫発生予察情報**: 2026-07-31 に「PDFのみでAPIが無く自動化が脆い」として見送り済み。**この判断は今回も覆さない**（新事実なし）。WAGRI 側で提供されていないかだけ確認する価値はある

**「外部情報が薄い」のではなく、「取れているのにモデルが自分で引けない」のが今のボトルネック。**
