## 1. 問い

> 同じような農業アプリが多くある中で、**自分の記録をもとにベストプラクティスを出し、外部の情報も取ってきて最善策を探る**エージェントは無いと認識している。この点の質を求めたい。

この認識は、少なくとも 2026-08 の競合調査の範囲では裏付けがある。競合（アグリハブ・アグリノート等）のレビュー89件を読んだ時点で、残っていた差別化は「**記録する場所とAIに聞く場所が同一プロダクト内にある**」の一点だった（`competitor-gap-analysis-2026-08.md`）。問題は、その一点を**画面の上で成立させられているか**である。

## 2. farm-app の現在地【実測】

`api/advise.ts` を読んだ結果。**「外部の情報をとってきて最善策を探る」は、現時点で実装されていない。**

| 項目 | 実装 |
|---|---|
| モデル呼び出し | `gpt-4o-mini` / `temperature 0.3` / `max_tokens 1200` / **1リクエスト1回きり** |
| 道具（tool / function calling） | **0件**。モデルが自分で調べに行く経路が無い |
| 外部データ | 天気（Open-Meteo、クライアントが取得して文字列で渡す）のみ。気象庁の警報JSONは防除助言側で別途利用 |
| 自農場のデータ | クライアントが組み立てて渡す（作業記録・登録農薬の適用行・過去の助言と照合結果） |
| 農薬の数値 | LLMに生成させず FAMIC 原文を `registration_facts` として別枠表示 |

つまり構造は「**あらかじめ人が集めた材料だけで1回答える**」であって、「探る」ではない。
外部の一般知識は **LLMの内部知識**から出ており、出典が無い。これは ChatGPT に聞くのと質的に同じで、**差別化にならない部分**にあたる。

一方、**他社が持っていない資産が3つある**。これは捨てずに核にする。

1. **助言 →「やること」→ 作業記録の照合**（`src/lib/adviceMatch.ts`）。「未実施」と「照合不可」を混ぜない
2. **農薬使用回数の非対称判定**（`src/lib/pesticideUsage.ts`）。超過の疑いだけ警告し「安全」とは言わない
3. **主題ごとのスレッドに溜まる**（`advice_threads`）。過去の助言を読み返せる

**差別化の核は「AIが賢い」ではなく、この3つ＝"自分の農場に接地していること"を画面で見せられるか**である。以下の事例は、その見せ方を集めたもの。

## 3. 事例（後発で大規模化し、接地・出典で差別化したもの）

すべて【記憶】。規模の数値は載せない（確認できないため）。**構造だけを読むこと。**

### 3.1 Perplexity — 出典を答えと同じ画面に置いた

- 後発（対 Google）で、差別化点は「AIの答え」ではなく **答えの各文に番号付きの出典が付いていること**
- 画面: 回答本文中に `[1][2]` の上付き番号 → 上部または横に**ソースカードの帯**（ドメイン名・タイトル・ファビコン） → 末尾に**関連する次の問い**が3〜5件 → 検索範囲を切り替える**モード選択**（Web / 学術など）
- 含意: **出典は「詳細を見る」の奥に畳まない。** 答えと同居させて初めて「調べてきた」ことが伝わる

### 3.2 NotebookLM — 「自分の資料」を常時見える場所に置いた

- 差別化点は生成能力ではなく **答えを自分の資料の中だけに閉じたこと**
- 画面: **3ペイン構成**（左＝ソース一覧・チェックボックスで参照範囲を選べる／中央＝対話／右＝ノート等の成果物）。回答中の引用チップを押すと**元資料の該当箇所に飛ぶ**。答えは「ノートに保存」で成果物に変わる
- 含意: **「何をもとに答えたか」が常に画面に出ている**こと自体が信頼の源。farm-app なら「この作付けの記録14件・天気14日・登録農薬78行」がそれにあたる

### 3.3 Whoop Coach / Oura Advisor — 個人の縦断データに接地したエージェント

- 差別化点は **自分の計測値を引用して答えること**（「あなたの直近3日は…だから」）
- 画面: **空のチャット欄を出さない。** 開くと今日の要約が先に1枚出て、その下に**質問候補のチップ**（「なぜ回復が低い？」等）が並ぶ。回答には自分の数値が本文に埋め込まれる
- 含意: farm-app の利用者は**質問文を自分で書かない**（高齢層・屋外・繁忙期）。スレッドを開いた瞬間に**先に喋る**必要がある

### 3.4 Strava の活動サマリー — AI出力を専用画面に隔離しない

- 差別化点は、AIの文章を**個々の活動記録の詳細画面に貼ったこと**。AI用の画面へ行かせない
- 含意: farm-app の作業報告詳細に「この記録から読めること」を1行置く余地がある。**記録を見に来た人にだけ、記録の文脈で出す**

### 3.5 Duolingo「Explain My Answer」— 失敗した瞬間の隣に置く

- 差別化点は機能ではなく**位置**。間違えた直後の画面にボタンがあり、その1問の文脈で説明する
- 含意: farm-app なら「農薬の使用回数が超過の疑い」と出た**その場**に「なぜ？／どうする？」を置く。今は警告だけで終わっている

### 3.6 Cursor — 提案を「差分」で出し、採用/却下を選ばせる

- 差別化点は、AIの出力を**散文ではなく、受け入れ/拒否できる単位**にしたこと。`@` で参照する文脈を利用者が明示的に足せる
- 含意: **farm-app の「やること」カード（実施済み／未実施／やらない）は既にこの形**。ここは既に競合より前に出ている。**伸ばすべきはここ**

### 3.7 Yuka — 「判定 → 理由 → 代替」の3点セットで完結させる

- 差別化点は、スキャン1回で **評価・その理由・ではどうするか（代替商品）** まで出し切ること。対話に持ち込まない
- 含意: 「だめ」で終わらせない。農薬が使えないなら**代わりに何を確認するか**まで出す（薬剤名は出せないので「登録のある薬剤の確認」に落とす）

### 3.8 深い調査（Deep Research 系）— 調べている最中を実況する

- 差別化点は、回答までに時間がかかることを**進捗の可視化で許容させた**こと（「〇〇を調べています」「n件読みました」）
- 含意: 道具を回すエージェントにすると応答が遅くなる。**遅さは実況で買える**

## 4. 8例から抽出した設計原則

farm-app に効く順。**「AIを賢くする」原則は1つも無い。全部「接地を見せる」原則である。**

| # | 原則 | farm-app の現状 |
|---|---|---|
| P1 | **出典を答えと同居させる**（畳まない） | 農薬登録の原文は表で出ている。**それ以外の根拠は画面に無い** |
| P2 | **「何を見たか」を毎回開示する**（記録n件・期間・天気・登録m行） | 防除助言だけ「使った天気を見る」がある。**相談スレッドには無い** |
| P3 | **出所を二層に分けて表示する**（自分の記録 / 外部の資料） | 分けていない。回答は全部同じ文章 |
| P4 | **空のチャットを出さない**（開いたら先に喋る・質問チップ3つ） | 空のスレッドが出る |
| P5 | **提案は受け入れ/却下できる単位で出す** | **実装済み・最大の資産**（やること照合） |
| P6 | **判定不可を潰さない** | **実装済み・資産**（非対称判定） |
| P7 | **失敗・警告の隣にエージェントを置く** | 使用回数の警告は出るが、そこから相談に入れない |
| P8 | **調べている最中を実況する** | 単発呼び出しのため該当なし（道具化するなら必須） |

## 5. 「外部の情報をとってくる」を実装するときの論点

### 5.1 単発呼び出しでは原理的にできない

現在の `api/advise.ts` は「材料を全部先に渡して1回答える」。**外部を"探る"には、モデルが自分で道具を呼ぶループが要る**（tool calling）。道具の候補は、いま人が手で組み立てているものをそのまま道具にするのが最短:

- `search_records`（自農場の作業記録を条件で引く）
- `pesticide_registrations`（FAMIC 原文を作物×病害虫で引く。**既に `api/pesticide-registration.ts` がある**）
- `weather`（Open-Meteo。**既にある**）
- `spray_history`（`pesticideUsage.ts` の集計。**既にある**）

**新規に作るものはほぼ無く、"渡す"を"引ける"に変えるだけで「探る」になる。** ここが今回の最大の発見。

### 5.2 外部の一次情報は、既に一度「見送り」判断がある

`docs/decision-log.md` の 2026-07-31 に **「病害虫発生予察情報の取り込みは次段の別仕様。和歌山県の予察情報はPDFのみでAPIが無く、自動化が脆いため分離した」** と残っている。**この判断は今回も覆さない。** 覆すだけの新事実（安定して取れる経路）を今回確認できていないため。

現時点で取れている外部情報は次の3つで、いずれも既存資産:

| 情報源 | 状態 |
|---|---|
| Open-Meteo（実績7日＋予報7日） | 取得済み・相談と防除助言で利用中 |
| 気象庁 警報JSON（CORS許可あり） | 取得済み・防除助言で利用中 |
| FAMIC 農薬登録情報（月2回更新・CP932） | 取得済み・Vercel Function 経由 |

**「外部情報が薄い」のではなく、「取れているのにモデルが自分で引けない」のが今のボトルネック。** 予察情報（PDF）に手を出す前に、5.1 を先にやる。

### 5.3 一般知識と一次情報を混ぜない

LLMの内部知識で書いた「目安」と、FAMIC 原文のような一次情報を、**同じ文章の中で同じ見た目にしてはいけない**。今のシステムプロンプトは「農薬の数値は渡された範囲だけ」と厳しく縛れているが、**画面上では両者が同じ本文に混ざって出ている**。P3（出所の二層表示）はここへの対処。
