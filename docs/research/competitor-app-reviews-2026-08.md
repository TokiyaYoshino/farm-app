# 競合アプリのストアレビュー実測（2026-08-09 / 全89件版）

**目的**：`docs/handoff-input-redesign.md` の「入力が面倒だから記録が続かない」という仮説を、自前データ（n=18・worker 0人）以外の一次情報で検証する。

> **改訂履歴**
> - 初版（22件・ストア表示分のみ）で「**『項目が多い』というレビューは1件も無い／入力UI再設計を支持する声は無い**」と書いたが、**これは誤り**。取得できていたのが Apple の既定「最も参考になった」順＝**高評価に偏ったサンプル**だったため。
> - 改訂版（本文）は**取得可能な全89件**。低評価を含めた結果、**入力負担は2番目に多い不満**だった。旧版の結論は撤回する。

## 結論（先に）

1. **1★を分けるのは入力画面の設計ではなく「動くか／動かないか」。** 最多の不満は**不具合・フリーズ・反応しない**（9件・うち7件が1〜2★）。
2. **2番目が入力負担**（8件・うち5件が低評価）。ただし中身は「項目が多い」より「**同じ入力をN回させられる**」「**入力途中に消える**」。
3. **5★を分けるのは「記録の出口」があるか。** 高評価は例外なく**振り返り・年次比較・売上・農薬使用回数**といった見返りに言及している。「めんどくさいと思いながらも」続けた人が5★を付けている。
4. **高齢者への言及は89件中0件。** 年齢に触れた唯一の例は「20代・新規就農」で、求めていたのは**簡単な画面ではなく次にやる作業の案内**だった。→ 引き継ぎ資料の「老人が使うから簡単に」を支持する外部証拠は**無い**。

## 調査方法

- 取得日：2026-08-09。App Store 日本
- **`itunes.apple.com/*/rss/customerreviews` は全variantで空**（HTTP 200・`entry` なし）。`amp-api.apps.apple.com` は 401
- 有効だったのは**レガシー iTunes デスクトップ経路**：ヘッダ `X-Apple-Store-Front: 143462-1,29` ＋ `User-Agent: iTunes/12.11 (Macintosh; OS X 10.15.7)` で
  `MZStore.woa/wa/viewContentsUserReviews` → `pageData.customerReviewsUrl` → `totalNumberOfReviews` と `userReviewsRowUrl` を得て
  `MZStore.woa/wa/userReviewsRow?...&startIndex=N&endIndex=N+20&sort=S&appVersion=all`（20件/頁・sort 1=参考 2=好意 3=批判 4=新着）を全ページ走査
- **APIが申告する総件数と取得件数が完全一致**（下表）＝取得可能分は網羅した
- 星ごとの内訳は `<script id="serialized-server-data">` の `$kind:"Ratings"` の `ratingCounts`。**配列順は [5★,4★,3★,2★,1★]**（両方の順序で加重平均を計算し公表平均と一致する側を採用して確定）
- Google Play の `batchexecute`（rpcid `UsvDTd`）は空。**罠**：Play の `com.agrinote` は**ベトナムの別アプリ**（開発者 `cdit.dev@gmail.com`／PTIT）。日本のアグリノートではない

### 限界（読むときの注意）

- **レビューは全ユーザーの分布ではない。** 評価数266に対して本文付きレビューは89件。書く人は「よほど気に入った」か「よほど困った」に偏る
- **アグリノートの直近14件は5日に固まっている**（2025-12-08×2 / 2026-02-25×3 / 2026-05-27×4 / 2026-05-28×2 / 2026-05-29×3）。うち10件が短文5★。**レビュー依頼キャンペーンの可能性が高く、割り引いて読む**。アグリハブは日付が散っており自然
- KSAS は5件しかない。「2.6という低評価」は読めるが、不満の内訳を統計として扱うには足りない

## 不満の分類（89件・多い順）

### 1. 不具合・フリーズ・反応しない ← 9件（うち1〜2★が7件）・最多

- アグリハブ 1★「タップ反応しなさすぎ」— iOS18 で反応しない
- アグリハブ 2★「フリーズが多く使いたい時に使えない」— 「**現状では手書きのノートの方が効率的です**」
- KSAS 1★「Crashes」／KSAS 1★「全く使い物になりません」
- ほか、起動しない・落ちる・同期しない系

**含意**：**入力画面をどう設計しても、動かなければ手書きに負ける。** farm-app は未公開なので実績が無い＝この不満は「まだ発生していない」だけ。公開前の安定性検証がUI改修より上位。

### 2. 入力負担 ← 8件（うち低評価5件）・**初版で見落としていた層**

内訳は3つに分かれ、性質が違う。

- **(a) 項目が多い**：アグリノート 2★「使い方」— 「**入力項目が多く手がつけづらい**」← 初版で「0件」と書いた型。実在した
- **(b) 同じ入力をN回させられる**：アグリハブ — 同時散布した複数薬剤をまとめられない／複数圃場に同じ農薬を撒くと圃場ごとに入力が必要／同一圃場の複数品種は「南から2列目」等の命名で回避するしかない
  - 開発者返信が示唆的：複数作物への同時散布は**検討したが「シンプルな画面構成にできず断念」**
- **(c) 入力途中に消える**：アグリハブ 5★（高評価の中の不満）— 「**作業記録入力中、他アプリに移動すると、すぐに入力中の記録が失われてしまいます**」。カメラで撮って戻るとメモが消えている。1分は保持してほしい

**含意**：(a) は実在するが1件で、しかも同じアプリの5★が「我慢して使い続けると必要性がわかる」と言っている。**(b)(c) のほうが件数も具体性も上**。「1画面を軽くする」より「**N回を1回にする**」「**消さない**」。

### 3. PC版とアプリ版の機能差 ← 4件

- KSAS 2★「**アプリ版はPC版でできる事の1/10**」— 圃場で撮った生育写真を生育記録に上げられずPCに移す必要がある。「1番欲しい機能が抜けています」（アグリノートに移行すると書いている）
- KSAS 2★ 自動日誌が反映されない／トラクターの作業内容を変更できない
- アグリノート「パソコン版と使い方が違うところを直して欲しい」
- アグリノート「計画・作業指示・初期設定はPC、アプリは作業記録と生育記録のみ。**アプリはあくまでも補助的に使うのに向いています**」

**含意**：farm-app に**そのまま存在する**。引き継ぎ資料 2.5章の「**アカウント作成UIがWeb版のみでExpo版に無い**」はこの型そのもの。

### 4. 入力の粒度・単位・検索の制約 ← 4件

- アグリノート 4★「作業時間が**10分単位でしか入力できない**」／PCから画像を複数落とせない
- aKnow「重量単位が kg 固定。花も作るので『本』も欲しい」
- アグリハブ 2★ 農薬検索が**強制AND**で目的の薬剤に辿り着けない
- アグリハブ 3★ **作物別の集計**が欲しい／**施設・作業所の登録**が欲しい

**含意**：引き継ぎ資料3章の注意（`quantity_unit` 5.6% を「不要」と読むな）が外部証拠で補強された。**単位・粒度は「多すぎる」ではなく「足りない」と言われている。**

### 5. 必須項目が邪魔 ← 1件

- aKnow「日報のとこ必須欄があるの邪魔」— 「休みの時つけれない」。開発者は反論

### 6. 初心者が何をすればいいか分からない ← 1件（唯一の年齢言及）

- アグリハブ 1★「よくわからなかった。」— 20代・新規就農。「**種まきした日を入れると今後の作業なども教えてくれる**」ようなものを期待していた。分からず**アプリを削除**

**含意**：**唯一の年齢言及が「20代」で、求めていたのは簡単な画面ではなく作業の案内。** 「老人が使うから項目を減らす」とは別方向の要求。

## 高評価（4〜5★・59件）が褒めている点

**共通しているのは「記録の出口」がある**こと。

- **振り返りの価値**：アグリノート 5★「**我慢して使い続けると必要性がわかる**」— 「めんどくさいと思いながらも」続けたら作の終わりに反省材料が多く見つかり、**指導員から褒められた**。「データが年々積み重なっていくのが楽しみ」
- **年次比較・売上**：アグリハブ 5★ 前年同月との売上比較が見える／**商品別・販売先別・月別の売上**が出る
- **農薬管理**：複数の5★が農薬機能を挙げる。**適用の可否と使用回数**が確認できる点
- **その場で完結**：アグリハブ 5★「圃場でその場で記録を完結できる」（※**同じレビューが入力消失バグを報告している**）
- **多品目でも続く**：アグリハブ 5★「多品目農家の必需品！」— 「**日々の入力にストレスがなく唯一続けてこられた**」。開発者が農家であることを評価
- **想定外の使い方**：アグリノート 5★ ドローン散布の請負業者が**顧客の**圃場を登録して使う
- **当事者性**：アグリハブは開発者自身が農家。返信で「私が野菜農家なので、農薬にこのような使い方があることを知りませんでした」と述べる。個人開発で121評価・4.0を支えている

## 「対象者」について分かったこと

- **高齢者への言及は89件中0件。** 「老人には難しい」「高齢の従業員が使えない」というレビューは1件も無い。**老人仮説を支持する外部証拠も、否定する証拠も無い**
- **入力しているのは経営者・管理者本人が中心。** 「PCで計画・指示、アプリで記録」と自分の作業を語る人、請負業者、家庭菜園など
- **「従業員が自分の作業記録を入力している」と明言したレビューは0件。** 最も近いアグリノート「**使い始めてから従業員への指示がいらなくなりました**」は従業員が**閲覧**している話
- → **farm-app の現状（admin 5人・worker 0人・全件admin入力）は競合の利用実態から見て異常ではない。** 「現場の作業者が入力すべき」という前提自体が未検証
