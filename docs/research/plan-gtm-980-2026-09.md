## 0. 先に検算する（この計画の形を決めている前提）

調査項目を並べる前に、目標そのものを数字に落とす。**ここが計画の分岐点**なので、メンバーに配る前に必ず読む。

### 0-1. 必要な有料件数

| 前提 | 必要件数 |
|---|---|
| 980円がそのまま入る（Web決済・手数料無視） | **307件** |
| App内課金・小規模事業者プログラム（手数料15%） | **361件** |
| App内課金・通常（手数料30%） | **438件** |
| 上記に加え 980円が税込 → 税抜891円で計算 | **さらに1.10倍** |

**「30万円」が売上（グロス）か手残り（ネット）かで、必要件数が1.4倍変わる。**

**【2026-09-18 オーナー決裁・確定】グロス307件を目標とする。**
- グロス（売上総額）= 顧客が払った合計。980円 × 307件 = 300,860円
- ネット（手取り）= そこから決済手数料・ストア手数料を引いて口座に残る額
- ネット30万円だと App内課金経由で438件になるため、ここはグロスで固定する

### 0-2. 期間と速度

- リリース 10月中旬 → 12月31日 = **約77日**
- 307件 ÷ 77日 = **1日あたり純増4件を、年末年始も含めて毎日**

### 0-3. 個人課金（D2C）で積む場合に必要な無料ユーザー数

フリーミアム転換率を2〜5%と置くと（`20260823-pricing-plan-review.md` の前提）:

| 転換率 | 必要な無料ユーザー | 1日あたり新規登録 |
|---|---|---|
| 5% | 6,140人 | 80人/日 |
| 3% | 10,230人 | 133人/日 |
| 2% | 15,350人 | 199人/日 |

**比較対象**（`dl-target-20k-2026-09.md` より・原文未検証）:

- アグリハブ: 登録者5万人まで数年、**2万人まで約3年半** ≒ 平均16人/日
- KSAS（クボタ）: 会員26,400人まで約5年 ≒ 平均14人/日（全国販売網つき）

つまり D2C 単独の場合、**業界の実績値の5〜12倍の獲得速度を、ブランドゼロ・レビューゼロの状態から77日間維持する**設定になる。現状の本番は worker 0人・記録18件。

### 0-4. したがって、この調査の本当の問いは1つに絞られる

> **307件を「1人ずつ」集めるのか、「まとめて」集めるのか。**

まとめて集める場合の形（980円/席の団体一括）:

| 契約単位 | 席数 | 月額 | 30万円に必要な件数 |
|---|---|---|---|
| 生産部会・農業法人 | 100席 | 98,000円 | **3件** |
| 同 | 50席 | 49,000円 | **6件** |
| 同 | 20席 | 19,600円 | **16件** |

**3〜6件の団体契約なら、77日でも射程に入る。307人の個人課金は入らない。**
ただし団体側の決裁が年度予算（4月始まり）に縛られるなら、10月着手で12月課金開始は成立しない。

**→ この計画の最優先調査は「団体一括は売れるか／決裁は何ヶ月か」（WP1）。他はその後ろに並ぶ。**

## 1. この調査で決める3つの分岐

調査は「知識を集める」ためではなく、**次の3つを選ぶため**に行う。各調査パッケージは必ずどれかに紐づく。

| 分岐 | 選択肢 | 決める調査 |
|---|---|---|
| **A. 収益の形** | ①個人307件 ②団体3〜6件 ③併用 | WP1, WP2 |
| **B. 無料と有料の線** | ①機能で切る ②蓄積データの活用範囲で切る ③席数・圃場数で切る | WP3, WP4, WP5 |
| **C. 12月という期日の扱い** | ~~①課金開始を12月まで ②契約内定30万円相当~~ → **①で確定（2026-09-18）** | 確定済 |

### 分岐Cの確定と、その帰結（2026-09-18）

**オーナー決裁: 12月末時点で「実際に課金が立っている30万円」を成果とする。**「契約内定」は成果に数えない。

この決定は目標を厳しくするだけでなく、**買い手を絞り込む**。帰結を明示しておく。

| 帰結 | 内容 |
|---|---|
| **年度予算の相手が対象外になる** | JA・自治体・公的機関は予算年度が4月始まり。10月に提案して12月に支払いが起きるのは補正予算等の例外のみ。**JAアクセラレーター等のチャネルは「12月の売上」には効かない**（来年度の仕込みとしては有効） |
| **即決で払える相手だけが残る** | ①農業法人（自社決裁・年度に縛られない）②個人農家（カード）③農機販売店・農薬販売店・種苗店等の民間商流 |
| **課金インフラが日付のクリティカルパスになる** | 「契約内定」なら決済が未完成でも成果は立つが、「課金」は決済が動いていないと1円も立たない。**WP6が最優先級に繰り上がる** |
| **リリースを待って営業を始めると間に合わない**（下記の逆算参照） | |

### 逆算カレンダー（12/31から引く）

| 期限 | やること | 根拠 |
|---|---|---|
| **12/31** | 月額30万円が課金されている状態 | 目標 |
| **12/10** | 契約・決済開始が完了（12月分の請求サイクルに乗る最終ライン） | 月額課金は契約開始日に初回課金。年末年始の事務停止を見込んで3週前倒し |
| **10/10〜10/31** | 商談を開始している | 法人の商談→契約は1〜2ヶ月（**WP1で検証すべき数字。ここが3ヶ月なら12月は成立しない**） |
| **10/10** | 営業資材（価格表・提案資料・デモ）と**請求手段**が揃っている | 商談に持っていくものが無いと商談が始まらない |
| **9月末** | マルチテナントの越境アクセス実地テスト（2組織目）が済んでいる | `roadmap.md` が「**他農場へ配る前**の必須項目」と明記。**これが未済のうちは他組織に売れない** |

**実働期間: 9/18 → 12/10 = 約12週。うち営業に使えるのは10週。**
リリース（10月中旬）は営業開始の合図ではなく、営業の**途中**に来る。**10月中旬を待ってから動くと、商談開始が11月になり逆算が破綻する。**

### WP1 【最優先】団体一括契約は成立するか、決裁は何ヶ月かかるか

**これで変わる判断**

**調べ方（一次情報）**

**担当の適性** 営業・事業開発寄り。電話・訪問を厭わない人

### WP3 農家が「払える」決済手段は何か（有料転換の物理的ボトルネック）

**問い**
基幹的農業従事者の平均年齢67.7歳・65歳以上69.6%（2025年農林業センサス）という母集団で、**クレジットカードによるApp内課金／Stripeが実際に完了できるのか。** 完了できないなら、有料転換率の議論より先にここが天井になる。

**これで変わる判断**
分岐B、および課金インフラの実装（WP6）。**「口座振替・請求書払いが要る」なら、IAP前提の料金設計そのものが崩れる。**

**調べ方**
1. 農業向けサービスの**決済手段の実態**: アグリハブ/アグリノート/KSAS等の有料プランが受け付けている決済手段（カードのみか、請求書・口座振替があるか）を料金ページ原文で確認
2. JA を通じた**購買・共済の決済慣行**（購買未収金・口座振替）。農家がJA口座からの引き落としに慣れている度合い
3. 高齢層のアプリ内課金の**離脱率に関する公開データ**（あれば）
4. **実地**: WP5のヒアリング対象に「スマホでクレカ決済をしたことがあるか／App Storeにカードを登録しているか」を必ず聞く

**成果物**
- 決済手段別の「使える見込み」判定表（カード/キャリア決済/口座振替/請求書/コンビニ）
- **団体一括の場合の請求方法**（請求書払いが必須なら、IAPではなくWeb契約になる → Apple手数料の議論が消える）

**担当の適性** リサーチ + ヒアリング
**期限** 着手から**10日**

### WP5 支払意思（WTP）の実地検証 — 農家20〜30人

**問い**
「何になら980円払うか」。現状 `ai_outputs` は全件が開発時の動作確認で、**支払意思を測るデータが存在しない**（`20260823-pricing-plan-review.md`）。

**これで変わる判断**

**調べ方**
1. **定性ヒアリング 20〜30人**（1人20分）。聞くのは機能の good/bad ではなく、**今払っているもの**:
   - 農業関係で今お金を払っているサービス・アプリは何か。月/年いくらか。誰が決めたか
   - 記録・防除・帳簿で、今いちばん時間を取られている作業は何か。年に何回か

**成果物**

**担当の適性** 現場に行ける人。農家との接点がある人を優先

### WP6 課金インフラと法務の実装要件（10月中旬リリースに間に合うか）

**問い**
マルチテナント化＋Stripe連携は未着手（`roadmap.md`）。**10月中旬リリース時点で課金は載るのか。** 載らないなら、12月までの77日はさらに短くなる。

**これで変わる判断**
分岐C（期日の扱い）。**課金開始日が11月なら、30万円到達の期間は実質1.5か月になる。**

**調べ方**

## 2-C. 制約の確定（2026-09-18・第2次）と、計画の作り直し

**オーナーから2つの制約が出た。これで計画の骨格が変わる。**

| 制約 | 内容 |
|---|---|
| **営業をしない** | マーケティングのみ。訪問・電話・商談は手段から外れる |
| **予算がほぼゼロ** | 使えるようになるのは**年末に約170万円**。つまり**期限（12/31）の後**に入る |

### この2つが消すもの

**「営業をしない」＝ 団体一括（3〜6件で30万）の経路が消える。**
セルフサーブで法人が20席を契約することは起きない。よって:

| WP | 扱い |
|---|---|
| WP1（団体一括の決裁期間） | **廃止**。売りに行かないので決裁期間を知っても使えない |
| WP9（1契約あたりの席数） | **大幅縮小**。「農業法人の雇用規模」は不要。ただし「**家族経営の平均人数**」だけは残す（下記 WP20） |
| WP10（競合の営業プロセス） | **差し替え**。営業プロセスではなく**マーケの流入経路**を調べる（WP16へ） |
| WP11（既存接点の棚卸し） | **差し替え**。営業先リストではなく**オーナー自身の発信力の棚卸し**（WP17へ） |
| WP2（チャネルの費用） | **縮小**。展示会・新聞広告・Web広告は予算ゼロの期間は実行不能。**ゼロ円で動くものだけに絞る**（WP15へ） |

**残るのは D2C セルフサーブ 1本。** つまり `0-3` に戻る:

> 転換率3%なら、12月までに**無料ユーザー10,233人**（133人/日）が必要。
> アグリハブは「宣伝広告費ゼロ・口コミ」で5万人に到達したが、**2万人まで3年半＝平均16人/日**。

### 170万円は、この目標には使えない

年末着金なので、12月末の課金には間に合わない。**そして仮に前倒しで使えたとしても、届くかは CAC 次第。**

LTV（980円 × 継続12か月）= グロス11,760円 / IAP15%控除後 9,996円。健全な CAC の上限（LTV の1/3）は**約3,800円**。

| CAC | 170万円で買える件数 | MRR |
|---|---|---|
| 2,000円 | 850件 | 833,000円 |
| 3,500円 | 485件 | 475,300円 |
| **5,500円** | **309件** | **302,820円** ← ぎりぎり届く線 |
| 6,000円 | 283件 | 277,340円 |
| 10,000円 | 170件 | 166,600円 |
| 20,000円 | 85件 | 83,300円 |

**170万円が30万円MRRに化けるのは、CAC が 5,500円以下のときだけ。** そしてそれは転換率に支配される:

| 転換率 | CAC 5,500円に必要な CPI（インストール単価） | 必要インストール数 |
|---|---|---|
| 2% | 110円 | 15,350 |
| 3% | 165円 | 10,233 |
| 5% | 275円 | 6,140 |
| **10%** | **550円** | **3,070** |

**転換率が3%か10%かで、同じ170万円の効きが3倍以上変わる。**
農業という狭いターゲットで CPI 165円は現実的でない可能性が高く、550円なら射程に入る。

### したがって、この計画の結論を書き換える

> **12月までの本当の仕事は「30万円を作ること」ではなく、
> 「170万円を1月に正しく使えるように、転換率と CAC を実測しておくこと」。**

予算ゼロの期間に転換率を測らずに年明けて170万円を投じるのが、この計画で最大のリスク。

オーナーが最初に聞いた「無料と有料、有料転換戦略」が、ここで最優先事項として戻ってくる。

### 現実的に到達しうる12月の数字

ゼロ円・10週・レビュー0件・ブランドなしの状態から。先行事例（アグリハブ 平均16人/日を広告費ゼロで達成）を上限の目安に置くと:

## 5. 品質基準（過去の調査から学んだこと）

`dl-target-20k-2026-09.md` は **原文到達ゼロ**のまま結論まで書いており、冒頭に自ら「数字を意思決定に使う前に原文確認をすること」と注記している。同じことを繰り返さないための基準:

1. **原文URLのない数字は、意思決定に使わない。** 報告書では「原文確認済み」「要約経由」を行ごとに区別する
2. **母数の定義が確認できない比率は使わない。**（「4軒に1軒」が母数によって3.4%〜32%に割れた例）
3. **単位を混ぜない。** DL / 登録者 / 利用組織 / アクティブ は別の数。競合の公表値はどれで語られているかを明記する
4. **反証を1つ探す。** 結論に都合の悪い事例を探してから書く
