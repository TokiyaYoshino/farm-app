# 栽培・防除・施肥の実務知識

「記録すべき項目」の背後にある農作業のリズムを理解していないと、入力タイミング・頻度・必須化の判断を誤る。ここでは防除の考え方、施肥設計、果樹の年間サイクルを扱う。

## 1. 防除体系と IPM（総合的病害虫・雑草管理）

IPM（Integrated Pest Management）は、輪作・抵抗性品種・土着天敵の活用などで**病害虫が発生しにくい環境を先につくり**、発生状況に応じて生物的防除（天敵）・物理的防除（粘着板等）・化学的防除（農薬）を適切に組み合わせて、環境負荷を抑えながら病害虫を管理する考え方。農薬散布ありきではなく、**発生状況のモニタリング→防除要否の判断→手段の選択**という順序が核心。農水省は果樹（カンキツ・リンゴ・ナシ・ブドウ等）を含む作物別の総合防除実践マニュアルを公開している。

**記録への含意**：IPM を実践している農場では「散布した」記録だけでなく「発生状況を見て散布しなかった」判断も価値がある。防除記録を「農薬を使った日」だけに絞ると、この判断の記録が抜け落ちる——将来「モニタリング記録」「見送り判断」を残せる項目を検討する余地がある。

## 2. 施肥設計の基本

- 施肥は土壌診断（pH・EC・肥料成分）を踏まえて設計するのが基本。土壌 pH は酸性・アルカリ性の指標で、作物ごとに適正範囲があり、外れると養分吸収効率が落ちる。
- 施肥は防除より**頻度が低い**（果樹なら年数回程度、露地野菜でも作期ごと）。防除記録と同じ粒度・同じ必須化基準を当てはめると、測っていない日にまで入力を強制することになり、虚偽入力（適当な値の入力）を誘発する。
- 施肥設計の記録は「いつ・何を・どれだけ」に加えて「土壌診断の結果」が紐づくと価値が上がる（次回の設計にフィードバックできる）。

## 3. 果樹の年間サイクル（紀州の主要品目：南高梅・温州みかん）

紀州（和歌山）は南高梅と温州みかんの主産地。farm-app が実際に扱う作物は DB の作物マスタが正だが、代表例として押さえておく価値が高い。**果樹は野菜と違い多年生**で、同じ樹への年間サイクルが記録の中心になる（作付けの入れ替わりが少ない分、年次比較の価値が高い）。

### 南高梅（うめ）の年間サイクル（目安）
| 時期 | 作業 |
|---|---|
| 12月〜2月上旬 | 冬剪定（休眠期〜花芽形成前） |
| 2月上旬〜下旬 | 開花（天候により変動） |
| 3月〜5月 | 摘果、防除（病害虫の発生状況に応じて） |
| 5月下旬〜6月上旬 | 青梅の収穫開始 |
| 6月中旬〜7月上旬 | 完熟梅の収穫（梅干し向け最盛期） |
| 7月〜8月 | 夏剪定（収穫後、翌年の花芽形成を促す） |

### 温州みかんの年間サイクル（目安、地域差が大きい）
| 時期 | 作業 |
|---|---|
| 4月〜5月 | 開花 |
| 6月下旬〜9月 | 摘果（粗摘果→仕上げ摘果の2段階が一般的） |
| 夏（品種・地域による） | マルチ栽培（シートで土壌水分を制御し糖度を上げる）、防除 |
| 11月〜12月 | 収穫最盛期（糖度・酸度・着色の出荷基準を満たしたものから） |

これらはあくまで一般的な目安で、**実際の時期は地域・天候・品種・栽培方式（早生・晩生等）で大きくずれる**。farm-app 上での判断（例：リマインダー通知の時期設定）は、この一般知識をたたき台にしつつ、実際の過去記録（作付け履歴・作業実績）で補正すべき。

## 4. 隔年結果と摘果

果樹には「なり年」と「不なり年」が交互に来る**隔年結果**という性質があり、摘果（余分な果実を間引く作業）はこれを緩和し果実品質を安定させる目的がある。摘果の記録は収穫量記録と組み合わせて初めて意味を持つ（摘果量と最終収穫量の関係）——収穫量予測系の機能を将来検討する際は、摘果記録の有無が精度を左右する重要な変数になる。

## 5. 天候と作業判断

- 防除（農薬散布）は風・降雨のタイミングに強く左右される。散布直後の降雨は効果を減らし、無駄な再散布や環境負荷につながるため、風・降雨前後は散布を避けるのが基本。
- 天候・気温・降雨の記録は、単なる参考情報ではなく「なぜこの日に散布/収穫したか」という判断根拠の記録でもある。
- 台風・霜・干ばつなど異常気象は、その年の収穫量・品質を大きく左右する外れ値要因。年次比較や収穫予測を行う際は、こうした異常気象の年をどう扱うか（除外する／注記する）を設計に含めるべき。

## 6. プロダクト判断への含意

- 記録項目の必須化・頻度は、**その作業の実際の頻度**に合わせる（散布は高頻度・施肥や土壌診断は低頻度）。頻度の低い項目を高頻度項目と同じ基準で必須化すると虚偽入力を誘発する。
- リマインダー通知や栽培暦ベースの機能は、一般的な栽培暦を初期値にしつつ、実績データで補正できる設計が望ましい。
- 収穫予測系の機能は、摘果記録・異常気象年の扱いなど、単純な「過去実績の平均」では拾えない変数があることを踏まえて設計する。
